# TCP/IP

**TCP/IP** is the layered set of protocols the internet actually runs on. Each layer solves one problem and hands the result to the layer above it — your browser never has to think about Ethernet frames, and Ethernet never has to think about HTTP.

## The four layers

<ItemExplorer title="TCP/IP Model" layout="grid" items={tcpIpLayerItems} />

Data flowing down through these layers gets wrapped at each step — an HTTP request becomes the payload of a TCP segment, which becomes the payload of an IP packet, which becomes the payload of an Ethernet frame. The receiving end unwraps it in reverse.

## What TCP actually adds

IP alone is "best effort" — packets can arrive out of order, get duplicated, or simply vanish, and IP itself does nothing about it. **TCP** sits on top of IP and turns that into a reliable, ordered, connection-oriented stream: every byte is numbered, acknowledged, and retransmitted if it doesn't arrive.

## TCP vs UDP, in one line

TCP guarantees delivery and order at the cost of latency and overhead (acknowledgments, retransmission, the handshake above). **UDP** skips all of that — no handshake, no guarantees, just send the packet — which is why it's used where speed matters more than reliability: DNS lookups, video calls, online games.
