# Web Fundamentals

Before a browser can send a single HTTP request, a lot has to happen: a domain name has to resolve to an IP address, a connection has to open, and — for anything on the modern web — that connection has to be encrypted. This section covers the layers underneath HTTP, and the infrastructure most real traffic passes through along the way.

## Start Here

- **[HTTP](/web-fundamentals/http)** — the protocol most of the web is actually built on.
- **[URLs & URIs](/web-fundamentals/urls)** — the anatomy of a URL and what each piece does.
- **[DNS](/web-fundamentals/dns)** — how a hostname becomes an IP address.
- **[TLS & HTTPS](/web-fundamentals/tls)** — how a connection gets encrypted before any HTTP flows over it.

## Networking

- **[TCP/IP](/web-fundamentals/tcp-ip)** — the layered model underneath every internet connection.
- **[Ports & Sockets](/web-fundamentals/ports-sockets)** — how one IP address serves hundreds of applications at once.

## Infrastructure

- **[Proxies](/web-fundamentals/proxies)** — forward vs. reverse proxies, and how a reverse proxy routes a request.
- **[CDNs](/web-fundamentals/cdns)** — serving content from servers close to the user instead of one origin far away.
