# 4xx Client Error Status Codes

The request had a problem. The client sent something invalid, unauthorized, or requested something that doesn't exist.

## Most Common 4xx Codes

| Code | Name | Meaning |
|------|------|---------|
| 400 | Bad Request | The request format is invalid. |
| 401 | Unauthorized | You need to authenticate (log in). |
| 403 | Forbidden | You're authenticated but not allowed. |
| 404 | Not Found | The resource doesn't exist. |
| 409 | Conflict | The request conflicts with server state. |
| 422 | Unprocessable Entity | The format is valid but the data is rejected. |
| 429 | Too Many Requests | You're sending too many requests (rate limited). |

---

## Detailed Breakdown

### 400 Bad Request
The request format is invalid or malformed.

```http
POST /api/users HTTP/1.1
Content-Type: application/json

{ invalid json }

HTTP/1.1 400 Bad Request
{
  "error": "Invalid JSON syntax"
}
```

**Use:** When the client sends:
- Invalid JSON
- Missing required fields
- Wrong content type
- Malformed query parameters

---

### 401 Unauthorized
You need to authenticate (provide credentials like username/password or API key).

```http
GET /api/admin HTTP/1.1

HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="api"
{
  "error": "No authentication provided"
}
```

**Use:** When the client hasn't authenticated or their token is expired.

---

### 403 Forbidden
You're authenticated, but you don't have permission to access this resource.

```http
GET /api/admin HTTP/1.1
Authorization: Bearer valid-token

HTTP/1.1 403 Forbidden
{
  "error": "Insufficient permissions"
}
```

**Use:** When the client is logged in but lacks the role/permission needed.

---

### 404 Not Found
The requested resource doesn't exist.

```http
GET /api/users/999999 HTTP/1.1

HTTP/1.1 404 Not Found
{
  "error": "User not found"
}
```

**Use:** When a resource never existed, or was deleted.

---

### 409 Conflict
The request conflicts with the current server state.

```http
PUT /api/documents/42 HTTP/1.1
If-Match: "old-version"

HTTP/1.1 409 Conflict
{
  "error": "The document was modified by someone else"
}
```

**Use:** When the client's version is out of date or a unique constraint fails.

---

### 422 Unprocessable Entity
The request format is valid (valid JSON), but the data is rejected.

```http
POST /api/users HTTP/1.1
Content-Type: application/json

{
  "name": "Alice",
  "email": "invalid-email"
}

HTTP/1.1 422 Unprocessable Entity
{
  "error": "Invalid email format"
}
```

**Use:** When:
- Email is invalid
- Phone number is wrong format
- Age is outside allowed range
- Email already exists (business logic violation)

---

### 429 Too Many Requests
You're sending too many requests. Slow down.

```http
POST /api/login HTTP/1.1

HTTP/1.1 429 Too Many Requests
Retry-After: 60
{
  "error": "Rate limit exceeded. Try again in 60 seconds."
}
```

**Use:** When the client is making requests too fast.

---

## Other Important 4xx Codes

- **405 Method Not Allowed** — The method (GET, POST, etc.) isn't allowed for this resource.
- **408 Request Timeout** — The client took too long to send the request.
- **410 Gone** — The resource was deleted and won't come back.
- **415 Unsupported Media Type** — The Content-Type isn't supported.
- **418 I'm a Teapot** — The server is a teapot (joke from RFC 2324).

---

## 401 vs 403: The Difference

| 401 Unauthorized | 403 Forbidden |
|-----------------|---------------|
| You need to log in | You're logged in, but no permission |
| No credentials provided or invalid credentials | Valid credentials, but insufficient role/permission |
| Include `WWW-Authenticate` header | Don't include `WWW-Authenticate` |

---

## Common Mistakes

**Avoid:** Using 404 for permission issues — Use 403, not 404. Don't hide that the resource exists.

**Avoid:** Using 400 for all client errors — Use more specific codes: 401, 403, 404, 409, 422.

**Avoid:** Not including `Retry-After` on 429 — Tell the client how long to wait before retrying.

**Avoid:** Using 401 when you mean 403 — 401 means "log in", 403 means "no permission".
