# 2xx Success Status Codes

The request succeeded. The response contains the result or confirmation.

## Most Common 2xx Codes

| Code | Name | When to Use |
|------|------|------------|
| 200 | OK | Generic success. Everything worked. |
| 201 | Created | Resource was successfully created (POST). |
| 202 | Accepted | Request accepted but processing is async. |
| 204 | No Content | Success, but there's no body to return (DELETE, PATCH). |

---

## Detailed Breakdown

### 200 OK
The request succeeded. Include the result in the response body.

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 42,
  "name": "Alice"
}
```

**Use for:** GET, PUT (when returning the updated resource), PATCH.

---

### 201 Created
The request succeeded and a new resource was created.

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/users/42

{
  "id": 42,
  "name": "Alice"
}
```

**Use for:** POST (when creating a new resource).

**Important:** Include a `Location` header with the URL of the new resource.

---

### 202 Accepted
The request was accepted and is being processed, but it's not complete yet.

```http
HTTP/1.1 202 Accepted
Content-Type: application/json

{
  "status": "processing",
  "job_id": "abc-123"
}
```

**Use for:** Long-running operations (file uploads, transcoding, reports).

The client should check the job status later using the job ID.

---

### 204 No Content
The request succeeded, but there's no content to return.

```http
HTTP/1.1 204 No Content
```

**Use for:** DELETE, PATCH (when you don't need to return the updated resource).

**Important:** The response has NO body (not even `{}`).

---

## Other 2xx Codes

- **205 Reset Content** — Success, and the client should reset the form / UI.
- **206 Partial Content** — Returning only part of a resource (range request).

---

## Common Mistakes

**Avoid:** Using 200 when you should use 201 — POST that creates a resource should return 201, not 200.

**Avoid:** Using 204 but still sending a body — If you send 204, don't include a body.

**Avoid:** Forgetting Location header on 201 — Include where the new resource can be accessed.
