# PATCH

**PATCH** modifies a resource with **partial updates**. Unlike PUT (which replaces the entire resource), PATCH lets you update only the fields you want to change.

## When to Use PATCH

- Update one or two fields on a resource
- Don't want to send the entire object
- The full resource is large or changes frequently

**Example:** Update a user's email without sending their entire profile.

```json
PATCH /api/users/42 HTTP/1.1
Host: api.example.com
Content-Type: application/json

{
  "email": "newemail@example.com"
}
```

---

## PATCH vs PUT

| Aspect | PUT | PATCH |
|--------|-----|-------|
| **Updates** | Full replacement | Partial update |
| **Body** | Full resource | Only changed fields |
| **Idempotent** | Yes | No (usually) |
| **Safe** | No | No |

**PUT:**
```json
PUT /api/users/42 HTTP/1.1

{
  "id": 42,
  "name": "Alice",
  "email": "alice@example.com",
  "phone": "+1-555-0123"
}
```

**PATCH (same result, less data):**
```json
PATCH /api/users/42 HTTP/1.1

{
  "email": "alice@example.com"
}
```

---

## Content-Type Matters

When you PATCH with JSON, use `application/json`:

```http
PATCH /api/users/42 HTTP/1.1
Content-Type: application/json
```

For **RFC 6902 JSON Patch** (a standard format for describing changes), use `application/json-patch+json`:

```json
PATCH /api/users/42 HTTP/1.1
Content-Type: application/json-patch+json

[
  { "op": "replace", "path": "/email", "value": "newemail@example.com" },
  { "op": "add", "path": "/phone", "value": "+1-555-0199" }
]
```

---

## Response Status Codes

- **200 OK** — Patch applied successfully, body contains updated resource
- **204 No Content** — Patch applied, but server doesn't return the resource
- **400 Bad Request** — Patch format is invalid
- **404 Not Found** — Resource doesn't exist
- **409 Conflict** — Patch can't be applied (conflicting changes, version mismatch)
- **422 Unprocessable Entity** — Patch is valid JSON but data is rejected

---

## Common Mistakes

**Avoid:** PATCH vs PUT confusion — PATCH is for partial updates, PUT is full replacement.

**Avoid:** Not sending Content-Type — Always specify the format of your patch.

**Avoid:** Assuming PATCH is idempotent — It usually isn't. Calling PATCH twice might produce different results than calling it once.

**Avoid:** PATCH without checking response status — Always check if the patch succeeded.
