# CDNs

A **Content Delivery Network** is a globally distributed set of caching servers that sit between clients and your origin server. Instead of every request in the world traveling all the way to wherever your one backend actually lives, most requests get served from a server physically close to the person making them.

It's a specialized [reverse proxy](/web-fundamentals/proxies) — the same "sits in front of the server, hides it from the client" model, just replicated at hundreds of locations worldwide with caching as the primary job.

## Why it's faster

- **Distance** — a round trip to a server 15ms away instead of 150ms away is the single biggest win, especially for anything with several sequential requests (like loading a page with many assets).
- **Origin load** — the origin server only has to handle cache misses and truly dynamic requests, not every single request from every user everywhere.
- **Absorbing traffic spikes** — a sudden surge in requests for a cached asset is absorbed by the edge network; the origin never sees most of it.

## What CDNs are good — and bad — for

CDNs excel at **static, cacheable content**: images, CSS, JS bundles, video. They're a much worse fit for **highly dynamic, per-user content** (a live account balance, a personalized dashboard) — that either bypasses the cache entirely or needs careful, narrow cache rules (e.g. caching per-user only briefly, or not caching the response body at all while still caching static assets on the same page).
