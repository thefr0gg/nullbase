يغطي **GitLab** أرضية مشابهة إلى حد كبير لـ [GitHub](/ar/developer-tools/github) — استضافة مستودعات [Git](/ar/developer-tools/git)، وطلبات الدمج (اسم GitLab لطلب السحب)، وتتبّع المشاكل — لكنه تميّز تاريخياً بجعل CI/CD ميزة أصلية مدمجة بعمق بدلاً من منتج منفصل يُلحَق لاحقاً، وبإصدار مفتوح المصدر يُستضاف ذاتياً يمكن للمؤسسات تشغيله بالكامل على بنيتها التحتية الخاصة.

## طلبات الدمج مقابل طلبات السحب

**طلب الدمج (MR)** في GitLab هو من الناحية الوظيفية نفس مفهوم طلب السحب في GitHub — اقتراح دمج فرع في آخر، ومراجعة التغييرات، وتشغيل CI، ثم الدمج — فقط باسم مختلف يعود إلى تطور GitLab المستقل السابق. عمليات Git الأساسية متطابقة بغض النظر عن المنصة المستضيفة للمستودع؛ فقط واجهة التعاون والمصطلحات تختلف.

## GitLab CI/CD

تُعرَّف خطوط أنابيب (pipelines) GitLab في ملف واحد `.gitlab-ci.yml` عند جذر المستودع:

```yaml
stages:
  - test
  - deploy

test:
  stage: test
  script:
    - npm ci
    - npm test

deploy:
  stage: deploy
  script:
    - ./deploy.sh
  only:
    - main
```

تعرّف `stages` المراحل المرتَّبة لخط الأنابيب؛ وتُشغَّل المهام (jobs) ضمن نفس المرحلة بالتوازي، ولا تبدأ مرحلة إلا بعد نجاح كل مهمة في المرحلة السابقة. هذا البنية مشابهة إلى حد كبير لنموذج jobs-and-steps في GitHub Actions، لكن CI/CD في GitLab وُضِع تاريخياً كميزة أساسية للمنصة لا كإضافة، مع دعم مدمج أوثق لأشياء مثل خطوط أنابيب النشر متعددة المراحل والبيئات.

## الاستضافة الذاتية

يوفّر GitLab إصداراً مُستضافاً ذاتياً باسم "Community Edition" (مفتوح المصدر) و"Enterprise Edition" (بميزات إضافية مدفوعة)، مما يتيح لمؤسسة تشغيل المنصة بأكملها — استضافة المستودعات، ومُشغّلات CI، وتتبّع المشاكل — على خوادمها الخاصة بدلاً من الاعتماد على منصة SaaS من طرف ثالث. يهم هذا المؤسسات ذات متطلبات صارمة لإقامة البيانات أو الامتثال لا يمكن لخدمة مستضافة تلبيتها، على حساب أن تتولى المؤسسة الآن تشغيل تلك البنية التحتية بنفسها.

## الاختيار بينهما

بالنسبة لمعظم الفرق، يعتمد الاختيار على النظام البيئي والألفة السابقة أكثر من أي قيد تقني صارم — كلاهما ناضج، وكلاهما يدعم نفس تدفقات عمل Git الأساسية، ونقل تاريخ Git الخام لمستودع بينهما مباشر تماماً لأن Git نفسه لا يهتم بالمنصة المستضيفة له. الفروقات الأكثر أهمية (احتياجات الاستضافة الذاتية، عمق CI/CD، ألفة الفريق الحالية) هي عادة ما يحسم القرار فعلياً.
