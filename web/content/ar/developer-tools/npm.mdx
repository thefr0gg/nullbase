**npm (Node Package Manager)** هو الأداة الافتراضية لتثبيت تبعيات جافاسكريبت ونشرها وإدارتها، إلى جانب السجل العام الذي يستضيف الحزم نفسها. يأتي مدمجاً مع Node.js، وهذا معظم سبب بقائه الخيار الافتراضي رغم وجود بدائل ([Yarn](/ar/developer-tools/package-managers)، وpnpm).

## package.json

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "dependencies": {
    "express": "^4.18.0"
  },
  "devDependencies": {
    "vitest": "^1.0.0"
  },
  "scripts": {
    "start": "node server.js",
    "test": "vitest run"
  }
}
```

`dependencies` مطلوبة وقت التشغيل؛ أما `devDependencies` فمطلوبة فقط أثناء التطوير (أطر الاختبار، وأدوات اللنت، وأدوات البناء) ولا تُثبَّت عندما تُثبَّت الحزمة كتبعية *لشخص آخر*. تعرّف `scripts` أوامر shell مُسمّاة يمكن تشغيلها عبر `npm run <name>` — بديل خفيف ومحلي للمشروع عن مُشغِّل مهام منفصل.

## ملف القفل (Lockfile)

يكتب `npm install` (أو يحدّث) ملف `package-lock.json`، مسجِّلاً الإصدار المحلول *الدقيق* لكل تبعية وكل تبعية متعدّية مثبَّتة فعلياً — لا مجرد نطاقات الإصدارات في `package.json`. بدون ملف قفل، يمكن أن يحصل شخصان يشغّلان `npm install` على نفس `package.json` في وقتين مختلفين على إصدارات تبعيات متعدّية مختلفة إذا نُشِر أي إصدار جديد في المنبع بينهما؛ يثبّت ملف القفل تلك الإصدارات، لذا يُعيد `npm ci` (التثبيت الصارم المعتمد على ملف القفل المستخدم في CI) إنتاج نفس شجرة التبعيات بالضبط في كل مرة.

## ما يفعله `npm install` فعلياً

1. يقرأ نطاقات الإصدارات المُعلَنة في `package.json` (و`package-lock.json` إن وُجد).
2. يحل إصداراً متوافقاً لكل تبعية ولكل تبعية من تبعياتها، بشكل تكراري.
3. يحمّل أرشيف (tarball) كل حزمة من السجل (أو من ذاكرة تخزين مؤقت محلية، إن كان مُحمَّلاً سابقاً).
4. يستخرج كل شيء إلى `node_modules/`، مع محاولة خوارزمية التسطيح في npm تجنّب نسخ مكررة من نفس إصدار الحزمة حيثما أمكن.
5. يكتب/يحدّث `package-lock.json` لتسجيل ما تم حله بالضبط.

## نطاقات الإصدار الدلالي

`^4.18.0` في المثال أعلاه نطاق، وليس تثبيتاً دقيقاً — يسمح `^` بأي إصدار لا يغيّر المكوّن الأقصى يساراً غير الصفري (فـ `4.19.2` مسموح، و`5.0.0` غير مسموح)، اتّباعاً لاتفاقية [الإصدار الدلالي](/ar/developer-tools/semantic-versioning) بأن ترقية الإصدار الرئيسي (major) تعني حدوث تغيير كاسر. `~4.18.0` أكثر صرامة، ولا يسمح إلا بتحديثات مستوى الرقعة (patch) (`4.18.x`)؛ ولا يسمح إصدار دقيق بلا بادئة بأي تحديثات آلية على الإطلاق.
