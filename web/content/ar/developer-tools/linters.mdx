تحلّل **أداة الفحص اللغوي (linter)** الكود المصدري تحليلاً ساكناً — دون تنفيذه — بحثاً عن أنماط هي على الأرجح أخطاء، أو أسلوب غير متسق، أو مخالفات لاتفاقيات فريق متفق عليها. ESLint (جافاسكربت/TypeScript)، وPylint/Ruff (بايثون)، وRuboCop (روبي) أمثلة شائعة؛ تمتلك كل لغة رئيسية تقريباً أداة فحص لغوي واحدة على الأقل مستخدمة على نطاق واسع.

## ما تكتشفه أداة الفحص اللغوي فعلياً

```js
function getUser(id) {
  if (id = 42) {         // ⚠ assignment in a condition — almost certainly meant ===
    return admin;
  }
  const x = 1;
  const x = 2;            // ⚠ 'x' is already declared
  return unusedVar;       // ⚠ 'unusedVar' is not defined
}
```

لا شيء من هذا أخطاء نحوية — سيُحلَّل الكود بلا مشكلة — لكن كل واحدة منها إما خطأ صريح (`=` بدلاً من `===`) أو إشارة قوية إلى وجود خطأ ما (متغيّر أُعيد إعلانه، إشارة إلى شيء لم يُعرَّف قط). القيمة الكاملة لأداة الفحص اللغوي هي اكتشاف هذه الفئة تحديداً من الأخطاء: صياغة صحيحة لكنها على الأرجح ليست ما قصده الكاتب.

## الفحص اللغوي مقابل فحص الأنواع

تبحث أداة الفحص اللغوي عن *أنماط* في الكود بغض النظر عن فهمها للأنواع الفعلية المتدفقة عبره؛ يتحقق فاحص الأنواع (TypeScript، mypy) من استخدام القيم بشكل متسق مع أنواعها المُعلَنة أو المُستنتَجة. تكتشف الأداتان فئتين مختلفتين من المشكلات، غير متداخلتين في معظمها — يمكن لأداة الفحص اللغوي وسم `==` التي يجب أن تكون `===` دون معرفة أي شيء عن الأنواع، ويمكن لفاحص الأنواع اكتشاف تمرير `string` حيث يُتوقَّع `number` دون الاهتمام إطلاقاً بأسلوب الكود. تستخدم معظم المشاريع الحقيقية كليهما.

## قواعد قابلة للتخصيص

```json
{
  "rules": {
    "no-unused-vars": "error",
    "no-console": "warn",
    "eqeqeq": "error"
  }
}
```

يمكن ضبط القواعد لتكون خطأ (يُفشِل البناء/CI)، أو تحذيراً (يُبلَّغ عنه دون إفشال أي شيء)، أو مُعطَّلة تماماً — مما يتيح لفريق فرض الاتفاقيات التي يهتم بها تحديداً دون تبنّي كل قاعدة تأتي بها أداة الفحص اللغوي افتراضياً. تتيح الإعدادات المشتركة (مثل `eslint-config-airbnb` أو الإعداد المُوصى به لإطار عمل ما) للفرق البدء من نقطة أساس معقولة بدلاً من ضبط مئات القواعد الفردية من الصفر.

## الإصلاح التلقائي

كثير من قواعد أداة الفحص اللغوي قابلة للإصلاح ميكانيكياً — يمكن ببساطة حذف استيراد غير مستخدَم، ويمكن إعادة كتابة `==` تلقائياً إلى `===` — وتدعم معظم أدوات الفحص اللغوي وضع إصلاح تلقائي (`eslint --fix`) يطبّق كل مخالفة قابلة للإصلاح دون حاجة إنسان لتعديل كل واحدة يدوياً. تُترَك القواعد التي تتطلب حكماً حقيقياً (متغيّر غير مستخدَم فعلياً قد يشير إلى خطأ حقيقي، وليس مجرد كود ميت) عادةً ليحلّها إنسان.
