PostgreSQL ("Postgres") هي قاعدة بيانات علائقية بنمط عميل-خادم — خلافاً لـ [SQLite](/ar/databases/sqlite)، تعمل كعملية طويلة الأمد خاصة بها، تقبل اتصالات عبر الشبكة من العديد من التطبيقات والمستخدمين المحتملين في آن واحد. تُعرف بالتزامها الوثيق بمعيار SQL، ونموذج تزامن قوي حقاً (MVCC — انظر [المعاملات](/ar/databases/transactions))، ونظام امتدادات يتيح لها القيام بمهام لا تستطيعها قاعدة بيانات علائقية أبسط (البحث النصي الكامل، والاستعلامات الجغرافية المكانية عبر PostGIS، وحتى بحث التشابه الاتجاهي للتضمينات).

## جرّبه (SQL قياسي، يعمل على المحرك داخل المتصفح)

يعمل الملعب أدناه على نفس محرك SQLite المضمَّن كباقي هذا القسم — إنها نفس SQL القياسية التي يفهمها Postgres أيضاً، لكنها ليست Postgres حرفياً. صياغة Postgres الخاصة (أسفل هذه الصفحة) مُعروضة في كتل كود ثابتة بدلاً من ذلك، لأنها لن تعمل فعلياً هنا.

بدون `RETURNING`، سيستغرق استرجاع الصف الجديد رحلة ذهاب وإياب ثانية (`INSERT` متبوعاً بـ `SELECT` منفصلة) — أشاع Postgres هذه العبارة، وهي مفيدة حقاً لدرجة أن SQLite أضافت دعماً لها أيضاً.

## ما هو خاص فعلياً بـ Postgres

```sql
-- SERIAL: عدد صحيح تلقائي الزيادة، اختصار Postgres لنمط شائع
CREATE TABLE users (id SERIAL PRIMARY KEY, email TEXT UNIQUE NOT NULL);

-- JSONB: JSON مُرمَّز ثنائياً وقابل للفهرسة، مخزَّن مباشرة في عمود
CREATE TABLE events (id SERIAL PRIMARY KEY, payload JSONB);
SELECT * FROM events WHERE payload->>'type' = 'signup';

-- أعمدة مصفوفة أصيلة — لا حاجة لجدول ربط منفصل لقائمة بسيطة
CREATE TABLE posts (id SERIAL PRIMARY KEY, tags TEXT[]);
SELECT * FROM posts WHERE 'featured' = ANY(tags);

-- المخططات: أسماء نطاقات ضمن قاعدة بيانات واحدة
CREATE SCHEMA billing;
SELECT * FROM billing.invoices;
```

لا يوجد أي من هذه الأربعة في SQLite القياسية — `JSONB` بالتحديد جزء كبير من سبب اختيار Postgres حتى لأعباء العمل التي تشعر بأنها أقرب إلى المستندية من العلائقية، لأنها تتيح لفريق الحصول على قوة الاستعلام المُهيكل على بيانات شبه مُهيكلة دون اللجوء إلى مخزن [NoSQL](/ar/databases/nosql) منفصل أصلاً.

## MVCC: كيف يتعامل Postgres مع الوصول المتزامن

يستخدم Postgres MVCC (التحكم في التزامن متعدد الإصدارات): بدلاً من أن يحجب القرّاء الكاتبين (أو العكس)، ترى كل معاملة لقطة متسقة من البيانات كما كانت عند بدء تلك المعاملة — استعلام تقرير طويل الأمد لا يحجب الكتابات الجارية أو يُحجَب بها أبداً. التكلفة أن إصدارات الصفوف القديمة ("الصفوف الميتة") تتراكم حتى تستردها عملية خلفية (`VACUUM`) — اهتمام تشغيلي حقيقي، وإن كان غير مرئي عادة، في قاعدة بيانات Postgres المزدحمة.
