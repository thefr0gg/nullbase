**TypeScript** لغة ثابتة الكتابة تُترجَم إلى JavaScript عادية. لا تُدخِل بيئة تشغيل جديدة، ولا جامع قمامة جديداً، ولا دلالات تنفيذ جديدة — كل برنامج JavaScript صالح هو (تقريباً) برنامج TypeScript صالح، وكل برنامج TypeScript يصبح في النهاية كود JavaScript يعمل في المحركات نفسها التي تعمل فيها JavaScript بالفعل (V8، Node، المتصفحات). ما تضيفه TypeScript هو **مُدقِّق أنواع (type checker)**: مرحلة منفصلة وقت الترجمة تقرأ تعليقاتك التوضيحية (annotations) والأنواع المُستنتَجة، وتُبلِغ عن أي تعارض، ثم تمحو كل تلك المعلومات النوعية قبل أن يُنفَّذ الكود على الإطلاق.

هذه النقطة الأخيرة مهمة. الأنواع في TypeScript لها **تكلفة تنفيذية صفرية وحضور صفري وقت التشغيل** — تختفي `interface`، و`type`، ومعظم التعليقات التوضيحية النوعية تماماً أثناء الترجمة (`tsc`، أو مُحوِّل مثل esbuild/SWC). هذا هو سبب قدرة TypeScript على التقاط فئة كاملة من الأخطاء — تمرير `string` حيث يُتوقَّع `number`، استدعاء تابع غير موجود على كائن، نسيان معالجة `null` — قبل أن تُشغِّل البرنامج مطلقاً، دون تغيير سلوك البرنامج بمجرد أن يعمل فعلاً.

## لماذا نضيف نظام أنواع إلى JavaScript

الكتابة الديناميكية في JavaScript مرنة، لكنها تعني أن أخطاءً كثيرة لا تظهر إلا وقت التشغيل، وغالباً في الإنتاج. يفحص مُصرِّف TypeScript أشكال بياناتك أثناء كتابة الكود:

```ts
function greet(name: string) {
  return `Hello, ${name.toUpperCase()}!`;
}

greet("Ada");
greet(42); // Type error: Argument of type 'number' is not assignable to parameter of type 'string'
```

كان الاستدعاء الثاني سيرمي خطأ `TypeError` وقت التشغيل في JavaScript العادية (`42.toUpperCase is not a function`) — لكن فقط بمجرد تنفيذ ذلك السطر فعلياً، وربما في مسار كود نادر التنفيذ. تلتقطه TypeScript فوراً، في اللحظة التي تكتبه فيها، داخل محررك.

## الكتابة البنيوية (Structural Typing)

خلافاً للغات المبنية على الأصناف مثل Java أو C#، نظام أنواع TypeScript **بنيوي (structural)** وليس اسمياً (nominal): يكون نوعان متوافقين إذا كان لهما الشكل نفسه، بغض النظر عن الاسم أو العلاقة المُعلَنة.

```ts
interface Point {
  x: number;
  y: number;
}

function printPoint(p: Point) {
  console.log(`(${p.x}, ${p.y})`);
}

const coord = { x: 3, y: 4, label: "origin-ish" };
printPoint(coord); // OK — coord has at least x and y as numbers
```

لم يُصرَّح `coord` أبداً كنوع `Point`، بل يحمل حتى حقلاً إضافياً `label`، لكنه يُلبِّي بنيوياً شكل `Point`، لذا الإسناد مسموح. هذا خيار تصميمي مقصود يعكس الطريقة التي تُمرَّر بها كائنات JavaScript فعلياً.

## كيف يُنظَّم هذا القسم

- **[بنية اللغة والأنواع](/ar/programming-languages/typescript/syntax-basics)** — تصريحات المتغيرات، والأنواع الأولية، وأسماء `type`.
- **[التحكم بمسار التنفيذ](/ar/programming-languages/typescript/control-flow)** — `if`/`switch` مع تضييق الأنواع (type narrowing).
- **[الدوال](/ar/programming-languages/typescript/functions)** — معاملات ذات أنواع، وأنواع إرجاع، ومعاملات اختيارية وافتراضية.
- **[هياكل البيانات](/ar/programming-languages/typescript/data-structures)** — مصفوفات ذات أنواع، والصفوف (tuples)، و`Record`، و`Map`.
- **[الأصناف والواجهات](/ar/programming-languages/typescript/oop-or-structs)** — مُحدِّدات الوصول، و`interface` مقابل `type`.
- **[معالجة الأخطاء](/ar/programming-languages/typescript/error-handling)** — `try`/`catch` وأصناف فرعية مخصصة من `Error`.
- **[الوحدات والحزم](/ar/programming-languages/typescript/modules-packages)** — وحدات ES، وnpm، و`tsconfig.json`، و`@types`.
- **[الأنواع العامة (Generics)](/ar/programming-languages/typescript/advanced)** — كتابة كود يعمل عبر أنواع متعددة دون التخلي عن أمان الأنواع.

تُبنى TypeScript فوق JavaScript — راجع دليل [JavaScript](/ar/programming-languages/javascript) لسلوك بيئة التشغيل الكامنة.
