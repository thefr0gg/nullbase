تقبل دوال JavaScript أي وسائط تُمرَّرها إليها، واستدعاء بعدد أو نوع خاطئ من الوسائط يفشل عادةً بصمت (الوسائط الزائدة تُتجاهَل، والمفقودة تصبح `undefined`) أو يرمي خطأً في عمق جسم الدالة. تُعلِن توقيعات دوال TypeScript بالضبط ما هو متوقَّع، ويفحص المُصرِّف كل موضع استدعاء مقابل ذلك التصريح قبل أن يعمل الكود مطلقاً.

## معاملات وأنواع إرجاع ذات كتابة

```ts
function add(a: number, b: number): number {
  return a + b;
}

add(2, 3); // 5
add(2, "3"); // Type error: Argument of type 'string' is not assignable to parameter of type 'number'
add(2); // Type error: Expected 2 arguments, but got 1
```

يُقيِّد `a: number` و`b: number` المعاملات؛ و`: number` بعد قائمة المعاملات يُقيِّد ما يُسمَح للدالة بأن تُعيده (`return`). لو حاول جسم الدالة تنفيذ `return a + b + "!"` (سلسلة نصية)، لرفض المُصرِّف ذلك أيضاً — يُفحَص نوع الإرجاع المُصرَّح مقابل عبارات الإرجاع الفعلية، وليس مجرد استنتاجه وتركه دون فحص.

يمكنك أيضاً ترك TypeScript تستنتج نوع الإرجاع بدلاً من كتابته صراحة:

```ts
function multiply(a: number, b: number) {
  return a * b; // نوع الإرجاع مُستنتَج كـnumber
}
```

لا يزال كتابة أنواع الإرجاع الصريحة يستحق العناء في الدوال المُصدَّرة/العامة — فهي تعمل كعقد لا يتغيّر بصمت إذا عدَّل أحدهم جسم الدالة لاحقاً.

## المعاملات الاختيارية

إلحاق `?` باسم معامل يجعله اختيارياً — يمكن للمستدعين حذفه، وداخل الدالة يشمل نوعه `undefined`:

```ts
function greet(name: string, title?: string): string {
  if (title) {
    return `Hello, ${title} ${name}!`;
  }
  return `Hello, ${name}!`;
}

greet("Ada"); // "Hello, Ada!"
greet("Ada", "Dr."); // "Hello, Dr. Ada!"
```

يجب أن تأتي المعاملات الاختيارية بعد كل المعاملات المطلوبة في قائمة المعاملات — `function f(a?: string, b: string)` خطأ وقت الترجمة، لأنه لن توجد طريقة لمعرفة أي وسيط كان استدعاء بقيمة واحدة يقصد ملأه.

## المعاملات الافتراضية

تجعل القيمة الافتراضية المعامل اختيارياً عند موضع الاستدعاء مع منحه قيمة ملموسة داخل جسم الدالة — دون حاجة لفحص `undefined`:

```ts
function createUser(name: string, role: string = "member") {
  return { name, role };
}

createUser("Ada"); // { name: "Ada", role: "member" }
createUser("Ada", "admin"); // { name: "Ada", role: "admin" }
```

بما أن نوع `role` مُستنتَج من قيمته الافتراضية (`string`)، فإن تمرير أي شيء آخر غير `string | undefined` يفشل في الترجمة رغم كل شيء — `createUser("Ada", 1)` خطأ نوع، حتى لو كانت لـ`role` قيمة افتراضية.
