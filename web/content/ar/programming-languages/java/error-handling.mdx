تعالج Java الأخطاء بالاستثناءات بدلاً من قيم إرجاع للخطأ. ما يميّز Java
عن معظم اللغات السائدة الأخرى هو تمييز يفرضه المصرّف بين فئتين من
الاستثناءات: **مفحوصة (checked)** و**غير مفحوصة (unchecked)**.

## استثناءات مفحوصة مقابل غير مفحوصة

يجب أن يُلتَقَط الاستثناء **المفحوص** (أي صنف فرعي من `Exception` ليس
`RuntimeException`) أو يُعلَن في عبارة `throws` لتابع — يرفض المصرّف
كوداً يتجاهل الاحتمال كلياً. `IOException` المثال الكلاسيكي، بما أن أي
عملية إدخال/إخراج يمكن أن تفشل لأسباب خارج سيطرة برنامجك:

```java
import java.io.IOException;

public void readConfig() throws IOException {
    // عملية ما يمكن أن ترمي IOException مفحوصة
    throw new IOException("config file missing");
}
```

يجب على الكود المستدعي معالجتها أو تمريرها، وإلا فلن يُصرَّف الملف:

```java
public void loadApp() {
    try {
        readConfig();
    } catch (IOException e) {
        System.out.println("Failed to load config: " + e.getMessage());
    }
}
```

الاستثناء **غير المفحوص** (أي صنف فرعي من `RuntimeException`، مثل
`NullPointerException` أو `IllegalArgumentException`) لا يفرضه المصرّف —
يمكنك رمي أو تجاهل واحد دون أن يتطلب المصرّف أبداً `try`/`catch` أو عبارة
`throws`. تمثّل هذه عادةً أخطاء برمجية (إحالة إلى null، وسيط غير صالح)
وليس شروطاً خارجية قابلة للاسترجاع:

```java
public int divide(int a, int b) {
    if (b == 0) {
        throw new IllegalArgumentException("divisor cannot be zero");
    }
    return a / b;
}
```

النية وراء هذا الفصل: تُنمذج الاستثناءات المفحوصة شروطاً يُتوقَّع من
المستدعي توقعها والتعافي منها (ملف مفقود، مهلة شبكة)؛ تُنمذج الاستثناءات
غير المفحوصة أخطاء لا يمكن إجبار أي مستدعٍ معقول على التخطيط لها في كل
موقع استدعاء. عملياً، متطلب الاستثناء المفحوص مثير للجدل — من الشائع رؤية
استثناءات مفحوصة مُغلَّفة داخل أخرى غير مفحوصة لتجنب انتشار عبارات
`throws` عبر كود غير ذي صلة.

## try / catch / finally

تُغلِّف `try` كوداً قد يرمي؛ تعالج كتلة `catch` واحدة أو أكثر أنواع
استثناءات محدَّدة؛ تعمل `finally` دون شرط، سواء حدث استثناء أم لا — المكان
المعياري لتحرير مورد:

```java
public void process() {
    try {
        int result = 10 / 0;
        System.out.println(result);
    } catch (ArithmeticException e) {
        System.out.println("Caught: " + e.getMessage());
    } finally {
        System.out.println("Cleanup runs regardless.");
    }
}
```

تُجرَّب كتل `catch` المتعددة بالترتيب، وتفوز أول كتلة يطابق نوع استثنائها
(بما في ذلك مطابقة نوع أب) — لذا يجب سرد أنواع الاستثناءات الأكثر تحديداً
قبل الأكثر عمومية:

```java
try {
    Object[] items = new String[3];
    items[0] = 42; // يرمي ArrayStoreException وقت التشغيل
} catch (ArrayStoreException e) {
    System.out.println("Array store violation: " + e.getMessage());
} catch (RuntimeException e) {
    System.out.println("Some other runtime exception");
}
```

## try-with-resources

منذ Java 7، يُغلِق `try (...)` تلقائياً أي مورد ينفّذ `AutoCloseable` في
نهاية الكتلة، حتى لو رُمي استثناء — مستبدلاً نمط الإغلاق اليدوي
`finally { resource.close(); }`:

```java
import java.io.BufferedReader;
import java.io.FileReader;
import java.io.IOException;

public void printFirstLine(String path) throws IOException {
    try (BufferedReader reader = new BufferedReader(new FileReader(path))) {
        System.out.println(reader.readLine());
    } // يُستدعى ()reader.close تلقائياً هنا
}
```
