تعالج PHP الحديثة الفشل بالاستثناءات، كثيراً مثل Java أو Python. لكن تاريخ PHP يعني أنك ستصادف آلية أقدم ومنفصلة — "أخطاء" و"تحذيرات" PHP — خاصة في الكود القديم أو عندما تفشل دالة مدمجة بطريقة تسبق نموذج استثناءات PHP. معرفة كلا الأمرين مهمة لقراءة قواعد كود PHP حقيقية.

## try / catch / finally

```php
<?php

function divide(int $a, int $b): float {
    if ($b === 0) {
        throw new InvalidArgumentException("Cannot divide by zero");
    }
    return $a / $b;
}

try {
    echo divide(10, 0);
} catch (InvalidArgumentException $e) {
    echo "Error: " . $e->getMessage() . "\n";
} finally {
    echo "Division attempt finished\n";
}
```

تُنفَّذ `finally` سواء أُطلق استثناء أو التُقط أم لا — مفيدة للتنظيف مثل إغلاق مقبض ملف أو اتصال قاعدة بيانات.

## التقاط أنواع استثناءات متعددة

يمكن لكتلة `catch` واحدة سرد عدة أنواع استثناءات بـ `|`، وتُجرَّب كتل catch بالترتيب، لذا ضع الأنواع الأكثر تحديداً أولاً:

```php
<?php

function parseConfig(string $json): array {
    $data = json_decode($json, true, flags: JSON_THROW_ON_ERROR);
    return $data;
}

try {
    parseConfig("{not valid json");
} catch (JsonException | TypeError $e) {
    echo "Could not parse config: " . $e->getMessage() . "\n";
}
```

## الاستثناءات المخصصة

الاستثناءات هي فئات عادية تتوسّع من `Exception` (أو فئة فرعية مدمجة أكثر تحديداً مثل `RuntimeException`). هذا يتيح لك حمل بيانات مهيكلة والتقاط فشل محدد على مستوى التطبيق بحسب النوع:

```php
<?php

class InsufficientFundsException extends RuntimeException {
    public function __construct(public readonly float $shortfall) {
        parent::__construct("Insufficient funds, short by $shortfall");
    }
}

function withdraw(float $balance, float $amount): float {
    if ($amount > $balance) {
        throw new InsufficientFundsException($amount - $balance);
    }
    return $balance - $amount;
}

try {
    withdraw(50.0, 75.0);
} catch (InsufficientFundsException $e) {
    echo "Short by: " . $e->shortfall . "\n";
}
```

## نموذج الإبلاغ عن الأخطاء الأقدم، باختصار

قبل تبنّي الاستثناءات بالكامل (ولا يزال الحال كذلك اليوم لدوال مدمجة كثيرة)، كانت PHP تبلّغ عن المشاكل بوصفها **أخطاء، وتحذيرات، وملاحظات** — أحداثاً ليست استثناءات يمكن تسجيلها، أو عرضها ضمن المخرجات، أو تجاهلها بصمت حسب إعدادات `error_reporting`، بدلاً من فك تسلسل مكدس الاستدعاءات كما يفعل الاستثناء المُطلَق:

```php
<?php

$value = @$undefinedArray["missing"]; // @ suppresses the warning
echo $value === null ? "null, no exception thrown\n" : "found\n";
```

عامل "قمع الأخطاء" `@` نمط قديم تثبّطه معظم أدلة أسلوب PHP الحديثة — فهو يخفي أخطاءً حقيقية جنباً إلى جنب مع الضجيج. حوّلت PHP 8 كثيراً من هذه التحذيرات القديمة إلى استثناءات `Error` مناسبة (تسلسل شقيق لـ `Exception`، كلاهما ينفّذ `Throwable`)، وهذا سبب أن استدعاء دالة غير معرَّفة يطلق الآن `Error` يمكنك التقاطها بـ `catch`، بدلاً من مجرد إصدار تحذير ومتابعة العمل بـ `null`.
