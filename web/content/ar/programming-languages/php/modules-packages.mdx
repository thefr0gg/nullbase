تملك قصة الوحدات في PHP طبقتين يسهل خلطهما في البداية: جمل تضمين الملفات منخفضة المستوى (`require`/`include`)، الموجودة في اللغة منذ البداية، والمساحات الاسمية بالإضافة إلى Composer، التي وصلت لاحقاً وتشكّل الآن العمود الفقري لكيفية تنظيم كود PHP الحديث ومشاركته فعلياً.

## require وinclude

تسحب هذه الجمل كود ملف PHP آخر إلى الملف الحالي، بشكل يشبه تقريباً `#include` في C لكنه يُقيَّم أثناء التشغيل، وليس أثناء الترجمة:

```php
<?php
// math.php
function square(int $n): int {
    return $n * $n;
}
```

```php
<?php
require "math.php";

echo square(5) . "\n"; // 25
```

تُطلق `require` خطأً فادحاً إذا كان الملف مفقوداً؛ بينما تُطلق `include` تحذيراً فقط وتترك السكربت يستمر. تضيف `require_once`/`include_once` فحصاً يتخطى إعادة تضمين ملف مُحمَّل بالفعل — مهم لتجنب أخطاء "الدالة معرَّفة مسبقاً" عندما قد تسحب ملفات متعددة نفس الاعتمادية.

```php
<?php
require_once "math.php";
require_once "math.php"; // silently skipped, already loaded
```

عملياً، نادراً ما تكتب مشاريع PHP الحديثة `require` يدوياً لكودها الخاص — يجعل محمّل التحميل التلقائي لـ Composer (أدناه) ذلك غير ضروري — لكنه لا يزال بالضبط ما يعمل تحت الغطاء.

## المساحات الاسمية

تجمع `namespace` الفئات/الدوال/الثوابت المرتبطة تحت بادئة مشتركة، ما يمنع تصادم الأسماء بين كودك وكود مكتبة (أو بين مكتبتين) بالطريقة التي تفعلها حزم Java أو مساحات أسماء C++:

```php
<?php
// src/Billing/Invoice.php
namespace App\Billing;

class Invoice {
    public function __construct(public float $amount) {}
}
```

```php
<?php
require "src/Billing/Invoice.php";

use App\Billing\Invoice;

$invoice = new Invoice(150.0);
echo $invoice->amount . "\n"; // 150
```

تستورد `use` اسماً ذا مساحة اسمية بحيث يمكنك الإشارة إليه دون تأهيل؛ بدونها، كان عليك كتابة `App\Billing\Invoice` كاملاً في كل مرة.

## Composer وcomposer.json

Composer هو مدير الاعتماديات المعتمد فعلياً في PHP — تفترضه تقريباً كل مشاريع PHP الحديثة، وكل إطار عمل رئيسي (Laravel، Symfony). يعلن المشروع اعتمادياته في `composer.json`:

```json
{
    "name": "acme/billing-app",
    "require": {
        "php": ">=8.2",
        "monolog/monolog": "^3.0"
    },
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    }
}
```

يضيف `composer require monolog/monolog` اعتمادية ويحدّث هذا الملف تلقائياً؛ ويقرأ `composer install` هذا الملف (وملف القفل، `composer.lock`) ويحمّل إصدارات دقيقة وقابلة لإعادة الإنتاج إلى `vendor/`.

قسم `autoload` هو ما يحل محل استدعاءات `require` اليدوية: يولّد Composer **محمّل تحميل تلقائي وفق PSR-4** يربط بادئة مساحة اسمية بدليل، بحيث تُحمَّل الفئات عند الطلب في أول مرة يُشار إليها فيها:

```php
<?php
require "vendor/autoload.php"; // the one require you still write by hand

use App\Billing\Invoice;
use Monolog\Logger;

$invoice = new Invoice(200.0);
$logger = new Logger("billing");
```

بذلك السطر الوحيد `require "vendor/autoload.php"`، تصبح فئاتك الخاصة ذات المساحة الاسمية تحت `src/` وكل حزمة Composer مثبَّتة متاحة دون أي تضمينات يدوية أخرى.
