يستحق الأمر توضيحاً مباشراً مسبقاً: **PHP في جوهرها متزامنة وحاجبة (blocking)، على أساس كل طلب على حدة.** يبدأ سكربت PHP قياسي (يعمل تحت PHP-FPM، أو mod_php الخاص بـ Apache، أو خادم التطوير المدمج) عندما يصل طلب، وينفَّذ من الأعلى للأسفل، ثم يخرج — لا توجد حلقة أحداث تعمل تحته كما هو الحال في Node.js، ولا كلمتا `async`/`await` مفتاحيتان في اللغة. هذه ليست ثغرة بقدر ما هي نتيجة متعمَّدة لنموذج PHP القائم على عدم مشاركة أي شيء بين الطلبات، وهي اختلاف حقيقي عن اللغات التي تعامل التزامن كجزء أساسي.

ما *تملكه* PHP أصلاً — وما يقصده الناس غالباً بشكل فضفاض عندما يقولون "PHP غير متزامنة" — هو **المولّدات (generators)**، التي تمنحك تكراراً كسولاً وفعّالاً من حيث الذاكرة. هذه ميزة لغة حقيقية ومن الدرجة الأولى. أما الإدخال/الإخراج غير الحاجب الحقيقي والتزامن الحقيقي، بالمقابل، فيحتاجان إلى شيء إضافي مبنيّ فوق PHP، وهذا ما تغطيه هذه الصفحة بصدق بدلاً من المبالغة في تقديمه.

## المولّدات وyield

تصبح الدالة التي تحتوي على `yield` مولّداً: بدلاً من حساب وإرجاع مصفوفة كاملة مسبقاً، تُنتج قيماً واحدة تلو الأخرى، عند الطلب، موقفة تنفيذها بين كل واحدة والأخرى.

```php
<?php

function countUpTo(int $max) {
    for ($i = 1; $i <= $max; $i++) {
        yield $i;
    }
}

foreach (countUpTo(5) as $n) {
    echo $n . " ";
}
echo "\n"; // 1 2 3 4 5
```

الفائدة الأساسية هي الذاكرة: مولّد يُنتج مليون قيمة لا يحتفظ أبداً بكل المليون في الذاكرة دفعة واحدة، بخلاف بناء وإرجاع مصفوفة. هذا يجعل المولّدات مناسبة طبيعياً لقراءة ملفات كبيرة سطراً بسطر، أو إنتاج تسلسل لا نهائي (أو طويل جداً فقط):

```php
<?php

function readLines(string $path) {
    $handle = fopen($path, "r");
    while (($line = fgets($handle)) !== false) {
        yield rtrim($line, "\n");
    }
    fclose($handle);
}

foreach (readLines("access.log") as $line) {
    if (str_contains($line, "ERROR")) {
        echo $line . "\n";
    }
}
```

## yield بمفاتيح، وyield كتعبير

يمكن لـ `yield` إنتاج أزواج مفتاح-قيمة، تماماً مثل مصفوفة ترابطية، ويمكن استخدامها أيضاً كتعبير يستقبل قيمة تُرسَل مرة أخرى إلى المولّد عبر `send()` — هذا ما يجعل المولّدات قوية بما يكفي لنمذجة تحكّم شبيه بالإجراءات المشتركة (coroutines)، وليس مجرد تكرار بسيط:

```php
<?php

function keyValuePairs() {
    yield "name" => "Ada";
    yield "role" => "admin";
}

foreach (keyValuePairs() as $key => $value) {
    echo "$key: $value\n";
}

function echoBack() {
    while (true) {
        $received = yield;
        echo "got: $received\n";
    }
}

$gen = echoBack();
$gen->current();     // primes the generator to its first yield
$gen->send("hello"); // got: hello
```

## أين تحتاج البرمجة غير المتزامنة الحقيقية إلى مساعدة

لا تمنحك المولّدات وحدها تزامناً — تعمل `countUpTo(5)` أعلاه بالكامل ضمن الطلب الحالي أحادي الخيط. للقيام بعمل متزامن فعلياً (معالجة اتصالات متزامنة كثيرة، تشغيل إدخال/إخراج دون حجب العملية بأكملها)، تحتاج PHP القياسية إلى بيئة تشغيل أو مكتبة مبنية فوق اللغة، وليس ميزة أساسية:

- **ReactPHP** و**Amp** مكتبتان في مساحة المستخدم تبنيان حلقة أحداث وتجريدات على غرار الوعود (promises) في PHP نفسها، مستخدمتين المولّدات داخلياً لتتيح لك كتابة كود قائم على `yield` يُقرأ إلى حد ما مثل `async`/`await`.
- **Swoole** و**OpenSwoole** إضافتا PHP (مكتوبتان بلغة C) تستبدلان النموذج التقليدي "طلب واحد لكل عملية" بعملية خادم طويلة الأمد بحلقة أحداث، ما يمنح PHP إجراءات مشتركة (coroutines) حقيقية وإدخال/إخراج غير حاجب على مستوى بيئة التشغيل.
- **FrankenPHP** خادم تطبيق أحدث يتيح أيضاً عمليات PHP طويلة الأمد بأسلوب العامل (worker)، كبديل لنموذج PHP-FPM-لكل-طلب الكلاسيكي.

لا شيء من هذه أجزاء من PHP الأساسية، واللجوء إليها غير معتاد بالنسبة لتطبيق ويب PHP قياسي — معظم كود PHP (طلب Laravel أو WordPress النموذجي) متزامن عن قصد، وهذا خيار افتراضي معقول، وليس قيداً يجب الالتفاف عليه. PHP غير المتزامنة نمط حقيقي ومستخدم في الإنتاج في مجالات محددة (عمّال طويلو الأمد، خوادم WebSocket، خدمات مصغّرة عالية الإنتاجية)، لكنها الاستثناء، وليست كيف تُكتَب معظم PHP.
