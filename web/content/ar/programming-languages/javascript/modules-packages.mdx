قبل ES6، لم يكن لدى JavaScript نظام وحدات مدمج — كان الكود مُقسَّماً عبر
وسوم `<script>` أو مُجمَّعاً بأدوات خارجية مثل CommonJS (`require`/
`module.exports` الخاصة بـNode). وحدات ES، باستخدام `import` و`export`،
هي الآن المعيار وتعمل بنفس الطريقة في المتصفحات (بـ`<script
type="module">`) وفي Node.js.

## التصديرات المسمّاة والافتراضية

يمكن لوحدة أن تُصدِّر قيماً مسمّاة متعددة، وتصديراً افتراضياً واحداً
اختيارياً.

```js
// math.js
export function add(a, b) {
  return a + b;
}

export function subtract(a, b) {
  return a - b;
}

export const PI = 3.14159;

export default function multiply(a, b) {
  return a * b;
}
```

```js
// main.js
import multiply, { add, subtract, PI } from "./math.js";

console.log(add(2, 3));      // 5
console.log(multiply(2, 3));  // 6
console.log(PI);              // 3.14159
```

يجب أن تطابق الاستيرادات المسمّاة الأسماء المُصدَّرة بالضبط (أو تُعاد
تسميتها بـ`as`)، ويمكن أن يوجد تصدير افتراضي واحد كحد أقصى لكل وحدة، وهذا
سبب استيراده دون أقواس معقوفة.

```js
import multiply, { subtract as minus } from "./math.js";

console.log(minus(10, 4)); // 6
```

## استيراد مساحة الأسماء وإعادة التصدير

يمكنك سحب كل تصدير مسمّى لوحدة كـكائن واحد، ويمكن للوحدات إعادة تصدير
أشياء من وحدات أخرى — مفيد لبناء نقطة دخول "برميل" (barrel) واحدة لمجلد
من الملفات ذات الصلة.

```js
import * as MathUtils from "./math.js";
console.log(MathUtils.add(1, 1)); // 2

// utils/index.js — إعادة التصدير من ملفات متعددة
export { add, subtract } from "./math.js";
export { formatDate } from "./dates.js";
```

## package.json وnpm

يصف ملف `package.json` كل مشروع Node.js (ومعظم مشاريع الواجهة الأمامية):
اسم المشروع، وإصداره، واعتمادياته، والسكربتات التي تُشغِّلها بـ
`npm run`.

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "start": "node index.js",
    "test": "node --test"
  },
  "dependencies": {
    "express": "^4.19.0"
  },
  "devDependencies": {
    "eslint": "^9.0.0"
  }
}
```

يخبر `"type": "module"` نود أن يعامل ملفات `.js` كوحدات ES بدلاً من صيغة
CommonJS الأقدم — دونه، ترمي `import`/`export` خطأ صيغة وستحتاج
`require`/`module.exports` بدلاً منهما. يقرأ `npm install`
`dependencies` و`devDependencies` ويُنزِّل كل شيء (بالإضافة إلى
اعتمادياته الخاصة، تكرارياً) إلى `node_modules`، مُسجِّلاً الإصدارات
المحلولة الدقيقة في `package-lock.json` كي تكون التثبيتات قابلة لإعادة
الإنتاج عبر الأجهزة. تعني `^` في `"^4.19.0"` "أي إصدار متوافق بدءاً من
4.19.0، وحتى (لكن غير شامل) 5.0.0" — اصطلاح npm لنطاقات الإصدار
الدلالي (semantic versioning).

تُشحَن `dependencies` مع تطبيقك في الإنتاج؛ `devDependencies` (المدقّقات
اللغوية (linters)، مشغّلات الاختبار، أدوات التجميع) لازمة فقط أثناء
التطوير ويتخطاها `npm install --omit=dev` في تثبيتات الإنتاج.
