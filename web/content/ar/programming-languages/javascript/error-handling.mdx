تعالج JavaScript الأخطاء بالاستثناءات: تُطلِق `throw` استثناءً، وتعالجه
`try`/`catch`/`finally`. خلافاً لبعض اللغات، تتيح لك JavaScript رمي أي
قيمة إطلاقاً — سلسلة نصية، رقم، كائن عادي — لكن عملياً ينبغي أن ترمي
دائماً `Error` (أو صنفاً فرعياً منه)، لأن كائنات `Error` تلتقط تتبع مكدس
(stack trace) عند نقطة إنشائها، وهو أمر لا يُقدَّر بثمن للتصحيح.

## try/catch/finally

```js
function parseConfig(json) {
  try {
    return JSON.parse(json);
  } catch (err) {
    console.error("Invalid config JSON:", err.message);
    return {};
  } finally {
    console.log("Parse attempt finished.");
  }
}

console.log(parseConfig('{"port": 8080}')); // { port: 8080 }
console.log(parseConfig("not json"));         // تُسجِّل الخطأ، تُعيد {}
```

تعمل `finally` سواء رُمي خطأ أم لا، وسواء أعادت كتلة `try` أو `catch`
مبكراً أم لا — إنها المكان الصحيح لتنظيف يجب أن يحدث على أي حال، مثل
إغلاق اتصال أو مسح علامة تحميل.

```js
function withLogging(fn) {
  console.log("starting");
  try {
    return fn();
  } finally {
    console.log("done"); // يعمل رغم أن كتلة try تعيد أعلاه
  }
}

withLogging(() => 42);
// starting
// done
```

## أصناف Error فرعية مخصَّصة

يتيح لك توسيع صنف `Error` المدمج إرفاق بيانات إضافية بخطأ وتمكين
المستدعين من تمييز أنواع الأخطاء بـ`instanceof`، بدلاً من تحليل رسائل
الخطأ كسلاسل نصية.

```js
class ValidationError extends Error {
  constructor(message, field) {
    super(message);
    this.name = "ValidationError"; // يظهر في تتبعات المكدس والسجلات
    this.field = field;
  }
}

function validateAge(age) {
  if (typeof age !== "number" || age < 0) {
    throw new ValidationError("Age must be a non-negative number", "age");
  }
  return age;
}

try {
  validateAge(-5);
} catch (err) {
  if (err instanceof ValidationError) {
    console.log(`${err.name}: ${err.message} (field: ${err.field})`);
  } else {
    throw err; // ليس لنا — دعه ينتشر بدلاً من ابتلاعه بصمت
  }
}
// ValidationError: Age must be a non-negative number (field: age)
```

إعادة رمي أخطاء غير معروفة من كتلة `catch` — بدلاً من ابتلاع كل شيء —
مهمة: `catch` لا تتحقق مما التقطته يمكن أن تخفي أخطاء حقيقية (`TypeError`
من خطأ مطبعي، مثلاً) خلف أي معالجة عامة كتبتها للخطأ الذي توقعته.

## الأخطاء والكود غير المتزامن

تعمل `try`/`catch` أيضاً حول Promises منتظَرة (awaited) تُرفَض، وهو أحد
أكبر مكاسب راحة الاستخدام لـ`async`/`await` على سلاسل `.then()`/
`.catch()` الخام:

```js
async function fetchUser(id) {
  try {
    const response = await fetch(`/api/users/${id}`);
    if (!response.ok) {
      throw new Error(`Request failed with status ${response.status}`);
    }
    return await response.json();
  } catch (err) {
    console.error("Could not fetch user:", err.message);
    return null;
  }
}
```

تحتاج سلسلة `.then()` عادية إلى `.catch()` في النهاية لمعالجة الرفض؛
نسيان واحدة يترك Promise مرفوضاً يختفي بصمت (أو يُطلِق تحذير "رفض غير
معالَج") بدلاً من مُعالجته إطلاقاً.
