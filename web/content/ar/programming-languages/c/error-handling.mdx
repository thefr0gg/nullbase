لا تملك C `try`/`catch`، ولا `throw`، ولا مفهوم استثناء يفكّ مكدس الاستدعاء. كل دالة يمكن أن تفشل تُشير إلى ذلك عبر **قيمة إرجاعها**، وتضبط دوال المكتبة القياسية التي تتعامل مع نظام التشغيل إضافة إلى ذلك متغيراً عاماً يُدعى `errno` يصف *سبب* فشلها. لا توجد آلية على مستوى اللغة تُجبر المستدعي على فحص أيهما — تجاهل قيمة إرجاع أو `errno` يُترجَم بلا مشكلة وهو مصدر شائع لأخطاء حقيقية.

## اصطلاحات رموز الإرجاع

الاصطلاح السائد في C هو: أرجع قيمة خاصة (غالباً `-1`، أو `NULL`، أو رمز حالة غير صفري) للإشارة إلى الفشل، وقيمة عادية للإشارة إلى النجاح. تتبع `main` نفسها هذا — إرجاع `0` يعني النجاح، وغير الصفري يعني الفشل، ويمكن للشل أو العملية المستدعية فحص ذلك:

```c
#include <stdio.h>

int divide(int a, int b, int *result) {
    if (b == 0) {
        return -1; /* failure: division by zero */
    }
    *result = a / b;
    return 0; /* success */
}

int main(void) {
    int result;

    if (divide(10, 2, &result) == 0) {
        printf("10 / 2 = %d\n", result);
    } else {
        printf("error: division by zero\n");
    }

    if (divide(10, 0, &result) != 0) {
        printf("error: division by zero\n");
    }

    return 0;
}
```

لاحظ أن الجواب الفعلي يُسلَّم عبر معامل مُخرَج (`int *result`)، لأن قيمة الإرجاع نفسها محجوزة لحالة النجاح/الفشل — نمط يظهر باستمرار كلما احتاجت "النتيجة الحقيقية" لدالة وحالة خطئها إلى نقل منفصل.

## errno واستدعاءات النظام

غالباً ما تُرجع دوال المكتبة القياسية والدوال المتعاملة مع نظام التشغيل (مثل `fopen`، والاستدعاءات القريبة من `malloc`، واستدعاءات نظام POSIX) قيمة حارسة مثل `NULL` عند الفشل وتضبط `errno` العام إلى رمز يحدد المشكلة تحديداً. تحوّل `strerror` ذلك الرمز إلى رسالة قابلة للقراءة البشرية:

```c
#include <stdio.h>
#include <errno.h>
#include <string.h>

int main(void) {
    FILE *file = fopen("does_not_exist.txt", "r");

    if (file == NULL) {
        printf("failed to open file: %s\n", strerror(errno));
        return 1; /* nonzero exit code signals failure to the OS */
    }

    fclose(file);
    return 0;
}
```

`errno` ذات معنى فقط مباشرة بعد استدعاء فشل — لا تُعاد إلى 0 عند النجاح، لذا فإن فحصها *قبل* فحص قيمة إرجاع الدالة نفسها (أو فحصها بعد استدعاء آخر غير متعلق تماماً) يقرأ خطأً قديماً من شيء مختلف تماماً.

## لا استثناءات، لكن setjmp/longjmp موجودة

تتضمن مكتبة C القياسية `setjmp.h`، الذي يسمح بنوع من القفز غير المحلي يمكنه فك عدة إطارات مكدس دفعة واحدة — أقرب ما تملكه C إلى تحكم بمسار التنفيذ على طراز الاستثناءات، رغم ندرته في الكود العادي لأنه يتجاوز التنظيف الطبيعي (لا توجد هدّامات (destructors) لتعمل تلقائياً، لأن C لا تملك أياً منها):

```c
#include <stdio.h>
#include <setjmp.h>

jmp_buf recoveryPoint;

void riskyOperation(int fail) {
    if (fail) {
        longjmp(recoveryPoint, 1); /* jumps back to setjmp, as if it returned 1 */
    }
    printf("risky operation succeeded\n");
}

int main(void) {
    if (setjmp(recoveryPoint) == 0) {
        riskyOperation(1); /* this call never returns normally */
    } else {
        printf("recovered from failure\n");
    }
    return 0;
}
```

يلتزم معظم كود C برموز الإرجاع البسيطة و`errno` — تظهر `setjmp`/`longjmp` أساساً في سياقات متخصصة مثل تنفيذ معالجة أخطاء لغة سكربت أو التعافي من مُعالج إشارة (signal handler)، لا في فحص الأخطاء اليومي.
