أنشأ **دينيس ريتشي** لغة C في مختبرات بيل في أوائل السبعينيات، وكان الهدف الأصلي منها إعادة كتابة نواة يونكس بلغة أكثر قابلية للنقل من الأسمبلي. بعد أكثر من خمسين عاماً، لا تزال هذه اللغة هي التي تُكتَب بها معظم أنوية أنظمة التشغيل، والبرامج الثابتة (firmware) المدمجة، وبيئات تشغيل اللغات الأخرى (CPython، نواة JVM، Lua)، والمكتبات منخفضة المستوى (`libc`، وSQLite، وzlib). تُترجَم C مباشرة إلى كود آلة، ولا تملك جامع قمامة ولا شبكة أمان في وقت التشغيل، وتمنح المبرمج تحكماً شبه كامل في تخطيط الذاكرة وسلوك المعالج — وهذا بالضبط ما يجعلها سريعة للغاية وسهلة التسبب في كوارث في آنٍ واحد.

كل ما يغطيه هذا الموقع عن C ينبع من قرار تصميمي واحد: تثق C بالمبرمج ثقة كاملة. لا يوجد فحص لحدود المصفوفات، ولا إدارة تلقائية للذاكرة، ولا استثناءات — فقط دوال، ومؤشرات، ومكتبة قياسية صغيرة جداً. لغات حديثة مثل Rust وGo وُجدت إلى حد كبير كردة فعل على مقدار الثمن الذي تدفعه فعلياً مقابل تلك الثقة، لكن مباشرة C هي أيضاً السبب في بقائها اللغة المشتركة التي تُبنى بها بيئة تشغيل كل لغة أخرى تقريباً.

## برنامج C بسيط

```c
#include <stdio.h>

int main(void) {
    printf("Hello, nullbase!\n");
    return 0;
}
```

يستورد `#include <stdio.h>` تصريحات دوال الإدخال/الإخراج القياسية مثل `printf`. `main` هي نقطة الدخول التي يجب أن يمتلكها كل برنامج C؛ إرجاع `0` يخبر نظام التشغيل أن البرنامج انتهى بنجاح (بينما تشير القيمة غير الصفرية إلى خطأ لأي جهة استدعت البرنامج — سكربت شل، أداة بناء، وما إلى ذلك).

## ترجمة البرنامج وتشغيله

تُترجَم C مسبقاً (ahead of time)، وليست مفسَّرة — لا توجد بيئة تشغيل لـ C تقرأ الكود المصدري سطراً بسطر. يترجم المترجم (`gcc` أو `clang`) الكود المصدري إلى ملف تنفيذي أصلي *قبل* أن يعمل أبداً:

```c
#include <stdio.h>

int square(int n) {
    return n * n;
}

int main(void) {
    for (int i = 1; i <= 5; i++) {
        printf("%d squared is %d\n", i, square(i));
    }
    return 0;
}
```

بعد حفظه باسم `squares.c`، يصبح ملفاً تنفيذياً قابلاً للتشغيل بواسطة:

```bash
gcc squares.c -o squares
./squares
```

لا توجد خطوة لمدير حزم، ولا مفسِّر يُستدعى — يقرأ `gcc` ملف `.c`، ويحل محل `#include`، وينتج ملفاً تنفيذياً مستقلاً. هذا الفصل بين الترجمة والتشغيل (بدلاً من JIT أو مفسِّر) هو سبب انطلاق برامج C فوراً، وسبب كون خطأ مثل القراءة بعد نهاية مصفوفة انهياراً في وقت التشغيل، وليس خطأ ترجمة كان بإمكان المترجم اكتشافه لك.

## ما القادم

يشرح باقي هذا القسم بنية C ومتغيراتها، والتحكم بمسار التنفيذ، والدوال، والمصفوفات والسلاسل النصية، والبُنى (بديل C عن الأصناف)، ومعالجة الأخطاء عبر رموز الإرجاع، وكيفية بناء البرامج متعددة الملفات، وأخيراً المؤشرات وإدارة الذاكرة اليدوية — وهو الجزء الذي أزالته معظم اللغات الأخرى عمداً من C.
