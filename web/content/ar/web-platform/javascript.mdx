JavaScript هي اللغة الوحيدة التي تشغّلها المتصفحات أصلاً. شيئان يميّزانها مقارنة بمعظم لغات جهة الخادم: إنها **أحادية الخيط** (مكدس استدعاء واحد، لا تنفيذ متوازٍ حقيقي لكودك)، وتقريباً كل شيء يلامس العالم الخارجي — مؤقت، طلب شبكة، حدث DOM — هو **غير متزامن**، يُعالَج عبر دوال رد النداء، أو الـPromises، أو `async`/`await` بدلاً من حجب ذلك الخيط الوحيد.

## حلقة الأحداث

هذه هي الآلية التي توفّق بين "أحادي الخيط" و"غير متزامن": يعمل الكود المتزامن دائماً حتى الاكتمال أولاً، ثم تعمل دوال رد النداء غير المتزامنة المصفوفة بترتيب محدد وحتمي — لا وقتما تصادف اكتمالها.

## لماذا يفاجئ هذا الترتيب الناس

```js
console.log("1");
setTimeout(() => console.log("2"), 0);
Promise.resolve().then(() => console.log("3"));
console.log("4");
// logs: 1, 4, 3, 2 — not 1, 2, 3, 4
```

`setTimeout(fn, 0)` لا تعني "شغّل فوراً" — بل تعني "أضِف إلى طابور المهام الكبرى (macrotask) بمجرد انقضاء التأخير (عملياً: بأسرع وقت ممكن)"، وطابور المهام الصغرى (microtask) — الذي تنضم إليه دوال رد نداء الـPromise — يُفرَّغ دائماً بالكامل قبل تشغيل المهمة الكبرى التالية، حتى لو أُضيفت تلك المهمة بتأخير 0 مللي ثانية.

## Promises و async/await

`async`/`await` هي سكر نحوي فوق الـPromises، لا نموذج تزامن مختلف — الدالة `async` تعيد دائماً Promise، و`await` تُوقِف تلك الدالة (لا الخيط بأكمله) حتى تُسوَّى الـPromise المنتظَرة، مضيفةً بقية الدالة إلى طابور المهام الصغرى.

```js
async function getUser(id) {
  const res = await fetch(`/api/users/${id}`); // pauses here, thread is free
  return res.json();                            // resumes once the fetch settles
}
```

## أين يأتي دور DOM

JavaScript في المتصفح تنتهي دائماً تقريباً بقراءة DOM أو تعديلها — [DOM](/ar/web-platform/dom) هي الشجرة الحية التي يبنيها المتصفح من [HTML](/ar/web-platform/html) المحلَّل. أحداث DOM (نقرة، ضغطة مفتاح) هي بالضبط ذلك النوع من العمل غير المتزامن الموصوف أعلاه: دالة رد نداء تُضاف إلى الطابور لتعمل بمجرد انتهاء الكود المتزامن الحالي.
