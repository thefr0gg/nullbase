تحذف **DELETE** مورداً. بعد نجاح DELETE، يختفي المورد.

## DELETE أساسية

```http
DELETE /api/users/42 HTTP/1.1
Host: api.example.com
```

**الاستجابة:**
```http
HTTP/1.1 204 No Content
```

---

## رموز حالة الاستجابة

- **200 OK** — حُذف، ويحتوي نص الاستجابة على تفاصيل
- **202 Accepted** — الحذف في قائمة الانتظار/قيد المعالجة
- **204 No Content** — حُذف بنجاح، بلا نص
- **404 Not Found** — المورد غير موجود
- **410 Gone** — المورد محذوف بالفعل

---

## DELETE مع معاملات استعلام

حذف عناصر محددة أو بشروط:

```http
DELETE /api/sessions/current HTTP/1.1

DELETE /api/files?older_than=2023-01-01 HTTP/1.1
```

---

## تكرارية وآمنة؟

- **تكرارية:** نعم — استدعاء DELETE مرتين له نفس أثر استدعائها مرة واحدة (المورد محذوف).
- **آمنة:** لا — تغيّر حالة الخادم (تحذف بيانات).

---

## أنماط شائعة

**الحذف المتسلسل:**
```http
DELETE /api/users/42?cascade=true HTTP/1.1
```

**الحذف الناعم (وضع علامة كمحذوف، دون حذفه فعلياً):**
```http
DELETE /api/users/42 HTTP/1.1
```
قد يعيد الخادم 200 مع `{ deleted: true, id: 42 }` بدلاً من حذفه فعلياً.

---

## أخطاء شائعة

**تجنّب:** افتراض أن DELETE فورية دائماً — قد توضع في قائمة انتظار (202 Accepted).

**تجنّب:** عدم استخدام 404 للموارد المفقودة — إذا كان المورد محذوفاً بالفعل، أعد 404.

**تجنّب:** DELETE مع نص — عادةً لا تحتاج DELETE نصاً. أدرج الشروط في عنوان URL أو الترويسات إن لزم.
