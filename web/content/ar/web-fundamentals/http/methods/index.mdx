يسمّي كل طلب HTTP **طريقة** — GET، وPOST، وPUT، وغيرها — تخبر الخادم بنوع العملية التي يجب إجراؤها على مورد. الاختيار مهم أبعد من الدلالة اللغوية: فهو يحدد ما إذا كان الطلب آمناً لإعادة المحاولة، وما إذا كان بإمكان Cache حفظ الاستجابة، وما إذا كان يُسمح لـ Proxy وسيط أصلاً بتمرير نص.

## كل الطرق بلمحة

| الطريقة | الغرض | لديها نص؟ | آمنة؟ | تكرارية؟ | قابلة للتخزين المؤقت؟ |
|--------|---------|-----------|-------|------------|-----------|
| GET | استرجاع مورد | لا | نعم | نعم | نعم |
| HEAD | جلب الترويسات فقط (بلا نص) | لا | نعم | نعم | نعم |
| POST | إنشاء مورد أو تشغيل إجراء | نعم | لا | لا | ربما |
| PUT | استبدال مورد | نعم | لا | نعم | لا |
| PATCH | تحديث مورد جزئياً | نعم | لا | لا | لا |
| DELETE | حذف مورد | لا | لا | نعم | لا |
| OPTIONS | وصف خيارات التواصل | لا | نعم | نعم | لا |
| CONNECT | إنشاء Tunnel (للـ Proxies) | لا | لا | لا | لا |
| TRACE | استعادة صدى الطلب (للتصحيح) | لا | نعم | نعم | لا |

## شرح الخصائص الأساسية

### آمنة
الطريقة **الآمنة** لا تعدّل البيانات على الخادم. للقراءة فقط. GET وHEAD وOPTIONS آمنة. POST وPUT وPATCH وDELETE ليست كذلك.

يجب ألا تعدّل الخوادم أبداً البيانات استجابةً لطلب آمن.

### تكرارية
استدعاء طريقة **تكرارية** عدة مرات له نفس أثر استدعائها مرة واحدة.

- **GET**: استدعها 1000 مرة، نفس النتيجة.
- **PUT**: استدعها 1000 مرة، نفس النتيجة (ينتهي المورد بنفس الحالة).
- **DELETE**: استدعها 1000 مرة، نفس النتيجة (يبقى محذوفاً).
- **POST**: **ليست** تكرارية. استدعها مرتين، وقد تنشئ موردين.

الطرق التكرارية آمنة لإعادة المحاولة. إذا فشلت شبكتك وأعدت المحاولة، لن تفعل شيئاً مرتين عن طريق الخطأ.

### قابلة للتخزين المؤقت
هل يمكن **تخزين** الاستجابة **مؤقتاً** بواسطة المتصفح أو تخزينات مؤقتة وسيطة؟

- استجابات GET: تُخزَّن مؤقتاً عادةً.
- استجابات POST: فقط إذا نصّت ترويسات Cache صريحة على ذلك.
- PUT وPATCH وDELETE: لا تُخزَّن مؤقتاً (لأنها تعدّل البيانات).

## أكثر الطرق شيوعاً

### [GET](/ar/web-fundamentals/http/methods/get)
استرجاع مورد. هذه هي الطريقة الافتراضية التي يستخدمها متصفحك.

```http
GET /api/users/42 HTTP/1.1
Host: api.example.com
```

### [POST](/ar/web-fundamentals/http/methods/post)
إنشاء مورد أو تشغيل إجراء. يتطلب نصاً.

```http
POST /api/users HTTP/1.1
Host: api.example.com
Content-Type: application/json

{
  "name": "Alice",
  "email": "alice@example.com"
}
```

### [PUT](/ar/web-fundamentals/http/methods/put)
استبدال مورد كاملاً. يتطلب المورد الكامل في النص.

```http
PUT /api/users/42 HTTP/1.1
Host: api.example.com
Content-Type: application/json

{
  "id": 42,
  "name": "Alice",
  "email": "alice@example.com"
}
```

### [DELETE](/ar/web-fundamentals/http/methods/delete)
حذف مورد.

```http
DELETE /api/users/42 HTTP/1.1
Host: api.example.com
```

### [PATCH](/ar/web-fundamentals/http/methods/patch)
تحديث مورد جزئياً (أرسل فقط الحقول التي تغيّرها).

```http
PATCH /api/users/42 HTTP/1.1
Host: api.example.com
Content-Type: application/json

{
  "email": "alice@example.com"
}
```

## طرق أقل شيوعاً

### [HEAD](/ar/web-fundamentals/http/methods/head)
مثل GET، لكن لا يرسل الخادم نص الاستجابة. مفيدة للتحقق من وجود مورد أو حجمه دون تنزيله.

### [OPTIONS](/ar/web-fundamentals/http/methods/options)
تسأل الخادم عن الطرق المسموحة. تُستخدم للفحوصات التمهيدية لـ CORS (عندما يتحقق متصفحك مما إذا كان طلب عابر للأصول مسموحاً).

### [CONNECT](/ar/web-fundamentals/http/methods/connect)
تنشئ Tunnel عبر Proxy. تُستخدم لـ HTTPS عبر الـ Proxies. نادراً ما تستخدم هذه مباشرة.

### [TRACE](/ar/web-fundamentals/http/methods/trace)
تستعيد صدى الطلب إليك (للتصحيح). تعطّل معظم الخوادم هذا لأسباب أمنية.

## الإنشاء مقابل التحديث

**الإنشاء (POST):**
- العميل لا يعرف المعرّف
- الخادم يولّد المعرّف
- الطلب: `/api/users` مع نص
- الاستجابة: `201 Created` مع المورد الجديد

**الاستبدال (PUT):**
- العميل يعرف المعرّف (في عنوان URL)
- يرسل العميل المورد الكامل
- الطلب: `/api/users/42` مع نص كامل
- الاستجابة: `200 OK` أو `204 No Content`

**التحديث الجزئي (PATCH):**
- العميل يعرف المعرّف
- يرسل العميل فقط الحقول التي تغيّرت
- الطلب: `/api/users/42` مع نص جزئي
- الاستجابة: `200 OK` أو `204 No Content`

## أخطاء شائعة

**تجنّب:** استخدام GET لبيانات حساسة — معاملات الاستعلام مرئية في عناوين URL. استخدم POST.

**تجنّب:** الاعتقاد بأن GET يمكن أن يكون له نص — تتجاهله معظم الخوادم. استخدم POST بدلاً من ذلك.

**تجنّب:** استخدام POST لكل شيء — POST ليست تكرارية. استخدم GET للجلب فقط، وPUT/PATCH للتحديثات، وDELETE للحذف.

**تجنّب:** عدم التحقق مما إذا كانت الطريقة تكرارية — قبل إعادة محاولة طلب، تحقق مما إذا كانت الطريقة آمنة لإعادة المحاولة.

**تجنّب:** الخلط بين PUT وPATCH — PUT تستبدل الشيء كاملاً، وPATCH تحدّث فقط ما ترسله.
