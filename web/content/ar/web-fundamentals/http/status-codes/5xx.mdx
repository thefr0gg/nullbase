تعني حالة `5xx` أن الطلب كان صالحاً، لكن الخادم فشل في معالجته — استثناء غير معالَج، أو خدمة تالية لم تستجب، أو نفاد السعة. خلافاً لـ `4xx`، عادةً لم يفعل العميل شيئاً خاطئاً، لذا قد تنجح إعادة المحاولة لاحقاً.

## أكثر رموز 5xx شيوعاً

| الرمز | الاسم | المعنى |
|------|------|---------|
| 500 | Internal Server Error | خطأ خادم عام (حدث خلل ما). |
| 502 | Bad Gateway | يعمل الخادم كـ Proxy واستلم استجابة غير صالحة. |
| 503 | Service Unavailable | الخادم معطَّل مؤقتاً (صيانة، أو تحميل زائد). |
| 504 | Gateway Timeout | يعمل الخادم كـ Proxy ولم يستلم استجابة في الوقت المحدد. |

---

## تفصيل شامل

### 500 Internal Server Error
خطأ خادم عام. حدث خلل ما، ولا يريد الخادم قول ماهيته.

```http
POST /api/users HTTP/1.1
Content-Type: application/json

{
  "name": "Alice",
  "email": "alice@example.com"
}

HTTP/1.1 500 Internal Server Error
{
  "error": "Internal server error"
}
```

**الاستخدام:** عندما:
- أُلقي استثناء غير متوقع
- فشل استعلام قاعدة بيانات
- يحتوي الكود على خلل
- فشلت خدمة خارجية

**ممارسة جيدة:** لا تُظهر تفاصيل داخلية في استجابات 500 (لا آثار تكديس للعملاء). سجّلها على الخادم لتصحيح الأخطاء.

---

### 502 Bad Gateway
يعمل الخادم كـ Proxy (أو موازن حمل) واستلم استجابة غير صالحة من الخادم الخلفي.

```http
GET /api/data HTTP/1.1

HTTP/1.1 502 Bad Gateway
{
  "error": "Bad gateway"
}
```

**الاستخدام:** عندما:
- لا يستطيع Reverse Proxy الاتصال بالخلفية
- ترسل الخلفية HTTP مشوَّهاً
- تعطّل الخادم الخلفي

---

### 503 Service Unavailable
الخادم غير قادر مؤقتاً على معالجة الطلب. عادةً مؤقت (صيانة، وتحميل زائد، وإعادة تشغيل).

```http
GET /api/data HTTP/1.1

HTTP/1.1 503 Service Unavailable
Retry-After: 120
{
  "error": "Service temporarily unavailable"
}
```

**الاستخدام:** عندما:
- الخادم تحت الصيانة
- قاعدة البيانات معطَّلة
- الخادم محمَّل زيادة
- الخادم يعيد التشغيل

**ممارسة جيدة:** أدرج ترويسة `Retry-After` حتى يعرف العميل متى يعيد المحاولة.

---

### 504 Gateway Timeout
يعمل الخادم كـ Proxy واستغرقت الخلفية وقتاً طويلاً للاستجابة.

```http
GET /api/expensive-query HTTP/1.1

HTTP/1.1 504 Gateway Timeout
{
  "error": "Gateway timeout"
}
```

**الاستخدام:** عندما:
- ينتظر Reverse Proxy الخلفية طويلاً
- يستغرق استدعاء API خلفي وقتاً طويلاً
- يستغرق استعلام قاعدة بيانات وقتاً طويلاً

---

## رموز 5xx أخرى

- **501 Not Implemented** — الطريقة أو الميزة غير منفَّذة بعد.
- **505 HTTP Version Not Supported** — لا يدعم الخادم إصدار HTTP.

---

## متى تستخدم 5xx مقابل 4xx

| السيناريو | الرمز |
|----------|------|
| أرسل العميل JSON غير صالح | 400 |
| فشلت قاعدة البيانات في حفظ البيانات | 500 |
| العميل غير مسجَّل الدخول | 401 |
| تعطّل الخادم | 500 |
| المورد غير موجود | 404 |
| الخادم معطَّل للصيانة | 503 |

---

## كيف يجب أن يتعامل العملاء مع أخطاء 5xx

- **أعد المحاولة مع تأخير متزايد** — انتظر وحاول مجدداً (استخدم `Retry-After` إن وُجدت).
- **لا تعد محاولة 500 فوراً** — تأخير أُسّي (1ث، 2ث، 4ث، 8ث...).
- **أعد محاولة 503 بعد الوقت المحدَّد** — أخبرك الخادم متى تحاول مجدداً.
- **لا تعد محاولة 501** — الميزة غير منفَّذة؛ جرّب نهجاً مختلفاً.

---

## أخطاء شائعة

**تجنّب:** إعادة 500 لأخطاء العميل — استخدم 4xx لأخطاء العميل (400، و401، و403، و404، وغيرها).

**تجنّب:** إظهار آثار التكديس للعملاء — سجّل الأخطاء على الخادم، لكن أرسل رسائل عامة للعملاء.

**تجنّب:** عدم تضمين Retry-After في 503 — أخبر العميل متى يعيد المحاولة.

**تجنّب:** عدم تسجيل أخطاء 5xx — هذه أخطاء برمجية. سجّلها حتى تستطيع إصلاحها.
