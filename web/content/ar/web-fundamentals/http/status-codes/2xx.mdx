تعني حالة `2xx` أن الخادم استقبل الطلب وفهمه وقبله. أي رمز يعود — `200` عادية، أو `201` بعد إنشاء شيء، أو `204` بلا شيء لعرضه — يعتمد على ما طلبه الطلب فعلياً.

## أكثر رموز 2xx شيوعاً

| الرمز | الاسم | متى تُستخدم |
|------|------|------------|
| 200 | OK | نجاح عام. كل شيء نجح. |
| 201 | Created | أُنشئ المورد بنجاح (POST). |
| 202 | Accepted | قُبل الطلب لكن المعالجة غير متزامنة. |
| 204 | No Content | نجاح، لكن لا يوجد نص لإعادته (DELETE وPATCH). |

---

## تفصيل شامل

### 200 OK
نجح الطلب. أدرج النتيجة في نص الاستجابة.

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "id": 42,
  "name": "Alice"
}
```

**استخدمه لـ:** GET، وPUT (عند إعادة المورد المحدَّث)، وPATCH.

---

### 201 Created
نجح الطلب وأُنشئ مورد جديد.

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/users/42

{
  "id": 42,
  "name": "Alice"
}
```

**استخدمه لـ:** POST (عند إنشاء مورد جديد).

**مهم:** أدرج ترويسة `Location` بعنوان URL للمورد الجديد.

---

### 202 Accepted
قُبل الطلب وهو قيد المعالجة، لكنه لم يكتمل بعد.

```http
HTTP/1.1 202 Accepted
Content-Type: application/json

{
  "status": "processing",
  "job_id": "abc-123"
}
```

**استخدمه لـ:** العمليات طويلة الأمد (رفع الملفات، والتحويل الترميزي، والتقارير).

يجب على العميل التحقق من حالة المهمة لاحقاً باستخدام معرّف المهمة.

---

### 204 No Content
نجح الطلب، لكن لا يوجد محتوى لإعادته.

```http
HTTP/1.1 204 No Content
```

**استخدمه لـ:** DELETE، وPATCH (عندما لا تحتاج لإعادة المورد المحدَّث).

**مهم:** لا يحتوي رد 204 **أي** نص (ولا حتى `{}`).

---

## رموز 2xx أخرى

- **205 Reset Content** — نجاح، ويجب على العميل إعادة ضبط النموذج/الواجهة.
- **206 Partial Content** — إعادة جزء فقط من مورد (طلب نطاق).

---

## أخطاء شائعة

**تجنّب:** استخدام 200 عندما يجب استخدام 201 — يجب أن يعيد POST الذي ينشئ مورداً 201، وليس 200.

**تجنّب:** استخدام 204 مع إرسال نص مع ذلك — إذا أرسلت 204، لا تُضمّن نصاً.

**تجنّب:** نسيان ترويسة Location في 201 — أدرج مكان الوصول إلى المورد الجديد.
