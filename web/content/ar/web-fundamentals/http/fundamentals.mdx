**بروتوكول نقل النص التشعبي (HTTP)** هو البروتوكول المستخدم لنقل البيانات عبر الشبكة العنكبوتية العالمية. هو الطريقة التي يجلب بها متصفحك صفحات الويب، وكيف يرسل هاتفك بيانات إلى الخوادم، وكيف تتواصل واجهات برمجة التطبيقات (APIs).

## ما الذي يميّز HTTP

### عديم الحالة
كل طلب مستقل. لا يتذكر الخادم الطلبات السابقة إلا إذا أخبرته صراحةً (عبر ملفات تعريف الارتباط، والجلسات، وغيرها). هذا يبقي الخادم بسيطاً وقابلاً للتوسّع.

### الطلب–الاستجابة
يبدأ التواصل دائماً من **العميل**. لا يرسل الخادم بيانات أبداً ما لم يُطلب منه ذلك. النمط هو:

1. يرسل العميل طلباً
2. يعالجه الخادم
3. يرسل الخادم استجابة
4. قد يُغلق الاتصال أو يبقى مفتوحاً لإعادة الاستخدام

### قائم على النص (في معظمه)
رسائل HTTP هي في معظمها نص قابل للقراءة (خلافاً للبروتوكولات الثنائية). هذا يجعله قابلاً لتصحيح الأخطاء والفحص.

```http
GET /api/users HTTP/1.1
Host: example.com
Content-Type: application/json

```

كل طلب يحتوي على:
- **طريقة** (GET، وPOST، وPUT، وDELETE، وغيرها)
- **عنوان URL** (أي مورد)
- **ترويسات** (بيانات وصفية)
- **نص** (اختياري، البيانات المرسَلة)

كل استجابة تحتوي على:
- **رمز الحالة** (200، و404، و500، وغيرها)
- **ترويسات** (بيانات وصفية عن الاستجابة)
- **نص** (المحتوى الفعلي)

## عناوين URL

يحدد عنوان URL المورد الذي تريده:

```text
https://api.example.com/v1/users/42?sort=name#details
```

- **https** — البروتوكول (المخطط)
- **api.example.com** — المضيف
- **/v1/users/42** — المسار (المورد)
- **?sort=name** — سلسلة الاستعلام (المعاملات)
- **#details** — الجزء (من جانب العميل فقط)

## الطرق

تخبر **الطريقة** الخادم بما تريد فعله:

| الطريقة | الغرض | لديها نص؟ | تكرارية؟ |
|--------|---------|-----------|------------|
| GET | استرجاع مورد | لا | نعم |
| POST | إنشاء مورد أو تشغيل إجراء | نعم | لا |
| PUT | استبدال مورد | نعم | نعم |
| PATCH | تحديث مورد جزئياً | نعم | لا |
| DELETE | حذف مورد | لا | نعم |
| HEAD | مثل GET، لكن الترويسات فقط | لا | نعم |
| OPTIONS | وصف خيارات التواصل | لا | نعم |

**التكرارية (Idempotent)** تعني أن استدعاءها عدة مرات له نفس أثر استدعائها مرة واحدة. آمنة لإعادة المحاولة.

## رموز الحالة

يستجيب الخادم برمز من ثلاثة أرقام يخبرك بما حدث:

| النطاق | المعنى | أمثلة |
|-------|---------|----------|
| 1xx | إعلامي | 100 Continue |
| 2xx | نجاح | 200 OK، و201 Created، و204 No Content |
| 3xx | إعادة توجيه | 301 Moved، و302 Found، و304 Not Modified |
| 4xx | خطأ من جهة العميل | 400 Bad Request، و401 Unauthorized، و404 Not Found |
| 5xx | خطأ من جهة الخادم | 500 Internal Server Error، و502 Bad Gateway |

## الترويسات

الترويسات هي أزواج مفتاح-قيمة تحمل بيانات وصفية عن الطلب أو الاستجابة.

**ترويسات الطلب الشائعة:**
- `Authorization` — من أنت (اسم مستخدم، ومفتاح API، ورمز)
- `Content-Type` — تنسيق النص (application/json، وform-data، وغيرها)
- `Accept` — التنسيقات التي يمكنك فهمها
- `User-Agent` — أي عميل يرسل الطلب

**ترويسات الاستجابة الشائعة:**
- `Content-Type` — تنسيق نص الاستجابة
- `Cache-Control` — مدة التخزين المؤقت لهذا
- `Set-Cookie` — تخزين بيانات على العميل
- `Location` — إلى أين تُعاد التوجيه (لاستجابات 3xx)

## النصوص (Bodies)

**النص** هو البيانات الفعلية المنقولة. يمكن أن يكون للطلبات نص (عادةً POST وPUT وPATCH). للاستجابات نص دائماً تقريباً.

**مثال طلب مع نص:**
```json
POST /api/users HTTP/1.1
Host: api.example.com
Content-Type: application/json

{
  "name": "Alice",
  "email": "alice@example.com"
}
```

**مثال استجابة مع نص:**
```json
HTTP/1.1 201 Created
Content-Type: application/json

{
  "id": 42,
  "name": "Alice",
  "email": "alice@example.com"
}
```

## الإصدارات

تطوّر HTTP. الاختلافات مهمة:

- **HTTP/1.0** (1991) — بسيط، طلب واحد لكل اتصال.
- **HTTP/1.1** (1997–الحاضر) — Keep-Alive، وخط الأنابيب، والترميز المجزّأ.
- **HTTP/2** (2015) — تعدد الإرسال، ودفع الخادم، والتأطير الثنائي.
- **HTTP/3** (2022) — مبني على QUIC للسرعة والموثوقية.

تستخدم معظم المتصفحات والخوادم الحديثة HTTP/1.1 أو HTTP/2. HTTP/3 في تزايد.

## أخطاء شائعة

**تجنّب:** الاعتقاد بأن طلبات GET يمكن أن يكون لها نص — تقبلها بعض الخوادم، لكنه ليس معياراً. استخدم POST بدلاً من ذلك.

**تجنّب:** استخدام GET لبيانات حساسة — معاملات الاستعلام مرئية في عناوين URL. استخدم POST مع نص وHTTPS.

**تجنّب:** عدم قراءة رمز الحالة — 200 يعني النجاح، لكن 201 و202 و204 تعني النجاح أيضاً (بمعانٍ مختلفة).

**تجنّب:** نسيان Content-Type — لن تحلّل بعض الخوادم نصك بدونها.

**تجنّب:** عدم معالجة إعادة توجيه 3xx — يحتاج عميلك لاتباع إعادة التوجيه تلقائياً (تفعله معظمها).
