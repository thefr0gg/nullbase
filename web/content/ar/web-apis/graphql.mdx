GraphQL هي لغة استعلام لواجهات برمجة التطبيقات، تُقدَّم عادةً عبر نقطة نهاية HTTP واحدة (غالباً `POST /graphql`). بدلاً من أن يقرر الخادم الشكل الذي تعيده كل نقطة نهاية، يصف **العميل** الشكل الذي يريده في جسم الاستعلام، ويعيد الخادم بالضبط ذلك — لا أكثر ولا أقل.

```graphql
query {
  user(id: 42) {
    name
    email
  }
}
```

تعكس الاستجابة شكل الاستعلام:

```json
{
  "data": {
    "user": { "name": "Grace Hopper", "email": "grace@example.com" }
  }
}
```

هذا العرض التوضيحي لا يشغّل مخططاً حقيقياً — إنه يُصدي الاستعلام والمتغيرات التي أرسلتها بحيث يبقى شكل الطلب/الاستجابة صادقاً في كونه محاكاة، لا خادم GraphQL حقيقياً.

## لماذا تلجأ إليها الفرق

- **لا إفراط في الجلب.** تعيد `GET /api/users/42` في REST أياً كانت الحقول التي تعيدها تلك النقطة دائماً. أما استعلام GraphQL فيعيد فقط الحقول المطلوبة.
- **لا نقص في الجلب.** هل تحتاج مستخدماً وآخر 5 طلبات له في شاشة واحدة؟ غالباً ما يحتاج عميل REST رحلتين ذهاباً وإياباً (`GET /api/users/42`، ثم `GET /api/users/42/orders`). يمكن لاستعلام GraphQL واحد طلب كليهما متداخلَين في طلب واحد.
- **نقطة نهاية واحدة، تتطور بدلاً من أن تُصدَر بالرابط.** يمكن إضافة حقول دون كسر الاستعلامات الحالية، ويمكن تمييز الحقول المهجورة بـ `@deprecated` وإزالتها لاحقاً — انظر [إصدار واجهة برمجة التطبيقات](/ar/web-apis/api-versioning) لمعرفة كيف يعالج REST نفس المشكلة بطريقة مختلفة.

## المقايضات

تستبدل GraphQL نموذج REST البسيط والقابل للتخزين المؤقت ذا المورد-لكل-رابط بمرونة الاستعلام. استجابة `GET /api/users/42` قابلة للتخزين المؤقت بشكل تافه عبر رابطها وحده (تعرف المتصفحات وشبكات CDN كيفية ذلك مسبقاً)؛ أما استجابة GraphQL فتعتمد على كامل جسم الاستعلام، لذا يحتاج التخزين المؤقت عملاً مقصوداً (استعلامات محفوظة، تسوية الاستجابة على العميل). وقد يكون استعلام متداخل بشكل تعسفي مكلفاً في حله على الخادم — تفرض واجهات GraphQL الحقيقية عادةً حداً أقصى لعمق/تعقيد الاستعلام للحماية من ذلك، وهو نسخته الخاصة من [تحديد المعدل](/ar/web-apis/rate-limiting).

## طالع أيضاً

- **[REST](/ar/web-apis/rest)** — البديل الموجَّه للموارد الذي تُقارَن به GraphQL في أغلب الأحيان.
- **[RPC](/ar/web-apis/rpc)** — طفرات GraphQL أقرب في روحها إلى استدعاءات RPC المسمّاة منها إلى نموذج فعل-على-مورد في REST.
