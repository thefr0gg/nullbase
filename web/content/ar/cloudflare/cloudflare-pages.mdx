تستضيف **Cloudflare Pages** المواقع الثابتة (والمواقع ذات منطق خفيف من جهة الخادم عبر Pages Functions) بنشر مدفوع مباشرة من مستودع Git — ادفع commit، واحصل على نشرة جديدة تلقائياً، مع حصول كل طلب سحب (pull request) على رابط معاينة خاص به قبل أي دمج إلى الإنتاج.

## سير العمل الأساسي

1. اربط مستودع GitHub أو GitLab.
2. اضبط أمر البناء (`npm run build`) ومجلد المخرجات (`dist` أو `out`).
3. كل دفعة (push) إلى فرع الإنتاج تُطلق نشرة إنتاج جديدة تلقائياً.
4. يحصل كل فرع وطلب سحب آخر على رابط معاينة فريد خاص به، بحيث يمكن للمراجعين رؤية النتيجة المعروضة فعلياً قبل الموافقة، لا مجرد الفرق (diff).

يزيل هذا النموذج المدفوع بـ Git خطوة "ابنِ محلياً، وارفع الملفات إلى مكان ما" يدوياً بالكامل — تاريخ النشر *هو* تاريخ الـ commits، والتراجع عن نشرة سيئة بسيط مثل إعادة ترقية نشرة سابقة معروفة بأنها جيدة.

## Pages Functions

بخلاف الاستضافة الثابتة الصرفة، تسمح Pages Functions لمسارات معينة بتشغيل كود من جهة الخادم — باستخدام نفس بيئة تشغيل Workers الأساسية، لكن باتفاقية توجيه قائمة على الملفات (`functions/api/hello.js` تصبح تلقائياً `/api/hello`) بدلاً من معالج `fetch` واحد يوجّه كل شيء بنفسه.

```js
// functions/api/hello.js
export async function onRequest(context) {
  return new Response("Hello from a Pages Function");
}
```

## التقارب مع Workers

ما فتئت Cloudflare توحّد تدريجياً بين Pages وWorkers العادية — يمكن الآن لمشروع Workers خدمة أصول ثابتة مباشرة (وهذا بالضبط ما يشغّل واجهة nullbase الأمامية نفسها، تصدير Next.js ثابت تخدمه إعدادات أصول ثابتة لـ Workers بدلاً من مشروع Pages منفصل)، ما يجعل "Pages مقابل Workers" أقل شقاً حاداً وأكثر سؤالاً عن سير النشر (الدفع عبر Git مقابل `wrangler deploy`) الأنسب لعملية فريق معين.
