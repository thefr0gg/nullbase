**R2** هو منتج تخزين الكائنات من Cloudflare — مبني تحديداً لنوع البيانات الثنائية الكبيرة وغير المهيكلة ([رفع الملفات](/ar/backend/file-uploads)، والنسخ الاحتياطية، والوسائط، والتصديرات) التي لا مكان لها في قاعدة بيانات علائقية مثل [D1](/ar/cloudflare/d1) أو مخزن مفتاح-قيمة صغير مثل [KV](/ar/cloudflare/kv). وهو متوافق عمداً من ناحية الواجهة البرمجية مع Amazon S3، الخيار الافتراضي الراسخ منذ زمن طويل لهذه الفئة، بحيث تعمل أدوات ومكتبات عميل S3 الحالية إلى حد كبير مع R2 بمجرد تغيير نقطة النهاية (endpoint).

## الاستخدام الأساسي

```js
export default {
  async fetch(request, env) {
    if (request.method === "PUT") {
      await env.MY_BUCKET.put("uploads/photo.jpg", request.body);
      return new Response("Uploaded");
    }
    const object = await env.MY_BUCKET.get("uploads/photo.jpg");
    return new Response(object?.body, {
      headers: { "content-type": object?.httpMetadata?.contentType ?? "application/octet-stream" },
    });
  },
};
```

تُخزَّن الكائنات وتُسترجَع بمفتاح (`uploads/photo.jpg`) — لا توجد لدى R2 بنية مجلدات حقيقية تحت السطح؛ المفتاح الذي يحتوي على شرطات مائلة هو مجرد سلسلة نصية *تبدو* هرمية، وهو نفس الاصطلاح الذي يستخدمه S3 نفسه.

## بلا رسوم مغادرة بيانات

الفارق الأبرز عن S3 ومعظم منافسيه في تخزين الكائنات: تفرض R2 رسوماً على التخزين والعمليات، لكن ليس على **egress** — عرض النطاق المستخدَم لتقديم البيانات إلى الإنترنت. تفرض العديد من مزوّدي تخزين الكائنات رسوماً معتبرة على egress، ما قد يجعل تقديم ملفات كبيرة (فيديو، أصول قابلة للتنزيل) على نطاق واسع مكلفاً بشكل مفاجئ بغض النظر عن رخص التخزين نفسه؛ يزيل نموذج تسعير R2 هذه التكلفة المحددة كلياً.

## روابط موقّعة مسبقاً للرفع المباشر

بدلاً من تمرير كل رفع كبير عبر Worker (وإنفاق وقت تنفيذ ووحدة معالجة Worker على بيانات هو فقط يمررها)، يمكن لـ Worker توليد **رابط موقّع مسبقاً (pre-signed URL)** — بيانات اعتماد محددة النطاق وقصيرة الأجل يستخدمها العميل للرفع مباشرة إلى R2، متجاوزاً Worker كلياً في نقل الملف الفعلي. هذا يعكس نفس النمط المشروح عموماً في [File Uploads](/ar/backend/file-uploads)، مع كون R2 هو وجهة التخزين الملموسة.
