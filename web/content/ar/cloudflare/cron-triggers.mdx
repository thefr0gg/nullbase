يشغّل **Cron Trigger** عامل Worker بجدول زمني — كل ساعة، كل ليلة، كل خمس دقائق — بدلاً من الاستجابة لطلب HTTP وارد. إنه إجابة منصة Workers على حاجة يواجهها كل نظام خلفي في النهاية: مهام تنظيف، تقارير مجدولة، مزامنات دورية للبيانات، لا شيء منها يُفعَّل طبيعياً بزيارة مستخدم لرابط.

## الضبط

```jsonc
// wrangler.jsonc
{
  "triggers": {
    "crons": ["0 3 * * *"]  // every day at 03:00 UTC
  }
}
```

يستخدم الجدول صياغة cron القياسية — خمسة حقول للدقيقة والساعة ويوم الشهر والشهر ويوم الأسبوع — نفس الصيغة التي يستخدمها `crontab` في أي نظام يونكس، بحيث تنتقل الألفة الحالية بتعابير cron مباشرة.

## المعالج المجدول

```js
export default {
  async fetch(request, env) {
    return new Response("This Worker also handles normal requests");
  },
  async scheduled(event, env, ctx) {
    await cleanupExpiredSessions(env.DB);
  },
};
```

يمكن لعامل Worker واحد أن ينفّذ كلاً من `fetch` (لطلبات HTTP العادية) و`scheduled` (يُستدعى تلقائياً في كل وقت cron مضبوط) — وهما نقطتا دخول مستقلتان إلى نفس Worker المنشور، تشتركان في نفس [الروابط (bindings)](/ar/cloudflare/workers-bindings) والكود، لكن تُفعَّلان بأحداث مختلفة تماماً.

## لماذا يناسب هذا نموذج Workers طبيعياً

بما أن Worker قصير العمر وعديم الحالة بطبيعته أصلاً، يكون الاستدعاء المجدول مطابقاً معمارياً للاستدعاء المُفعَّل بطلب — يبدأ، يعمل حتى الاكتمال، ثم يخرج، دون حاجة لعملية منفصلة تعمل باستمرار فقط لإبقاء ساعة تدق في مكان ما. هذا نموذج مختلف بشكل جوهري عن مهمة cron التقليدية، التي تتطلب خادماً فعلياً (أو على الأقل عملية دائمة) جالسة فقط لتكون متاحة في الوقت المجدول.

## ماذا تفعل فعلياً داخل معالج مجدول

من الاستخدامات الشائعة انتهاء صلاحية بيانات قديمة، ومزامنة مصدر بيانات خارجي دورياً، وإرسال رسائل ملخّص مجدولة، وتدوير السجلات أو تنظيفها — بشكل عام أي شيء يجب أن يحدث بانتظام لكنه ليس استجابة مباشرة لأي فعل مستخدم معيّن. بما أن معالجات `scheduled` ما زالت خاضعة لنفس حدود زمن المعالجة (CPU) التي تخضع لها معالجات `fetch`، عادة ما يكون من الأفضل نمذجة عمل دفعي طويل فعلياً كمعالج مجدول *يُضيف* عملاً إلى طابور (انظر [Queues](/ar/cloudflare/queues)) بدلاً من محاولة تنفيذه كله ضمن استدعاء واحد.
