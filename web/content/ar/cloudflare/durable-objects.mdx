**Durable Object** هو نسخة واحدة قابلة للعنونة من صنف (class)، محددة بشكل فريد بمعرّف (ID)، تضمن Cloudflare أنها تعمل في مكان واحد فقط في أي وقت — يُوجَّه كل طلب لذلك المعرّف المحدد إلى النسخة نفسها، أينما كانت تعيش حالياً. هذا هو الرد المباشر على مشكلة التنسيق التي تواجهها [الحوسبة الطرفية](/ar/devops/edge-computing) بشكل عام: [KV](/ar/cloudflare/kv) سريع في كل مكان لكنه متسق فقط في نهاية المطاف (eventually consistent)؛ أما Durable Object فمتسق بقوة بحكم البنية، لأنه لا توجد سوى نسخة واحدة منه لتكون متسقة معها.

## لماذا "نسخة واحدة" تحل مشكلة التنسيق

إذا أمكن معالجة طلبين لنفس المورد المنطقي (غرفة دردشة، جلسة لعبة، مُحدِّد معدل لكل مستخدم) بواسطة خادمين مختلفين في آنٍ واحد، فإن الحفاظ على اتساقهما يتطلب قفلاً موزّعاً، أو بروتوكولات توافق (consensus)، أو قبول الاتساق النهائي. توجيه كل طلب لذلك المورد إلى نسخة Durable Object محددة واحدة يتجاوز المشكلة كلياً — لا وجود لوصول متزامن يجب التوفيق بينه، لأنه يوجد مكان واحد بالضبط تعيش فيه الحالة فعلياً، وبنية Cloudflare التحتية هي من يتكفل بإيجاده والتوجيه إليه.

## الشكل الأساسي

```js
export class Counter {
  constructor(state, env) {
    this.state = state;
  }
  async fetch(request) {
    let count = (await this.state.storage.get("count")) || 0;
    count++;
    await this.state.storage.put("count", count);
    return new Response(String(count));
  }
}

// In the Worker routing to it:
const id = env.COUNTER.idFromName("global-counter");
const stub = env.COUNTER.get(id);
return stub.fetch(request);
```

يشتق `idFromName` معرّفاً ثابتاً من سلسلة نصية، بحيث يصل كل طلب يستخدم نفس الاسم إلى النسخة نفسها؛ و`state.storage` هو تخزين مفتاح-قيمة دائم ومعاملاتي (transactional) خاص بـ Durable Object نفسه، محصور بتلك النسخة الواحدة فقط.

## المفاضلة

بما أن Durable Object مثبَّت في موقع واحد ويعالج طلبات معرّفه بشكل متسلسل، فهو لا يتوسّع أفقياً كما يفعل Worker عديم الحالة — كل طلب لنفس المعرّف يمثل عنق زجاجة عبر تلك النسخة الواحدة، وهذا مقصود بالتصميم. هذه هي المفاضلة الصحيحة تحديداً حين يتطلب الاتساق فعلاً التسلسل؛ توزيع العمل عبر عدة كائنات Durable Objects بمفاتيح مختلفة (واحد لكل غرفة دردشة، لا واحد لكل الدردشة عالمياً) هو كيف تتجنب الأنظمة الحقيقية أن يصبح هذا العنق مشكلة في الممارسة العملية.

## طالع أيضاً

- **[Workers](/ar/cloudflare/workers)** — نموذج الحوسبة عديم الحالة الذي تمدّه Durable Objects تحديداً بحالة دائمة ومتسقة.
- **[KV](/ar/cloudflare/kv)** — البديل المتسق في نهاية المطاف، الأنسب حين لا يكون الاتساق الصارم مطلوباً.
- **[Edge Computing](/ar/devops/edge-computing)** — مشكلة التنسيق العامة التي تمثل Durable Objects رد Cloudflare المحدد عليها.
