يمثِّل XML (eXtensible Markup Language) البيانات المُهيكلة كعلامات مُسمَّاة ومتداخلة — أقرب في شكله إلى [HTML](/ar/web-platform/html) منه إلى [JSON](/ar/data-serialization/json)، بما أنه يستخدم نفس بنية الترميز. قبل أن يصبح JSON الافتراضي، كان XML صيغة تبادل البيانات المعيارية لواجهات برمجة تطبيقات الويب (SOAP، RSS، واجهات REST المبكرة تقريباً)؛ اليوم يبقى حياً بشكل رئيسي في أنظمة المؤسسات، وصيغ المستندات، والإعدادات.

```xml
<user id="42">
  <name>Grace Hopper</name>
  <active>true</active>
  <roles>
    <role>admin</role>
    <role>editor</role>
  </roles>
</user>
```

## السمات مقابل العناصر

يمكن التعبير عن نفس البيانات بطريقتَين مختلفتَين في XML، وهو مصدر غموض حقيقي لا يملكه JSON:

```xml
<user id="42" name="Grace Hopper" />
<!-- vs. -->
<user>
  <id>42</id>
  <name>Grace Hopper</name>
</user>
```

لا إحداهما "أصح" من الأخرى — تختلف الأعراف حسب المشروع، وهذا بحد ذاته انتقاد شائع لـ XML مقارنة بطريقة JSON الوحيدة والواضحة لكتابة زوج مفتاح-قيمة.

## أين لا يزال المعيار

يبقى XML المعيار الفعلي، لا مجرد إرث قديم، في عدة أماكن: خدمات الويب SOAP (شائعة في تكاملات المؤسسات/المالية/الرعاية الصحية)، صيغ ملفات Microsoft Office وOpenDocument (ملف `.docx` هو أرشيف zip لملفات XML)، تغذيات RSS/Atom، وSVG (وهو XML، وليس صيغة صورة منفصلة).

## طالع أيضاً

- **[JSON](/ar/data-serialization/json)** — الصيغة التي حلّت محل XML لمعظم واجهات برمجة التطبيقات الجديدة.
- **[YAML](/ar/data-serialization/yaml)** — خيار ثالث للبيانات المُهيكلة، محسَّن للتحرير البشري بدلاً من الصرامة الآلية.
