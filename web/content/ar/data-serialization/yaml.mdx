يمثِّل YAML ("YAML Ain't Markup Language") نفس البيانات المُهيكلة التي يمثِّلها [JSON](/ar/data-serialization/json) — كائنات، مصفوفات، سلاسل نصية، أرقام، قيم منطقية، null — مع استبدال علامات الترقيم بالمسافات البادئة، مُحسَّنة ليقرأها الإنسان ويكتبها يدوياً بدلاً من أن تُحلَّل بسرعة آلياً. نادراً ما تُستخدَم كصيغة طلب/استجابة فعلية لواجهة برمجة تطبيقات؛ موطنها الحقيقي هو ملفات الإعداد (Docker Compose، بيانات Kubernetes، خطوط أنابيب CI، إعداد بناء موقع من هذا النوع نفسه في بعض المكدّسات).

```yaml
id: 42
name: Grace Hopper
active: true
roles:
  - admin
  - editor
manager: null
```

نفس البيانات في JSON، للمقارنة:

```json
{ "id": 42, "name": "Grace Hopper", "active": true, "roles": ["admin", "editor"], "manager": null }
```

## المسافة البادئة ذات معنى، وغير متسامحة

خلافاً لأقواس JSON، تأتي بنية YAML بالكامل من المسافة البادئة — خلط علامات التبويب بالمسافات، أو الانحراف بمسافة واحدة، يُعد خطأ تحليل (أو أسوأ، يُغيِّر البنية بصمت) دون قوس إغلاق يلتقط الخطأ بصرياً.

```yaml
parent:
  child: value   # 2 spaces of indentation — a child of parent
sibling: value    # 0 spaces — a top-level key, not nested
```

## المطبّات الشهيرة

بما أن YAML يحاول استنتاج الأنواع من القيم غير المحاطة بعلامات اقتباس، فإن حفنة من السلاسل النصية المحددة لا تعني ما تبدو عليه:

```yaml
country: NO        # parsed as the boolean false in YAML 1.1 (Norway's country code!)
version: 1.10       # parsed as the number 1.1, not the string "1.10" — the trailing zero is lost
enabled: yes         # parsed as boolean true
```

هذا حقيقي، وليس افتراضياً — يُعرف عادة بـ"مشكلة النرويج (the Norway problem)"، وهذا سبب أن وضع القيمة بين علامتَي اقتباس صراحة (`country: "NO"`) هو الخيار الآمن الافتراضي كلما أمكن الخلط بين سلسلة نصية ونوع آخر.

## طالع أيضاً

- **[JSON](/ar/data-serialization/json)** — نفس نموذج البيانات، ببنية أكثر صرامة، صيغة السلك الفعلية لمعظم واجهات برمجة التطبيقات.
- **[XML](/ar/data-serialization/xml)** — الخيار الثالث للبيانات المُهيكلة، أكثر إسهاباً لكن بنظام تحقق من المخطط ناضج لا يضاهيه YAML.
