لا يمكن لرابط أن يحتوي بأمان إلا مجموعة محدودة من الأحرف — الحروف والأرقام وحفنة من علامات الترقيم (`- _ . ~` والأحرف البنيوية `: / ? # [ ] @ ! $ & ' ( ) * + , ; =`، المحجوزة لبناء الرابط نفسه). أي شيء آخر — مسافة، `&` داخل قيمة، نص غير ASCII — يجب أن يُرمَّز **بالنسبة المئوية**: يُستبدَل بـ `%` متبوعاً بقيمة بايت الحرف بالنظام الست عشري.

```
hello world     ->  hello%20world
100% done       ->  100%25%20done
café             ->  caf%C3%A9        (UTF-8 bytes, each percent-encoded)
```

## لماذا يهمّ `&` و`=` تحديداً

تستخدم سلاسل الاستعلام `&` لفصل أزواج المفتاح-القيمة و`=` لفصل مفتاح عن قيمته — حرف `&` أو `=` حرفي *داخل* قيمة يجب أن يُرمَّز بالنسبة المئوية، وإلا يُقرأ خطأً كبنية بدلاً من بيانات:

```
?comment=nice & tidy    -->  parsed as comment="nice ", " tidy"="" (broken)
?comment=nice%20%26%20tidy  -->  parsed as comment="nice & tidy"  (correct)
```

هذه بالضبط فئة الخطأ التي يوجد ترميز `application/x-www-form-urlencoded` في [بيانات النموذج](/ar/data-serialization/form-data) لمنعها بشكل منهجي، بدلاً من ترك كل قيمة نموذج لتُرمَّز يدوياً.

## `+` تعني مسافة، أحياناً

داخل سلسلة استعلام أو جسم `application/x-www-form-urlencoded` تحديداً، تكون `+` اختصاراً لمسافة — لكن `+` حرفياً في أي مكان آخر من الرابط تعني علامة زائد حرفية. هذا المعنى المزدوج مصدر متكرر للأخطاء عندما تُفكّ نفس السلسلة النصية بافتراض خاطئ حول السياق الذي أتت منه.

## `encodeURIComponent` مقابل `encodeURI`

تملك JavaScript مُرمِّزَين مدمجَين بنطاقَين مختلفَين، والخلط بينهما خطأ شائع:

```js
encodeURIComponent("a/b?c=d");  // "a%2Fb%3Fc%3Dd" — escapes EVERYTHING, safe for a single value
encodeURI("https://x.com/a/b?c=d"); // "https://x.com/a/b?c=d" — leaves URL structure characters alone
```

`encodeURIComponent` هو الخيار الصحيح دائماً تقريباً عند ترميز قيمة واحدة (معلمة استعلام، جزء مسار) ستُدرَج داخل رابط أكبر — `encodeURI` مخصص فقط لترميز سلسلة نصية هي بالفعل رابط كامل وصالح.
