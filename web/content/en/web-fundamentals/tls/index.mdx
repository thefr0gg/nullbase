**HTTPS** is just **HTTP** sent over a **TLS**-encrypted connection — the request/response model doesn't change at all, only the transport underneath it does. TLS (Transport Layer Security) is what provides:

- **Encryption** — nobody in between the client and server can read the traffic.
- **Integrity** — nobody in between can modify the traffic without both sides noticing.
- **Authentication** — the client gets cryptographic proof it's really talking to the server it thinks it is (via the server's certificate).

## What HTTPS doesn't protect

TLS secures the connection, not the endpoints. It doesn't stop:

- A compromised server from leaking data it holds in plaintext.
- Malware on the client reading data before it's encrypted or after it's decrypted.
- A user being phished into visiting `paypa1.com` instead of `paypal.com` — that's a valid HTTPS connection to the *wrong, but real*, server.
