A **proxy** is a server that sits between a client and the server it's actually trying to reach, forwarding traffic on someone's behalf. Which side it represents is the whole distinction:

- A **forward proxy** acts on behalf of the *client* — it's why your company's IT department can block certain sites, or a VPN can make your traffic look like it's coming from somewhere else.
- A **reverse proxy** acts on behalf of the *server* — it's why nullbase.wiki can be backed by any number of actual servers without you ever knowing.

## Why use one

- **Routing** — one hostname, many backend services, split by path or subdomain.
- **Load balancing** — spread requests across multiple identical backend instances.
- **TLS termination** — the proxy handles HTTPS, so backend services only need to speak plain HTTP internally.
- **Caching** — serve repeat requests from the proxy without hitting the backend at all.
- **Security** — the real backend servers are never directly reachable from the internet.
