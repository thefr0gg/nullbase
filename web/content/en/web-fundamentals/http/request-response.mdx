Every HTTP interaction is a single **request** from a client followed by a single **response** from a server. The protocol is stateless: each request is independent, and the server does not remember previous requests (state is carried by the client, e.g. in cookies or tokens).

## The lifecycle

1. **Client → Request** — The client builds a request: a *method*, the *request target* (usually a URI), *header fields*, and an optional *body*.
2. **Transport** — The request travels over the network (typically TCP, often TLS-encrypted as HTTPS).
3. **Server → Response** — The server processes the request and returns a response: a *status code*, *header fields*, and an optional *body*.

## Why it matters

- **Stateless** — any machine that understands HTTP can act as a server; no session state is assumed.
- **Idempotence** — some methods (`GET`, `PUT`) are idempotent: repeating them is safe.
- **Cacheability** — responses can be cached (by the client, a CDN, or an intermediary) to avoid redundant work.
