HTTP messages are of two kinds: **requests** (sent by a client) and **responses** (sent by a server). Both share the same generic structure: a **start line**, **header fields**, an optional blank line, and an optional **message body**.

## Request message

```http
GET /api/http/echo?hello=world HTTP/1.1
Host: nullbase.local
User-Agent: nullbase/1.0
Accept: application/json
```

The **request line** is `Method SP request-target SP HTTP-version CRLF`.

## Response message

```http
HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 87

{"method":"GET","path":"/api/http/echo","status":200}
```

The **status line** is `HTTP-version SP status-code SP reason-phrase CRLF`. The `reason-phrase` is human-readable and optional in practice; the `status-code` is what programs act on — see [Status Codes](/en/web-fundamentals/http/status-codes/200).

## Header fields

Headers are `Name: value` pairs that carry metadata: content negotiation, caching directives, authentication, cookies, and more. See [Headers](/en/web-fundamentals/http/headers/content-type) for the ones that matter most.
