JSON (JavaScript Object Notation) is a lightweight, text-based data format — despite the name, it's language-independent today, with a parser in essentially every programming language. It's the default request/response body format across [REST](/en/web-apis/rest), most [RPC](/en/web-apis/rpc), and [GraphQL](/en/web-apis/graphql), and every mock response on this site is JSON for exactly that reason.

```json
{
  "id": 42,
  "name": "Grace Hopper",
  "active": true,
  "roles": ["admin", "editor"],
  "manager": null
}
```

## The complete type system

JSON's entire type system is six types — nothing else is valid, which is part of why it's so easy to parse consistently across languages.

## What JSON can't represent

JSON has no `Date` type — timestamps are conventionally serialized as ISO 8601 strings (`"2024-01-15T09:00:00Z"`) and parsed back into real date objects by the consumer, not automatically. It also can't represent `undefined`, functions, or circular references — `JSON.stringify` silently drops `undefined` values and functions, and throws on a circular reference.

```js
JSON.stringify({ a: undefined, b: () => {}, c: 1 });
// '{"c":1}' — a and b are just gone, not null
```

## Strict syntax, on purpose

Unlike JavaScript object literals, JSON has no trailing commas, no comments, no unquoted keys, and no single-quoted strings — this strictness is deliberate: a parser doesn't have to guess intent, which is what makes JSON reliably interoperable across every language's implementation.
