An HTML `<form>` doesn't submit its fields as [JSON](/en/data-serialization/json) by default — it uses one of two older encodings, chosen by the form's `enctype` attribute, that predate JSON as a web format entirely.

## Try it

`/api/form-submit` in this site's mock API parses whichever encoding you actually send — try the urlencoded example, then switch the `Content-Type` header and body to JSON and send again.

`application/x-www-form-urlencoded` is the default and is what the example above sends — it's compact but can't carry binary data at all, since everything has to be percent-encoded text (see [URL Encoding](/en/data-serialization/url-encoding)). A form with `<input type="file">` has to use `multipart/form-data` instead, which is why file-upload forms always need `enctype="multipart/form-data"` set explicitly.

```http
POST /upload HTTP/1.1
Content-Type: multipart/form-data; boundary=----abc123

------abc123
Content-Disposition: form-data; name="username"

grace
------abc123
Content-Disposition: form-data; name="avatar"; filename="photo.png"
Content-Type: image/png

<binary bytes>
------abc123--
```

## FormData in JavaScript

The browser's `FormData` object builds either encoding for you when submitted via `fetch` — you never hand-construct the boundary string or percent-encoding yourself in modern code:

```js
const form = new FormData();
form.append("username", "grace");
form.append("avatar", fileInput.files[0]);
fetch("/upload", { method: "POST", body: form }); // browser sets Content-Type + boundary automatically
```
