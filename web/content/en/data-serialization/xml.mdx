XML (eXtensible Markup Language) represents structured data as nested, named tags — closer in shape to [HTML](/en/web-platform/html) than to [JSON](/en/data-serialization/json), since it uses the same markup syntax. Before JSON became the default, XML was the standard data-interchange format for web APIs (SOAP, RSS, early REST-ish APIs); today it survives mainly in enterprise systems, document formats, and configuration.

```xml
<user id="42">
  <name>Grace Hopper</name>
  <active>true</active>
  <roles>
    <role>admin</role>
    <role>editor</role>
  </roles>
</user>
```

## Attributes vs. elements

The same data can be expressed two different ways in XML, which is a real source of ambiguity JSON doesn't have:

```xml
<user id="42" name="Grace Hopper" />
<!-- vs. -->
<user>
  <id>42</id>
  <name>Grace Hopper</name>
</user>
```

Neither is "more correct" — conventions vary by project, which is itself a common criticism of XML compared to JSON's single obvious way to write a key-value pair.

## Where it's still the standard

XML remains the actual standard, not a legacy holdover, in several places: SOAP web services (common in enterprise/finance/healthcare integrations), Microsoft Office and OpenDocument file formats (a `.docx` is a zip of XML files), RSS/Atom feeds, and SVG (which is XML, not a separate image format).
