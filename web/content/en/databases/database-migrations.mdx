A migration is a small, version-controlled script that changes a database's schema — adding a column, creating a table, adding an index — applied the same way, in the same order, to every environment that needs it (a developer's laptop, staging, production). The alternative — manually running `ALTER TABLE` statements by hand against production — has no record of what ran where, and no way to guarantee two environments actually ended up with the same schema.

## Try it — applying a real migration live

<SqlPlayground
  title="0007_add_users_last_login — applied live"
  schema={`CREATE TABLE users (id INTEGER PRIMARY KEY, email TEXT NOT NULL);
INSERT INTO users (id, email) VALUES (1, 'ada@example.com'), (2, 'alan@example.com');`}
  defaultQuery={`ALTER TABLE users ADD COLUMN last_login_at TEXT;
PRAGMA table_info(users);`}
/>

The `PRAGMA table_info(users)` result now shows a real new `last_login_at` column — the migration actually ran against this in-browser database. Try the "down" migration next: `ALTER TABLE users DROP COLUMN last_login_at;` followed by `PRAGMA table_info(users);` again — the column is genuinely gone.

## Why migrations are additive by convention

A well-written migration avoids destructive changes in the same step a new column is introduced — dropping a column the application still reads from would break anything not yet redeployed with the new code. A safer sequence for renaming a column, for example, is usually: (1) add the new column, (2) deploy code that writes to both old and new, (3) backfill existing rows, (4) deploy code that only uses the new column, (5) only then drop the old one — several small migrations instead of one risky one.

## Schema drift

"Schema drift" is what happens when a database's actual schema no longer matches what the migration history says it should be — usually from someone running an ad-hoc `ALTER TABLE` by hand instead of through a migration. It's a real operational hazard specifically because it's invisible until a migration that assumes the "correct" prior state fails, or worse, silently succeeds against the wrong assumption.
