Go has three built-in composite types worth understanding well: arrays,
slices, and maps. Slices are what you'll use almost all the time — arrays
mostly exist as the thing slices are built on top of.

## Arrays

An array has a fixed length that's part of its type: `[3]int` and `[5]int`
are different types and can't be assigned to each other.

```go
var scores [3]int
scores[0] = 90
scores[1] = 85
scores[2] = 78
fmt.Println(scores) // [90 85 78]

primes := [5]int{2, 3, 5, 7, 11}
```

Because the size is fixed and known at compile time, arrays are used
directly by value: assigning one array to another copies every element.

## Slices

A slice is a view over an underlying array: a pointer, a length, and a
capacity. Slices are what you almost always reach for instead of arrays,
because they can grow.

```go
nums := []int{1, 2, 3}
nums = append(nums, 4)
fmt.Println(nums) // [1 2 3 4]
```

`make` creates a slice with a given length (and optionally capacity):

```go
buf := make([]int, 3)    // [0 0 0]
buf2 := make([]int, 0, 10) // length 0, capacity 10
```

Slicing an existing slice (`s[low:high]`) does **not** copy — the new slice
shares the same underlying array as the original. Mutating through one is
visible through the other, until an `append` forces a reallocation:

```go
a := []int{1, 2, 3, 4, 5}
b := a[1:3] // [2 3], shares a's backing array
b[0] = 99
fmt.Println(a) // [1 99 3 4 5] — a changed too
```

This aliasing is one of the most common sources of surprise for people
coming from languages where slicing always copies. When you need an
independent copy, use the built-in `copy` function:

```go
src := []int{1, 2, 3}
dst := make([]int, len(src))
copy(dst, src)
```

## Maps

A map is Go's built-in hash table, declared with `map[KeyType]ValueType`:

```go
ages := map[string]int{
	"ada":  36,
	"grace": 85,
}

ages["linus"] = 55
fmt.Println(ages["ada"]) // 36

value, ok := ages["missing"]
fmt.Println(value, ok) // 0 false — the zero value, and ok reports absence
```

Deleting a key uses the built-in `delete`:

```go
delete(ages, "grace")
```

Iterating a map with `range` visits entries in **random order** by design —
Go deliberately randomizes iteration order to stop code from accidentally
depending on it. Sort the keys yourself if you need a stable order.
