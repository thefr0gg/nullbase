Go has no classes and no inheritance. Instead it has two simpler pieces
that combine to cover most of what object-oriented languages use classes
for: `struct` types for data, and `interface` types for behavior contracts.
Once you're used to it, this ends up simpler than a class hierarchy — there
are no `super` calls, no diamond-inheritance problems, no ambiguity about
which parent method runs.

## Structs

A `struct` groups named fields into a single type:

```go
type Point struct {
	X int
	Y int
}

func main() {
	p := Point{X: 3, Y: 4}
	fmt.Println(p.X, p.Y) // 3 4
}
```

Fields starting with an uppercase letter are exported (visible outside the
package); lowercase fields are package-private. This is Go's entire
visibility system — there's no `public`/`private` keyword.

## Methods with receivers

Go doesn't put methods inside the struct definition. Instead, you declare a
regular function with a **receiver** — an extra parameter before the
function name that binds it to a type:

```go
type Rectangle struct {
	Width, Height float64
}

func (r Rectangle) Area() float64 {
	return r.Width * r.Height
}

func main() {
	rect := Rectangle{Width: 3, Height: 4}
	fmt.Println(rect.Area()) // 12
}
```

A receiver can be a value (`r Rectangle`) or a pointer (`r *Rectangle`).
Value receivers get a copy of the struct; pointer receivers can mutate the
original and avoid copying large structs:

```go
func (r *Rectangle) Scale(factor float64) {
	r.Width *= factor
	r.Height *= factor
}

func main() {
	rect := Rectangle{Width: 3, Height: 4}
	rect.Scale(2)
	fmt.Println(rect) // {6 8}
}
```

## Composition instead of inheritance

Go has no `extends`. To reuse fields and methods, you **embed** one struct
inside another. The outer struct promotes the embedded type's fields and
methods as if they were its own:

```go
type Animal struct {
	Name string
}

func (a Animal) Describe() string {
	return a.Name + " makes a sound"
}

type Dog struct {
	Animal // embedded — not a named field
	Breed  string
}

func main() {
	d := Dog{Animal: Animal{Name: "Rex"}, Breed: "Labrador"}
	fmt.Println(d.Describe()) // Rex makes a sound — promoted from Animal
	fmt.Println(d.Name)        // Rex — also promoted
}
```

## Interfaces are implicit

An interface lists a set of methods. A type satisfies it automatically just
by implementing those methods — there's no `implements` keyword and no
declared relationship:

```go
type Shape interface {
	Area() float64
}

func printArea(s Shape) {
	fmt.Println(s.Area())
}

func main() {
	rect := Rectangle{Width: 3, Height: 4}
	printArea(rect) // Rectangle satisfies Shape simply by having an Area() method
}
```

This means you can define an interface after the fact, in a completely
different package, and existing types will already satisfy it if their
method set matches. It decouples "what a type does" from "what a type
declares it does."
