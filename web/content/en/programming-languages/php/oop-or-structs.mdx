PHP has had object-oriented features since PHP 4, and a modern, fairly
conventional class model since PHP 5 — single inheritance, interfaces,
visibility modifiers, abstract classes. Since PHP 8, the object model has
picked up constructor property promotion, readonly properties, and enums,
narrowing the gap with newer languages.

## Classes

```php
<?php

class User {
    public function __construct(
        public string $name,
        public string $role = "member",
    ) {}

    public function describe(): string {
        return "{$this->name} ({$this->role})";
    }
}

$user = new User("Ada", "admin");
echo $user->describe() . "\n"; // Ada (admin)
```

That constructor uses **constructor property promotion** (PHP 8.0+): typing
a visibility modifier directly on a constructor parameter both declares the
property and assigns it, replacing what used to take three lines
(`public string $name;` plus a parameter plus a `$this->name = $name;`
assignment) with one.

## Inheritance

PHP classes support single inheritance via `extends`. `parent::` calls the
parent implementation explicitly:

```php
<?php

class Shape {
    public function area(): float {
        return 0.0;
    }
}

class Circle extends Shape {
    public function __construct(private float $radius) {}

    public function area(): float {
        return M_PI * $this->radius ** 2;
    }
}

$circle = new Circle(2.0);
echo round($circle->area(), 2) . "\n"; // 12.57
```

## Interfaces

An `interface` declares a contract with no implementation. A class can
implement any number of interfaces, unlike the single class it can extend:

```php
<?php

interface Comparable {
    public function compareTo(self $other): int;
}

class Money implements Comparable {
    public function __construct(public int $cents) {}

    public function compareTo(self $other): int {
        return $this->cents <=> $other->cents;
    }
}

$a = new Money(500);
$b = new Money(300);
echo $a->compareTo($b) . "\n"; // 1
```

## Traits — PHP's mixin mechanism

This is the PHP-specific piece: PHP doesn't allow multiple inheritance, but
a class can `use` any number of **traits** to pull in implemented methods
directly, as if they were copy-pasted into the class. This is how PHP shares
concrete behavior across otherwise unrelated class hierarchies.

```php
<?php

trait Loggable {
    public function log(string $message): void {
        echo "[" . static::class . "] $message\n";
    }
}

trait Timestamped {
    private ?string $createdAt = null;

    public function touch(): void {
        $this->createdAt = date("Y-m-d");
    }

    public function createdAt(): ?string {
        return $this->createdAt;
    }
}

class Order {
    use Loggable, Timestamped;
}

$order = new Order();
$order->touch();
$order->log("created on " . $order->createdAt());
```

A class using multiple traits that define the same method must resolve the
conflict explicitly with `insteadof`/`as` — PHP won't silently pick one,
which avoids the classic "diamond problem" ambiguity that multiple
inheritance runs into in other languages.
