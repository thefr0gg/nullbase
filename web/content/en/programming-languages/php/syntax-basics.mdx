PHP code lives inside `<?php ... ?>` tags. Everything outside those tags —
even in the middle of a file — is passed straight through as output, which
is what makes PHP convenient for mixing markup and logic in the same file.

## The `<?php` tag

```php
<html>
<body>
<?php
$name = "Ada";
echo "<p>Hello, $name!</p>";
?>
</body>
</html>
```

In practice, files that contain *only* PHP (no trailing HTML) should omit
the closing `?>` entirely. It's optional, and leaving it out avoids a subtle
bug: any whitespace or newline after `?>` gets sent to the output, which can
break things like setting HTTP headers after the script "ends."

```php
<?php

echo "No closing tag needed for a pure-PHP file.\n";
```

## Variables always start with `$`

Every variable in PHP is prefixed with a dollar sign, with no exceptions —
this is one of the most immediately recognizable things about PHP syntax.
Variables are also dynamically typed: you don't declare a type up front, and
a variable can hold a different kind of value after a later assignment.

```php
<?php

$age = 30;          // int
$age = "thirty";     // now a string — perfectly legal
$isAdmin = true;      // bool
$price = 19.99;        // float
```

Variable names are case-sensitive (`$Name` and `$name` are different
variables) and must start with a letter or underscore, never a digit.

## Constants

`define()` and the more modern `const` both create values that can't be
reassigned. `const` is preferred for simple scalar values and works at both
top-level and inside classes:

```php
<?php

const MAX_RETRIES = 3;
define("APP_NAME", "nullbase");

echo MAX_RETRIES . " retries allowed for " . APP_NAME . "\n";
```

Note that constants are referenced *without* the `$` sigil — another spot
where PHP's sigil rule has a well-known exception.

## String interpolation

Double-quoted strings interpolate variables directly; single-quoted strings
never do. This is a common source of subtle bugs when a literal `$` is
meant, so it's worth knowing cold:

```php
<?php

$user = "grace";
echo "Logged in as $user\n";   // Logged in as grace
echo 'Logged in as $user\n';    // Logged in as $user\n  (literal, no newline)
```

Curly braces disambiguate a variable from surrounding text, and are required
when interpolating a property or array access cleanly:

```php
<?php

$user = ["name" => "grace"];
echo "Hello, {$user['name']}!\n";
```

## Loose typing and type juggling

By default, PHP will convert types on the fly to make an operation work —
this is called **type juggling**. `declare(strict_types=1)` at the top of a
file turns that off for function argument and return type checks (though
loose comparison operators like `==` still juggle regardless):

```php
<?php
declare(strict_types=1);

function double(int $n): int {
    return $n * 2;
}

echo double(5) . "\n";   // 10
// double("5") would now throw a TypeError instead of silently converting
```
