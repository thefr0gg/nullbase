Modern PHP handles failure with exceptions, much like Java or Python. But
PHP's history means you'll still run into an older, separate mechanism —
PHP "errors" and "warnings" — especially in legacy code or when a built-in
function fails in a way that predates PHP's exception model. Knowing both
matters for reading real PHP codebases.

## try / catch / finally

```php
<?php

function divide(int $a, int $b): float {
    if ($b === 0) {
        throw new InvalidArgumentException("Cannot divide by zero");
    }
    return $a / $b;
}

try {
    echo divide(10, 0);
} catch (InvalidArgumentException $e) {
    echo "Error: " . $e->getMessage() . "\n";
} finally {
    echo "Division attempt finished\n";
}
```

`finally` runs whether or not an exception was thrown or caught — useful for
cleanup like closing a file handle or a database connection.

## Catching multiple exception types

A single `catch` block can list several exception types with `|`, and
catch blocks are tried in order, so put more specific types first:

```php
<?php

function parseConfig(string $json): array {
    $data = json_decode($json, true, flags: JSON_THROW_ON_ERROR);
    return $data;
}

try {
    parseConfig("{not valid json");
} catch (JsonException | TypeError $e) {
    echo "Could not parse config: " . $e->getMessage() . "\n";
}
```

## Custom exceptions

Exceptions are ordinary classes that extend `Exception` (or a more specific
built-in subclass like `RuntimeException`). This lets you carry structured
data and catch a specific application-level failure by type:

```php
<?php

class InsufficientFundsException extends RuntimeException {
    public function __construct(public readonly float $shortfall) {
        parent::__construct("Insufficient funds, short by $shortfall");
    }
}

function withdraw(float $balance, float $amount): float {
    if ($amount > $balance) {
        throw new InsufficientFundsException($amount - $balance);
    }
    return $balance - $amount;
}

try {
    withdraw(50.0, 75.0);
} catch (InsufficientFundsException $e) {
    echo "Short by: " . $e->shortfall . "\n";
}
```

## The older error-reporting model, briefly

Before exceptions were fully embraced (and still today for many built-in
functions), PHP reported problems as **errors, warnings, and notices** —
non-exception events that could be logged, displayed inline in output, or
silently ignored depending on `error_reporting` settings, rather than
unwinding the call stack the way a thrown exception does:

```php
<?php

$value = @$undefinedArray["missing"]; // @ suppresses the warning
echo $value === null ? "null, no exception thrown\n" : "found\n";
```

That `@` "error suppression" operator is a legacy pattern most modern PHP
style guides discourage — it hides genuine bugs along with the noise. PHP 8
converted many of these old warnings into proper `Error` exceptions (a
sibling hierarchy to `Exception`, both implementing `Throwable`), which is
why calling an undefined function now throws an `Error` you can `catch`,
rather than just emitting a warning and continuing with `null`.
