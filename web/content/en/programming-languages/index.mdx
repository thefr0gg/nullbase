Every guide here follows the same shape, so switching between languages means comparing like with like: syntax & variables, control flow, functions, data structures, how the language structures data + behavior (classes, structs, traits), error handling, modules & packages, and one advanced topic specific to that language (memory management, ownership, concurrency, generics, and so on). Every page ends with 3 hands-on exercises — drag-and-drop code assembly and predict-the-output — so reading isn't the only thing happening on the page.

## Systems languages

- **[C](/en/programming-languages/c)** — manual memory management, pointers, and the model most other languages eventually reference.
- **[C++](/en/programming-languages/cpp)** — C's model plus classes, references, and RAII-based resource management.
- **[Rust](/en/programming-languages/rust)** — memory safety without a garbage collector, enforced at compile time through ownership and borrowing.
- **[Go](/en/programming-languages/go)** — a small, garbage-collected language built around goroutines and channels for concurrency.

## Application & scripting languages

- **[Python](/en/programming-languages/python)** — readable syntax, dynamic typing, and a standard library that covers most everyday tasks.
- **[JavaScript](/en/programming-languages/javascript)** — the language of the browser, and increasingly the server, built around an event loop and asynchronous execution.
- **[TypeScript](/en/programming-languages/typescript)** — JavaScript plus a static type system checked before code ever runs.
- **[PHP](/en/programming-languages/php)** — a server-side scripting language built around handling one HTTP request at a time.

## Enterprise & managed-runtime languages

- **[Java](/en/programming-languages/java)** — a statically typed, deeply object-oriented language running on the JVM.
- **[C#](/en/programming-languages/csharp)** — a statically typed language on the .NET runtime, close in shape to Java with its own idioms (properties, LINQ, `async`/`await`).
