Before ES6, JavaScript had no built-in module system — code was split
across `<script>` tags or bundled with third-party tools like CommonJS
(Node's `require`/`module.exports`). ES modules, using `import` and
`export`, are now the standard and work the same way in browsers (with
`<script type="module">`) and in Node.js.

## Named and default exports

A module can export multiple named values, and optionally one default
export.

```js
// math.js
export function add(a, b) {
  return a + b;
}

export function subtract(a, b) {
  return a - b;
}

export const PI = 3.14159;

export default function multiply(a, b) {
  return a * b;
}
```

```js
// main.js
import multiply, { add, subtract, PI } from "./math.js";

console.log(add(2, 3));      // 5
console.log(multiply(2, 3));  // 6
console.log(PI);              // 3.14159
```

Named imports must match the exported names exactly (or be renamed with
`as`), and there can be at most one default export per module, which is
why it's imported without curly braces.

```js
import multiply, { subtract as minus } from "./math.js";

console.log(minus(10, 4)); // 6
```

## Namespace imports and re-exports

You can pull in every named export of a module as a single object, and
modules can re-export things from other modules — useful for building a
single "barrel" entry point for a folder of related files.

```js
import * as MathUtils from "./math.js";
console.log(MathUtils.add(1, 1)); // 2

// utils/index.js — re-exporting from multiple files
export { add, subtract } from "./math.js";
export { formatDate } from "./dates.js";
```

## package.json and npm

Every Node.js project (and most frontend projects) is described by a
`package.json` file: the project's name, version, dependencies, and the
scripts you run with `npm run`.

```json
{
  "name": "my-app",
  "version": "1.0.0",
  "type": "module",
  "scripts": {
    "start": "node index.js",
    "test": "node --test"
  },
  "dependencies": {
    "express": "^4.19.0"
  },
  "devDependencies": {
    "eslint": "^9.0.0"
  }
}
```

`"type": "module"` tells Node to treat `.js` files as ES modules rather
than the older CommonJS format — without it, `import`/`export` throw a
syntax error and you'd need `require`/`module.exports` instead. `npm
install` reads `dependencies` and `devDependencies` and downloads
everything (plus their own dependencies, recursively) into `node_modules`,
recording the exact resolved versions in `package-lock.json` so
installs are reproducible across machines. The `^` in `"^4.19.0"` means
"any compatible version starting from 4.19.0, up to but not including
5.0.0" — npm's convention for semantic versioning ranges.

`dependencies` ship with your app in production; `devDependencies`
(linters, test runners, bundlers) are only needed while developing and are
skipped by `npm install --omit=dev` in production installs.
