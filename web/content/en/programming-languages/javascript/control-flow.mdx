JavaScript's control flow constructs will look familiar if you've used any
C-family language, with a few JavaScript-specific conveniences layered on
top: optional chaining, nullish coalescing, and a handful of loop variants
suited to iterating collections rather than raw index ranges.

## Conditionals

`if`/`else if`/`else` works as expected. JavaScript also has a ternary
operator for compact conditional expressions, and two operators worth
knowing well: `??` (nullish coalescing) and `?.` (optional chaining).

```js
function describe(temp) {
  if (temp < 0) {
    return "freezing";
  } else if (temp < 20) {
    return "cool";
  } else {
    return "warm";
  }
}

console.log(describe(-5)); // "freezing"

const label = temp => (temp < 20 ? "cool" : "warm"); // ternary, no braces needed
```

`??` returns its right-hand side only when the left is `null` or
`undefined` — unlike `||`, which also falls through on `0`, `""`, and
`false`. `?.` short-circuits to `undefined` instead of throwing when a
property access hits `null`/`undefined` partway through a chain.

```js
const config = { retries: 0 };

console.log(config.retries || 3);  // 3  — 0 is falsy, so || overrides it (usually a bug!)
console.log(config.retries ?? 3);  // 0  — 0 is not nullish, so ?? keeps it (usually what you want)

console.log(config.server?.host ?? "localhost"); // "localhost", no crash on the missing server
```

## Loops

`for`, `while`, and `do...while` all exist with their usual semantics.
Two additional loop forms iterate collections directly: `for...of` (values
of an iterable — arrays, strings, `Map`s, `Set`s) and `for...in` (enumerable
property *keys* of an object, generally reserved for objects rather than
arrays).

```js
const scores = [88, 92, 79];

for (const score of scores) {
  console.log(score);
}
// 88
// 92
// 79

for (let i = 0; i < scores.length; i++) {
  console.log(`index ${i}: ${scores[i]}`);
}

const user = { name: "ada", role: "admin" };
for (const key in user) {
  console.log(key, user[key]);
}
```

`break` exits a loop entirely; `continue` skips to the next iteration.
Both can target a labeled outer loop when you need to escape nested loops
from the inside.

## switch

`switch` compares with `===` against each `case`. Forgetting `break` is
one of the most common JavaScript bugs — execution falls through to the
next case unless you explicitly stop it.

```js
function trafficAction(color) {
  switch (color) {
    case "red":
      return "stop";
    case "yellow":
      return "slow down";
    case "green":
      return "go";
    default:
      return "unknown signal";
  }
}

console.log(trafficAction("yellow")); // "slow down"
```
