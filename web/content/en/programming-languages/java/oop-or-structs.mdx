Java is a deeply object-oriented language: classes are the fundamental unit
of organization, and almost every non-trivial program is a network of
objects sending messages (calling methods) to each other. This page covers
the core object model — classes, inheritance, interfaces, and polymorphism —
in more depth than the other pages, since it's where most of Java's design
philosophy lives.

## Classes, fields, and constructors

A class bundles state (**fields**) with behavior (**methods**). A
**constructor** initializes a new instance:

```java
public class Point {
    private final double x;
    private final double y;

    public Point(double x, double y) {
        this.x = x;
        this.y = y;
    }

    public double distanceFromOrigin() {
        return Math.sqrt(x * x + y * y);
    }

    @Override
    public String toString() {
        return "Point(" + x + ", " + y + ")";
    }
}
```

```java
Point p = new Point(3.0, 4.0);
System.out.println(p.distanceFromOrigin()); // 5.0
System.out.println(p);                      // Point(3.0, 4.0) — toString is called implicitly
```

`private` fields are accessible only within the class itself — the standard
Java idiom is to keep fields private and expose behavior (or getter/setter
methods) instead of letting outside code reach directly into an object's
state. `this` refers to the current instance and disambiguates a field from
a same-named constructor parameter.

## Inheritance with extends

A class can `extend` exactly one superclass, inheriting its fields and
methods and optionally overriding behavior:

```java
public class Shape {
    protected String name;

    public Shape(String name) {
        this.name = name;
    }

    public double area() {
        return 0.0;
    }

    public String describe() {
        return name + " has area " + area();
    }
}

public class Circle extends Shape {
    private final double radius;

    public Circle(double radius) {
        super("Circle"); // must call the superclass constructor first
        this.radius = radius;
    }

    @Override
    public double area() {
        return Math.PI * radius * radius;
    }
}
```

```java
Shape s = new Circle(2.0);
System.out.println(s.describe()); // Circle has area 12.566370614359172
```

`super(...)` calls the superclass constructor and must be the first
statement in a subclass constructor if used explicitly; if omitted, Java
inserts an implicit no-argument `super()` call. `@Override` is optional but
strongly recommended — it tells the compiler "this must match a method in
the superclass," catching typos (a misspelled method name silently becomes
a new method rather than an override without it) at compile time.

Java deliberately supports only **single inheritance** of classes — a class
extends at most one superclass. This sidesteps the "diamond problem" that
arises when a class would inherit conflicting implementations of the same
method from two parents through full multiple inheritance.

## Polymorphism

A variable declared with a supertype can refer to any subtype instance, and
calling an overridden method dispatches to the actual runtime type's
implementation — not the declared (compile-time) type:

```java
Shape[] shapes = { new Circle(1.0), new Circle(2.0) };
for (Shape shape : shapes) {
    System.out.println(shape.describe()); // always calls Circle's area()
}
```

This is **dynamic dispatch**: even though the array's declared element type
is `Shape`, each call to `area()` resolves to `Circle.area()` at run time,
because that's the actual type of the object stored there.

## Interfaces

An interface declares a contract — method signatures with no implementation
(plus, since Java 8, optional `default` methods with a body) — that any
number of unrelated classes can implement:

```java
public interface Movable {
    void move(double dx, double dy);

    default void stop() {
        System.out.println("Stopped.");
    }
}

public class Robot implements Movable {
    private double x = 0;
    private double y = 0;

    @Override
    public void move(double dx, double dy) {
        x += dx;
        y += dy;
        System.out.println("Now at (" + x + ", " + y + ")");
    }
}
```

Unlike `extends`, a class can `implements` any number of interfaces — this
is how Java gets most of the practical benefit of multiple inheritance
without its pitfalls, since interfaces (mostly) don't carry conflicting
field state. A class that implements an interface is assignable to a
variable of that interface's type, exactly like it would be for a
superclass:

```java
Movable m = new Robot();
m.move(1.0, 2.0); // Now at (1.0, 2.0)
m.stop();         // Stopped. (uses the interface's default implementation)
```

## abstract classes

An `abstract` class can mix implemented methods with unimplemented
`abstract` ones, and — unlike an interface — can hold non-`static`,
non-`final` fields shared through inheritance. It can't be instantiated
directly; only a concrete subclass that implements every `abstract` method
can be:

```java
public abstract class Animal {
    protected final String name;

    public Animal(String name) {
        this.name = name;
    }

    public abstract String sound();

    public void speak() {
        System.out.println(name + " says " + sound());
    }
}

public class Dog extends Animal {
    public Dog(String name) {
        super(name);
    }

    @Override
    public String sound() {
        return "Woof";
    }
}
```

Choosing between an `abstract` class and an interface is mostly about
whether subtypes share real state and whether a type needs to inherit from
more than one source: reach for an interface by default, and an `abstract`
class when several related subclasses genuinely share fields and
constructor logic.
