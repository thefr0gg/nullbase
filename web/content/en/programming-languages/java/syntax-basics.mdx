Java is statically typed: every variable's type is fixed at compile time and
checked before the program ever runs. Unlike dynamically typed languages,
you can't reassign a variable to a value of an incompatible type — the
compiler rejects it before you get the chance.

## Declaring variables

The explicit form states the type, then the name, then an optional
initializer:

```java
int age = 36;
double price = 19.99;
boolean isAdmin = false;
String name = "Ada";
```

Since Java 10, `var` lets the compiler infer the type from the
initializer inside a method body. It is still statically typed — `var` is
just a shorthand for the compiler figuring out the type at compile time, not
a dynamic type:

```java
var age = 36;        // inferred as int
var name = "Ada";    // inferred as String
var isAdmin = false; // inferred as boolean
```

`var` cannot be used for fields, method parameters, or return types, and it
requires an initializer so the compiler has something to infer from — `var
x;` does not compile.

## Primitive types vs. wrapper classes

Java has eight built-in **primitive** types that are not objects and hold
their value directly, without pointer indirection:

| Category | Types |
|---|---|
| Integer | `byte`, `short`, `int`, `long` |
| Floating point | `float`, `double` |
| Other | `char` (a UTF-16 code unit), `boolean` |

Every primitive has a corresponding **wrapper class** (`Integer`, `Double`,
`Boolean`, and so on) that boxes it into an object — required whenever you
need a primitive to behave like an object, such as storing it in a
collection like `ArrayList<Integer>`, since generic collections can't hold
primitives directly:

```java
int primitive = 42;
Integer boxed = 42;          // autoboxing: implicit int -> Integer
int backToPrimitive = boxed; // auto-unboxing: implicit Integer -> int
```

This implicit conversion is called autoboxing and unboxing. It's convenient
but not free — boxing allocates an object — and a `null` wrapper unboxed
into a primitive throws a `NullPointerException` at run time.

## Constants with final

`final` on a local variable or field means it can be assigned exactly once.
It's Java's closest equivalent to a constant:

```java
final double PI = 3.14159;
final int MAX_RETRIES = 3;

// PI = 3.0; // compile error: cannot assign a value to final variable PI
```

By convention, `final` fields intended as constants are named in
`SCREAMING_SNAKE_CASE`.
