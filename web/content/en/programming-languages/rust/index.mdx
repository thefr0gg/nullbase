**Rust** is a statically typed, compiled systems language built around one central promise: memory safety and thread safety without a runtime garbage collector. It achieves this through the **ownership** system — a set of rules the compiler checks at compile time, with zero cost at runtime. Where languages like C and C++ leave memory management to the programmer (and accept the occasional use-after-free or data race as the price of that freedom), and languages like Java or Go pay a garbage collector to sweep up after you, Rust's compiler (specifically a component called the **borrow checker**) rejects a whole class of bugs before the program ever runs.

This is why Rust code that compiles tends to be unusually reliable — not because Rust programmers are more careful, but because the compiler refuses to produce a binary for code with dangling pointers, data races, or iterator invalidation. The tradeoff is a steeper learning curve: the borrow checker has opinions about how data can be shared and mutated, and fighting it is a rite of passage for every new Rust developer.

## What Rust is used for

Rust shows up wherever C or C++ traditionally lived, plus places neither could go comfortably: operating system components, browser engines (parts of Firefox), command-line tools (`ripgrep`, `fd`), WebAssembly modules, embedded firmware, and increasingly backend services where predictable performance without GC pauses matters.

## A first look

```rust
fn main() {
    let name = "world";
    let mut count = 0;

    for _ in 0..3 {
        count += 1;
        println!("Hello, {name}! (greeting #{count})");
    }
}
```

Running this prints the greeting three times, incrementing `count` each pass. A few things are already visible here that are distinctly Rust: `let mut` for a variable that can change (plain `let` bindings are immutable by default), string interpolation directly inside `println!`'s format string (`{name}`), and a range (`0..3`) as something you can loop over directly without an index variable.

## Compiler-enforced safety, by example

The feature that most defines Rust is that this kind of mistake doesn't compile:

```rust
fn main() {
    let s1 = String::from("hello");
    let s2 = s1; // s1's value is *moved* into s2, not copied

    println!("{s1}, world!"); // error: use of moved value
}
```

```text
error[E0382]: borrow of moved value: `s1`
 --> src/main.rs:5:20
  |
2 |     let s1 = String::from("hello");
  |         -- move occurs because `s1` has type `String`, which does not implement the `Copy` trait
3 |     let s2 = s1; // s1's value is *moved* into s2, not copied
  |              -- value moved here
4 |
5 |     println!("{s1}, world!"); // error: use of moved value
  |                ^^ value borrowed here after move
```

`String` owns a heap allocation, so assigning `s1` to `s2` transfers ("moves") ownership rather than copying the data — `s1` is no longer valid afterward. This isn't a runtime crash waiting to happen; the compiler catches it before the program is even built. The [Ownership & Borrowing](/en/programming-languages/rust/advanced) page covers exactly why this rule exists and what it buys you.
