Rust has no `class` keyword and no inheritance between data types. Instead, it splits the two things a class usually bundles into separate constructs: a **`struct`** holds data, and an **`impl`** block attaches functions to that struct. Shared behavior across unrelated types — what other languages reach for interfaces or inheritance to express — is done with **traits**.

## Structs

```rust
struct Rectangle {
    width: f64,
    height: f64,
}

fn main() {
    let rect = Rectangle { width: 30.0, height: 10.0 };
    println!("area: {}", rect.width * rect.height);
}
```

## `impl` blocks: methods and associated functions

An `impl` block attaches functions to a struct. A method takes `&self` (or `&mut self`, or `self`) as its first parameter and is called with dot syntax; an **associated function** (no `self` parameter) is called on the type itself, most commonly as a constructor named `new` by convention.

```rust
struct Rectangle {
    width: f64,
    height: f64,
}

impl Rectangle {
    // associated function — no `self`, called as Rectangle::square(5.0)
    fn square(size: f64) -> Rectangle {
        Rectangle { width: size, height: size }
    }

    // method — takes &self, called as rect.area()
    fn area(&self) -> f64 {
        self.width * self.height
    }

    fn scale(&mut self, factor: f64) {
        self.width *= factor;
        self.height *= factor;
    }
}

fn main() {
    let mut sq = Rectangle::square(5.0);
    println!("area before scale: {}", sq.area());

    sq.scale(2.0);
    println!("area after scale: {}", sq.area());
}
```

`&self` borrows the instance immutably (enough for `area`, which only reads), while `&mut self` borrows it mutably (needed for `scale`, which writes to `width` and `height`). This is the same borrowing rule that governs every other reference in Rust — methods aren't a special case.

## Traits: shared behavior without inheritance

A **trait** defines a set of methods a type promises to implement — Rust's answer to an interface. Unlike class inheritance, implementing a trait doesn't give a type any fields or behavior for free; it only requires the type to provide the methods the trait declares (traits can also supply default method bodies that implementers may override).

```rust
trait Describe {
    fn describe(&self) -> String;
}

struct Rectangle {
    width: f64,
    height: f64,
}

struct Circle {
    radius: f64,
}

impl Describe for Rectangle {
    fn describe(&self) -> String {
        format!("a {}x{} rectangle", self.width, self.height)
    }
}

impl Describe for Circle {
    fn describe(&self) -> String {
        format!("a circle with radius {}", self.radius)
    }
}

fn print_description(shape: &dyn Describe) {
    println!("{}", shape.describe());
}

fn main() {
    let rect = Rectangle { width: 3.0, height: 4.0 };
    let circle = Circle { radius: 2.0 };

    print_description(&rect);
    print_description(&circle);
}
```

`Rectangle` and `Circle` share no common ancestor and no fields — they're only related by both implementing `Describe`. `print_description` accepts `&dyn Describe`, meaning "a reference to anything that implements this trait," which is how Rust achieves polymorphism without a class hierarchy: the shared contract is the trait, not a shared base type.
