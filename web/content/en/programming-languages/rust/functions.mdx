Functions in Rust are declared with `fn`, and every parameter needs an explicit type annotation — unlike `let` bindings, Rust does not infer parameter or return types from how a function is called, because that would make a function's signature depend on its call sites instead of being a fixed contract.

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b // no semicolon: this is the returned expression
}

fn main() {
    let sum = add(3, 4);
    println!("{sum}");
}
```

## Expressions vs. statements as return values

The last expression in a function body is automatically its return value, *as long as it has no trailing semicolon*. Add a semicolon and it becomes a statement that evaluates to `()`, silently changing what the function returns:

```rust
fn add_broken(a: i32, b: i32) -> i32 {
    a + b; // semicolon turns this into a statement, not a return value
} // error: mismatched types — expected i32, found ()
```

You can still use an explicit `return` keyword — it's necessary for returning early from the middle of a function — but relying on the trailing expression for the "normal" exit path is the idiomatic style.

```rust
fn classify(n: i32) -> &'static str {
    if n < 0 {
        return "negative"; // early return, semicolon required after return
    }
    if n == 0 {
        "zero"
    } else {
        "positive"
    } // trailing expression: the normal-path return value
}
```

## Closures

A **closure** is an anonymous function that can capture variables from the scope it's defined in — written with pipes around its parameters (`|x| ...`) instead of `fn name(x: T)`. Closures are used heavily with iterator methods like `map` and `filter`.

```rust
fn main() {
    let threshold = 10;
    let numbers = vec![4, 12, 7, 15, 3];

    // the closure captures `threshold` from the surrounding scope
    let above: Vec<i32> = numbers.into_iter().filter(|n| *n > threshold).collect();

    println!("{above:?}"); // [12, 15]
}
```

Unlike a plain `fn`, this closure can see `threshold` without it being passed in explicitly — closures borrow or move the variables they reference from their environment, which is exactly what lets `filter`'s closure compare against a value defined outside it.
