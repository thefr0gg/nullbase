A **decorator** is a function that takes a function and returns a new function wrapping it — used to add behavior (logging, timing, access checks) without touching the original function's body. The `@decorator` syntax above a `def` is just shorthand for reassigning the function to the decorator's return value.

```python
def logged(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@logged
def add(a, b):
    return a + b

print(add(2, 3))
# Calling add
# 5
```

`@logged` above `def add(...)` is equivalent to writing `add = logged(add)` right after defining it — every call to `add` now actually calls `wrapper`, which prints, then calls the original `add` via the closure over `func`, and returns its result. This is the same closure mechanism covered in [Functions](/en/programming-languages/python/functions), applied to wrap behavior rather than just capture a value.

A **generator** is a function that produces a sequence of values lazily, one at a time, using `yield` instead of `return`. Calling a generator function doesn't run its body immediately — it returns a generator object, and the body only advances up to the next `yield` each time a value is requested.

```python
def countdown(n):
    while n > 0:
        yield n
        n -= 1

for number in countdown(3):
    print(number)
# 3
# 2
# 1
```

Each iteration of the `for` loop resumes `countdown` right after its `yield`, rather than re-running the whole function from scratch — the function's local state (`n`, and its position in the `while` loop) is preserved between yields. This makes generators memory-efficient for large or unbounded sequences: nothing beyond the current value has to exist in memory at once.

A **generator expression** — `(expr for item in iterable)` — is the lazy counterpart to a list comprehension, producing the same kind of one-at-a-time generator without a `def` and `yield` at all.

```python
squares = (x * x for x in range(5))
print(next(squares))       # 0
print(next(squares))       # 1
print(list(squares))       # [4, 9, 16] — the rest, in one go
```

`next()` pulls exactly one value out of the generator each time it's called; `list()` drains whatever's left. Note the first two values (`0`, `1`) are already gone by the time `list()` runs — a generator only produces each value once, and there's no way to "rewind" it.
