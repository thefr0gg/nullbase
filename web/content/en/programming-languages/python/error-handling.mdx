Python signals failure by raising exceptions, and handling one means wrapping the risky code in a `try` block with one or more `except` clauses that catch specific exception types.

```python
try:
    value = int(input("Enter a number: "))
except ValueError:
    print("That wasn't a valid number.")
else:
    print(f"You entered {value}")
finally:
    print("Done processing input.")
```

Each clause has a distinct job: the `try` block holds the code that might fail; `except ValueError` only catches that specific error (a `TypeError` elsewhere in the block would propagate uncaught); `else` runs only if the `try` block completed with no exception at all; `finally` always runs — exception or not, `return` or not — which makes it the right place for cleanup like closing a file or releasing a lock.

Catching `except ValueError` specifically, rather than a bare `except:`, matters: a bare `except` swallows *everything*, including typos that raise `NameError` and interrupts like `KeyboardInterrupt`, which makes real bugs silently disappear instead of surfacing.

Custom exceptions are just classes that inherit from `Exception` (or a more specific built-in exception), which lets calling code catch your specific failure mode by name instead of guessing at string messages.

```python
class InsufficientFundsError(Exception):
    """Raised when a withdrawal exceeds the account balance."""

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError(f"Cannot withdraw {amount}, balance is {balance}")
    return balance - amount

try:
    withdraw(100, 150)
except InsufficientFundsError as e:
    print(e)  # Cannot withdraw 150, balance is 100
```

`raise` is how code signals failure explicitly; `except ... as e` binds the caught exception instance to a name so its message (or any extra data attached to it) can be inspected.

```python
def read_config(path):
    try:
        with open(path) as f:
            return f.read()
    except FileNotFoundError:
        return "{}"
```

Here a specific, expected failure mode (the file doesn't exist yet) is handled with a sensible fallback, while any other error — a permissions problem, a disk failure — is left to propagate, since silently swallowing those would hide a real problem.
