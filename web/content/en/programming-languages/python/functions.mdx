Functions are defined with `def`, and Python doesn't require declaring a return type or parameter types — parameters can, however, be given default values, which makes them optional at the call site.

```python
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

print(greet("Sam"))                 # Hello, Sam!
print(greet("Sam", greeting="Hey"))  # Hey, Sam!
```

`greeting="Hello"` gives that parameter a default, so callers can omit it entirely. Arguments can also be passed by keyword (`greeting="Hey"`) instead of position, which is useful once a function takes several parameters and the call site would otherwise be a confusing list of bare values.

Sometimes the number of arguments a function should accept isn't fixed in advance. `*args` collects any extra positional arguments into a tuple, and `**kwargs` collects any extra keyword arguments into a dict — the names `args`/`kwargs` are just convention, the `*`/`**` prefixes are what matter.

```python
def total(*args, **kwargs):
    print("positional:", args)     # (1, 2, 3)
    print("keyword:", kwargs)       # {'label': 'sum'}
    return sum(args)

result = total(1, 2, 3, label="sum")
print(result)  # 6
```

This pattern shows up constantly in library code — a wrapper function that needs to accept "whatever arguments the thing it wraps accepts" without knowing that signature in advance uses `def wrapper(*args, **kwargs)` and forwards them with `wrapped(*args, **kwargs)`.

Functions are also regular objects: they can be assigned to variables, passed as arguments, and returned from other functions, which is what makes closures possible.

```python
def make_multiplier(factor):
    def multiplier(x):
        return x * factor
    return multiplier

double = make_multiplier(2)
triple = make_multiplier(3)
print(double(5), triple(5))  # 10 15
```

`multiplier` "remembers" the `factor` value from the call that created it, even after `make_multiplier` has already returned — that's a closure, and it's the mechanism behind Python decorators.
