A Python class is defined with `class`, and almost every class starts with an `__init__` method — the constructor, called automatically when a new instance is created — which sets up instance attributes via `self`.

```python
class Dog:
    def __init__(self, name, breed):
        self.name = name
        self.breed = breed

    def bark(self):
        return f"{self.name} says Woof!"

rex = Dog("Rex", "Labrador")
print(rex.bark())  # Rex says Woof!
```

`self` is the instance the method was called on — Python passes it explicitly as the first parameter of every instance method, rather than making it an implicit keyword like `this` in other languages. `rex.bark()` is really `Dog.bark(rex)` under the hood.

Inheritance lets a class reuse and extend another class's behavior. A subclass calls `super().__init__(...)` to run the parent class's constructor before adding its own setup, and it can override any method, including ones the parent already defines.

```python
class Puppy(Dog):
    def __init__(self, name, breed, age_months):
        super().__init__(name, breed)
        self.age_months = age_months

    def bark(self):
        return f"{self.name} says Yip!"

buddy = Puppy("Buddy", "Poodle", 4)
print(buddy.bark())  # Buddy says Yip!
```

"Dunder" (double-underscore) methods are how a class plugs into Python's built-in operators and functions instead of needing its own bespoke API. `__repr__` controls what `print()` and the REPL show for an instance; `__eq__` controls what `==` does between two instances.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Point({self.x}, {self.y})"

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

p1 = Point(1, 2)
p2 = Point(1, 2)
print(p1 == p2)  # True — because __eq__ compares the coordinates
print(p1)         # Point(1, 2) — because __repr__ formats it
```

Without `__eq__`, `==` falls back to identity comparison — whether the two names refer to the exact same object in memory — which is almost never what you want for a value-like class such as `Point`.
