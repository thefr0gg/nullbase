Python is an interpreted, dynamically-typed language whose defining trait is that it makes readability a language feature rather than a style preference: blocks are defined by indentation instead of braces or `end` keywords, so a script's visual structure and its actual control flow can never drift apart. There's no separate compile step to run — the reference implementation, CPython, reads a `.py` file and executes it directly — which is part of why Python shows up everywhere from one-off scripts to production web backends to data pipelines and machine learning code.

```python
print("Hello, world!")

name = "Ada"
age = 36
print(f"{name} is {age} years old")
```

Two things stand out even in that tiny example. First, there's no type declaration anywhere — `name` and `age` get their types from the values assigned to them, and a variable can be reassigned to a different type later without complaint. Second, the `f"..."` string is an f-string: a string literal with `{expression}` placeholders evaluated inline, which is how most Python code builds formatted output rather than concatenating pieces with `+`.

Python also ships with a large standard library and an enormous third-party package ecosystem installed via `pip`, so a surprising amount of real work — reading JSON, making HTTP requests, parsing dates — needs no dependencies beyond what's already installed or a single `pip install`.

```python
def fizzbuzz(n):
    for i in range(1, n + 1):
        if i % 15 == 0:
            print("FizzBuzz")
        elif i % 3 == 0:
            print("Fizz")
        elif i % 5 == 0:
            print("Buzz")
        else:
            print(i)

fizzbuzz(15)
```

Notice there are no parentheses around the `if` condition, no semicolons ending statements, and the function body's extent is defined purely by how far its lines are indented — remove the indentation and it's a syntax error, not just messy formatting.
