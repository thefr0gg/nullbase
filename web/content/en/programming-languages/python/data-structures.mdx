Python has four container types built into the language itself, no import required, and picking the right one is mostly a question of whether order matters, whether the contents need to change, and whether you're looking things up by position or by name.

A **list** is an ordered, mutable sequence — the default choice when you have a collection of things that might grow, shrink, or get reordered.

```python
numbers = [3, 1, 4, 1, 5, 9]
numbers.append(2)
numbers.sort()
print(numbers)  # [1, 1, 2, 3, 4, 5, 9]
```

A **tuple** looks like a list but is immutable — once created, it can't be appended to or have an item reassigned. That immutability makes tuples usable as dict keys (lists can't be) and signals intent: a tuple says "this is a fixed, small group of values," like coordinates.

```python
point = (10, 20)  # tuples are immutable
x, y = point       # unpacking works the same as with lists
print(x, y)  # 10 20
```

A **dict** stores key-value pairs and looks values up by key rather than position, which makes it the natural fit for anything you'd otherwise describe as "a record with named fields."

```python
user = {"name": "Rae", "age": 29}
user["email"] = "rae@example.com"
for key, value in user.items():
    print(key, value)
```

A **set** stores unique, unordered values and automatically discards duplicates on insertion — useful for membership tests (`x in my_set` is fast) and for deduplicating a collection.

```python
unique_ids = {1, 2, 2, 3, 3, 3}
print(unique_ids)  # {1, 2, 3}
```

The one thing to internalize about lists (and dicts, and sets) is that they're mutable *objects* — a variable holding one doesn't hold a copy of its contents, it holds a reference to the same underlying list everyone else who has that variable is also pointing at.
