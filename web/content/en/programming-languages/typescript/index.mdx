**TypeScript** is a statically typed language that compiles down to plain JavaScript. It doesn't introduce a new runtime, a new garbage collector, or new execution semantics — every valid JavaScript program is (almost) valid TypeScript, and every TypeScript program eventually becomes JavaScript that runs in the same engines JavaScript already runs in (V8, Node, browsers). What TypeScript adds is a **type checker**: a separate compile-time pass that reads your annotations and inferred types, flags mismatches, and then erases all of that type information before the code ever executes.

That last part matters. Types in TypeScript have **zero runtime cost and zero runtime presence** — `interface`, `type`, and most type annotations vanish completely during compilation (`tsc`, or a transpiler like esbuild/SWC). This is why TypeScript can catch a whole category of bugs — passing a `string` where a `number` is expected, calling a method that doesn't exist on an object, forgetting to handle `null` — before you ever run the program, without changing how the program behaves once it does run.

## Why add a type system to JavaScript

JavaScript's dynamic typing is flexible but means many mistakes only surface at runtime, often in production. TypeScript's compiler checks the shapes of your data as you write code:

```ts
function greet(name: string) {
  return `Hello, ${name.toUpperCase()}!`;
}

greet("Ada");
greet(42); // Type error: Argument of type 'number' is not assignable to parameter of type 'string'
```

The second call would have thrown a runtime `TypeError` in plain JavaScript (`42.toUpperCase is not a function`) — but only once that line actually executed, maybe deep in a rarely hit code path. TypeScript catches it immediately, at the point you write it, in your editor.

## Structural typing

Unlike class-based languages such as Java or C#, TypeScript's type system is **structural**, not nominal: two types are compatible if they have the same shape, regardless of name or declared relationship.

```ts
interface Point {
  x: number;
  y: number;
}

function printPoint(p: Point) {
  console.log(`(${p.x}, ${p.y})`);
}

const coord = { x: 3, y: 4, label: "origin-ish" };
printPoint(coord); // OK — coord has at least x and y as numbers
```

`coord` was never declared as a `Point`, and it even has an extra `label` field, but it structurally satisfies `Point`'s shape, so the assignment is allowed. This is a deliberate design choice that mirrors how JavaScript objects actually get passed around.
