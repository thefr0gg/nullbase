**Generics** are TypeScript's signature intermediate feature — the tool for writing code that works with many types without falling back to `any` and losing type safety entirely. A generic function or type takes a **type parameter**, conventionally named `T`, which acts as a placeholder that gets filled in with a concrete type at each call site.

## The problem generics solve

Without generics, you either write a function once per type, or you widen to `any` and lose all checking:

```ts
function firstAny(arr: any[]): any {
  return arr[0];
}

const num = firstAny([1, 2, 3]); // typed any — no error if you misuse it
num.toUpperCase(); // no compile error, but this crashes at runtime
```

`firstAny` compiles cleanly for any array, but the return value is `any`, so calling `.toUpperCase()` on a number sails right past the type checker and blows up at runtime.

## Writing a generic function

```ts
function first<T>(arr: T[]): T {
  return arr[0];
}

const num = first([1, 2, 3]); // T inferred as number; num: number
const str = first(["a", "b"]); // T inferred as string; str: string

num.toUpperCase(); // Type error: Property 'toUpperCase' does not exist on type 'number'
```

`first<T>` still works with an array of any type, exactly like `firstAny` did — but now the return type is tied to whatever `T` was inferred as for that specific call. `first([1, 2, 3])` returns `number`, so calling `.toUpperCase()` on the result is caught immediately, unlike the `any`-based version.

## Constraining a type parameter

`extends` restricts what a type parameter can be, so you can safely use operations that only make sense for a subset of types:

```ts
function getLength<T extends { length: number }>(value: T): number {
  return value.length;
}

getLength("hello"); // 5 — string has .length
getLength([1, 2, 3]); // 3 — array has .length
getLength(42); // Type error: Argument of type 'number' is not assignable to parameter of type '{ length: number }'
```

`T extends { length: number }` means "`T` can be anything, as long as it has a `.length` property that's a number" — it doesn't limit `T` to one specific type, just to the shapes that make `value.length` a safe thing to write.

## Generic types and interfaces

Generics aren't limited to functions — a `type` or `interface` can also take a type parameter, which is how a single reusable shape like `Box<T>` can describe a box holding any type of contents:

```ts
interface Box<T> {
  contents: T;
}

const numberBox: Box<number> = { contents: 42 };
const stringBox: Box<string> = { contents: "hello" };

numberBox.contents = "oops"; // Type error: Type 'string' is not assignable to type 'number'
```

Once `numberBox` is declared as `Box<number>`, `T` is fixed to `number` for that specific box — `contents` can never hold a `string`, even though `Box<T>` itself was written once and works for any `T`.
