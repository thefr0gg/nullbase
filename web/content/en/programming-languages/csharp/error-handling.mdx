C# uses exceptions for error handling rather than error return values.
Anything from an invalid array index to a failed network call throws an
object derived from `System.Exception`, and code further up the call stack
can catch it.

## try / catch / finally

```csharp
try
{
    int[] numbers = { 1, 2, 3 };
    Console.WriteLine(numbers[10]); // throws IndexOutOfRangeException
}
catch (IndexOutOfRangeException ex)
{
    Console.WriteLine($"Caught: {ex.Message}");
}
finally
{
    Console.WriteLine("This always runs, exception or not.");
}
```

`finally` runs whether or not an exception was thrown, and even if the `try`
or `catch` block returns early — it's the place for cleanup like closing a
file or a connection.

Multiple `catch` blocks let you handle different exception types
differently; they're checked top to bottom, so put more specific types
first:

```csharp
try
{
    string input = "not a number";
    int value = int.Parse(input);
}
catch (FormatException ex)
{
    Console.WriteLine($"Bad format: {ex.Message}");
}
catch (Exception ex)
{
    Console.WriteLine($"Something else went wrong: {ex.Message}");
}
```

An exception filter (`when`) lets a single `catch` clause fire only under
extra conditions, without swallowing exceptions that don't match:

```csharp
try
{
    throw new InvalidOperationException("disk full");
}
catch (InvalidOperationException ex) when (ex.Message.Contains("disk"))
{
    Console.WriteLine("Handling a disk-related failure specifically.");
}
```

## Custom exceptions

Deriving your own exception type from `Exception` (or a more specific base
class) lets calling code catch precisely the failure it cares about, and lets
you attach domain-specific data:

```csharp
class InsufficientFundsException : Exception
{
    public decimal Shortfall { get; }

    public InsufficientFundsException(decimal shortfall)
        : base($"Insufficient funds: short by {shortfall:C}")
    {
        Shortfall = shortfall;
    }
}

class Account
{
    public decimal Balance { get; private set; } = 100m;

    public void Withdraw(decimal amount)
    {
        if (amount > Balance)
        {
            throw new InsufficientFundsException(amount - Balance);
        }
        Balance -= amount;
    }
}

var account = new Account();
try
{
    account.Withdraw(150m);
}
catch (InsufficientFundsException ex)
{
    Console.WriteLine(ex.Message);      // Insufficient funds: short by $50.00
    Console.WriteLine(ex.Shortfall);    // 50
}
```

Custom exceptions should always call the base constructor (`: base(message)`)
so the standard `.Message` property and stack trace machinery keep working
as expected.
