C#'s signature concurrency feature is `async`/`await` built on top of
`Task` and `Task<T>` — asynchronous operations that represent "a value that
will be available later" (much like a JavaScript `Promise`, though `Task`
predates widespread use of that pattern and is backed by the .NET thread
pool rather than a single-threaded event loop).

## Task and Task\<T\>

A `Task` represents an ongoing operation with no result; `Task<T>` represents
one that will eventually produce a value of type `T`:

```csharp
using System.Threading;
using System.Threading.Tasks;

Task<int> task = Task.Run(() =>
{
    Thread.Sleep(1000); // simulate slow work
    return 42;
});

Console.WriteLine("Started, doing other work...");
int result = task.Result; // blocks until the task completes
Console.WriteLine(result); // 42
```

Blocking on `.Result` defeats much of the point of asynchrony — real async
code uses `await` instead, which suspends the current method without
blocking the underlying thread.

## async / await

Marking a method `async` lets it use `await` to suspend until a `Task`
completes, without blocking the calling thread. An `async` method itself
returns a `Task` (or `Task<T>`), so callers can `await` it in turn:

```csharp
using System.Net.Http;
using System.Threading.Tasks;

async Task<string> FetchGreetingAsync()
{
    await Task.Delay(500); // simulates an I/O-bound wait, non-blocking
    return "Hello from the async world";
}

async Task RunAsync()
{
    Console.WriteLine("Before await");
    string greeting = await FetchGreetingAsync();
    Console.WriteLine(greeting);
    Console.WriteLine("After await");
}

await RunAsync();
```

The method doesn't block a thread while waiting on `Task.Delay` — control
returns to the caller, and the rest of `FetchGreetingAsync` resumes on a
thread-pool thread once the delay finishes. This is why `async`/`await` is
the idiom of choice for I/O-bound work (network calls, file access, database
queries): threads aren't wasted sitting idle waiting on I/O.

## Running tasks concurrently

Awaiting tasks one at a time runs them sequentially. `Task.WhenAll` starts
several tasks and awaits all of them together, running the independent work
concurrently:

```csharp
async Task<int> FetchLengthAsync(string url)
{
    await Task.Delay(300); // stands in for an HTTP call
    return url.Length;
}

async Task RunAllAsync()
{
    Task<int> t1 = FetchLengthAsync("https://a.example");
    Task<int> t2 = FetchLengthAsync("https://b.example");
    Task<int> t3 = FetchLengthAsync("https://c.example");

    int[] lengths = await Task.WhenAll(t1, t2, t3);
    Console.WriteLine(string.Join(", ", lengths));
}

await RunAllAsync();
```

Because `t1`, `t2`, and `t3` are all started before any `await`, their
`Task.Delay(300)` calls overlap — the whole method takes roughly 300ms total,
not 900ms, unlike awaiting each one immediately after starting it.
