C# is thoroughly object-oriented: classes support single inheritance,
interfaces support multiple implementation contracts, and encapsulation is
built into the language through **properties** rather than left to
convention.

## Classes and fields

A class groups state (fields) and behavior (methods) together:

```csharp
class Dog
{
    private string name;

    public Dog(string name)
    {
        this.name = name;
    }

    public void Bark()
    {
        Console.WriteLine($"{name} says Woof!");
    }
}

var rex = new Dog("Rex");
rex.Bark(); // Rex says Woof!
```

A plain `private` field like `name` has no validation and no way to
intercept reads or writes from outside the class — that's what properties
are for.

## Properties: a language feature, not a convention

Unlike Java or C++, where "encapsulated fields" means hand-writing
`getName()`/`setName()` methods, C# builds getter/setter syntax directly into
the language. A property looks like a field to callers but can run code on
every read or write:

```csharp
class Person
{
    private int age;

    public string Name { get; set; } // auto-implemented property: compiler
                                      // generates the backing field for you

    public int Age
    {
        get => age;
        set
        {
            if (value < 0)
            {
                throw new ArgumentException("Age cannot be negative");
            }
            age = value;
        }
    }

    public string Greeting => $"Hi, I'm {Name}"; // read-only, expression-bodied

    public Person(string name, int age)
    {
        Name = name;
        Age = age;
    }
}

var p = new Person("Ada", 36);
Console.WriteLine(p.Greeting); // Hi, I'm Ada
p.Age = -5; // throws ArgumentException
```

Callers write `p.Age = 30;` exactly as if `Age` were a field — the validation
logic in the `set` block runs transparently. This is why C# style strongly
favors public properties over public fields: you can start with an
auto-implemented property and add logic later without breaking any caller.

## Interfaces and inheritance

An interface declares a contract with no implementation (default interface
methods aside); a class implements one or more interfaces and inherits from
at most one base class:

```csharp
interface IShape
{
    double Area();
}

class Circle : IShape
{
    public double Radius { get; }

    public Circle(double radius) => Radius = radius;

    public double Area() => Math.PI * Radius * Radius;
}

class Square : IShape
{
    public double Side { get; }

    public Square(double side) => Side = side;

    public double Area() => Side * Side;
}

List<IShape> shapes = new List<IShape> { new Circle(2), new Square(3) };
foreach (IShape shape in shapes)
{
    Console.WriteLine(shape.Area());
}
```

Base class inheritance uses the same `:` syntax and the `override` keyword
for polymorphism:

```csharp
class Animal
{
    public virtual string Speak() => "...";
}

class Cat : Animal
{
    public override string Speak() => "Meow";
}

Animal a = new Cat();
Console.WriteLine(a.Speak()); // Meow — resolved at runtime via the actual type
```
