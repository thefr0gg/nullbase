C# organizes code with **namespaces** (a logical grouping, independent of
file layout) and manages external dependencies with **NuGet** packages
declared in a project's `.csproj` file. Unlike some languages, a namespace in
C# doesn't have to match the folder structure on disk, though most projects
keep them aligned by convention.

## Namespaces and using

A namespace groups related types and avoids name collisions between
libraries that happen to define a type with the same name:

```csharp
namespace Nullbase.Payments
{
    public class Invoice
    {
        public decimal Amount { get; set; }
    }
}

namespace Nullbase.App
{
    using Nullbase.Payments; // brings Invoice into scope unqualified

    class Program
    {
        static void Main()
        {
            var invoice = new Invoice { Amount = 42.50m };
            Console.WriteLine(invoice.Amount);
        }
    }
}
```

Without the `using Nullbase.Payments;` directive, `Invoice` would need to be
written out fully as `Nullbase.Payments.Invoice` everywhere it's used.

Modern C# (10+) also supports **file-scoped namespaces**, which avoid an
extra indentation level for the common case of one namespace per file:

```csharp
namespace Nullbase.Payments; // applies to the rest of the file — no braces

public class Invoice
{
    public decimal Amount { get; set; }
}
```

## Global usings

A project can declare `using` directives once, project-wide, instead of
repeating them in every file — useful for namespaces like `System` that
almost every file needs:

```csharp
// GlobalUsings.cs
global using System;
global using System.Collections.Generic;
global using System.Linq;
```

## .csproj and NuGet

Every C# project is described by a `.csproj` XML file: target framework,
source files (implicitly included by folder in the SDK-style format), and
package references. NuGet is the package manager and public registry for
.NET, playing the same role `npm` plays for Node.js:

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <Nullable>enable</Nullable>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="Newtonsoft.Json" Version="13.0.3" />
  </ItemGroup>

</Project>
```

Adding a dependency is usually done from the command line rather than by
hand-editing XML:

```bash
dotnet add package Newtonsoft.Json
dotnet restore
dotnet build
dotnet run
```

`dotnet add package` writes the `<PackageReference>` entry into `.csproj` and
`dotnet restore` downloads the package (and its transitive dependencies) into
a local NuGet cache, similar to how `npm install` populates `node_modules`
from `package.json`.
