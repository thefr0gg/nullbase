A C++ **class** bundles data (member variables) and behavior (member functions) into a single type. Unlike a plain `struct` in C, a C++ class controls exactly which parts of that bundle outside code is allowed to touch — the mechanism that makes encapsulation possible.

## Constructors and access modifiers

```cpp
#include <iostream>
#include <string>

class BankAccount {
private:
    std::string owner;
    double balance;

public:
    // constructor: runs automatically when a BankAccount is created
    BankAccount(std::string ownerName, double startingBalance) {
        owner = ownerName;
        balance = startingBalance;
    }

    void deposit(double amount) {
        balance += amount;
    }

    double getBalance() const {
        return balance;
    }
};

int main() {
    BankAccount account("Ada", 100.0);
    account.deposit(50.0);
    std::cout << account.getBalance() << "\n"; // 150

    // account.balance = 1000000;  // would fail to compile: balance is private
    return 0;
}
```

`private` members (`owner`, `balance`) are only accessible from inside the class's own member functions; `public` members form the class's external interface. This is why `account.balance` can't be touched directly from `main` — all access has to go through `deposit()` and `getBalance()`, which lets the class enforce its own rules (for example, rejecting a negative deposit) instead of trusting every caller to do the right thing. The **constructor** — a function with the same name as the class and no return type — runs automatically whenever an object is created, guaranteeing every `BankAccount` starts in a valid state rather than relying on a separate `init()` call that's easy to forget.

## Inheritance

```cpp
#include <iostream>
#include <string>

class Animal {
protected:
    std::string name;

public:
    Animal(std::string animalName) : name(animalName) {}

    virtual std::string speak() const {
        return name + " makes a sound.";
    }
};

class Dog : public Animal {
public:
    Dog(std::string dogName) : Animal(dogName) {}

    std::string speak() const override {
        return name + " barks.";
    }
};

int main() {
    Animal generic("Creature");
    Dog rex("Rex");

    std::cout << generic.speak() << "\n"; // Creature makes a sound.
    std::cout << rex.speak() << "\n";     // Rex barks.
    return 0;
}
```

`class Dog : public Animal` makes `Dog` inherit `Animal`'s members — `protected` members (like `name`) are visible to derived classes but still hidden from outside code, a middle ground between `private` and `public`. `Animal(dogName)` in `Dog`'s constructor initializer list calls the base class's constructor explicitly, since a derived class doesn't automatically know how to initialize the base part of itself. Marking `speak()` as `virtual` in the base class and `override` in the derived one enables **polymorphism**: calling `speak()` through a base-class reference or pointer dispatches to the actual derived type's version at runtime, rather than always calling `Animal::speak()`.
