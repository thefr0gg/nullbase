C++ gives you a choice of containers depending on whether size is known up front and whether you need fast lookup by key rather than by position — picking the wrong one is a common source of both bugs and needless slowness.

## Arrays

```cpp
#include <iostream>

int main() {
    int scores[5] = {90, 85, 77, 92, 60};

    for (int i = 0; i < 5; i++) {
        std::cout << "scores[" << i << "] = " << scores[i] << "\n";
    }
    return 0;
}
```

A C-style array like `scores` has a size fixed at compile time and no bounds checking — reading or writing `scores[5]` compiles cleanly but reads past the array's memory, undefined behavior that can silently corrupt unrelated data. Its size also isn't tracked at runtime; a function receiving `scores` needs the length passed separately.

## `std::vector`

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> scores;
    scores.push_back(90);
    scores.push_back(85);
    scores.push_back(77);

    scores.push_back(100);
    std::cout << "Count: " << scores.size() << "\n";

    for (int s : scores) {
        std::cout << s << " ";
    }
    std::cout << "\n";

    scores.pop_back();
    std::cout << "After pop_back, count: " << scores.size() << "\n";
    return 0;
}
```

`std::vector<int>` is a resizable array: `push_back` appends an element and grows the underlying storage automatically, `size()` reports the current element count, and `pop_back()` removes the last element. Unlike a raw array, a vector always knows its own length and manages its own memory — this is why `std::vector` is the default choice for a sequence of values in modern C++, reserved for a fixed-size C-style array only when the size is truly constant and known at compile time (or in `std::array`, which offers the same fixed-size guarantee with a safer interface).

## `std::map`

```cpp
#include <iostream>
#include <map>
#include <string>

int main() {
    std::map<std::string, int> ages;
    ages["Ada"] = 36;
    ages["Grace"] = 85;
    ages["Alan"] = 41;

    ages["Ada"] = 37; // overwrites the existing entry

    for (const auto& pair : ages) {
        std::cout << pair.first << " -> " << pair.second << "\n";
    }
    return 0;
}
```

`std::map<K, V>` stores key-value pairs and keeps them ordered by key internally (using a balanced binary tree), so iterating over a map always visits entries in ascending key order — here, alphabetically by name. Indexing with `ages["Ada"]` either inserts a new entry or updates the existing one if the key is already present; looking up a key that doesn't exist with `[]` silently inserts it with a default-constructed value, which is a common surprise — `ages.find("Bob")` or `ages.count("Bob")` are the safer way to check for presence without inserting.
