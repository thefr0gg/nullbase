**C** was created by Dennis Ritchie at Bell Labs in the early 1970s, originally to rewrite the Unix kernel in something more portable than assembly. Over fifty years later it's still the language most operating system kernels, embedded firmware, language runtimes (CPython, the JVM's core, Lua), and low-level libraries (`libc`, SQLite, zlib) are written in. C compiles directly to machine code, has no garbage collector and no runtime safety net, and gives the programmer near-total control over memory layout and CPU behavior — which is exactly why it's both extremely fast and extremely easy to shoot yourself in the foot with.

Everything this site covers about C follows from one design decision: C trusts the programmer completely. There's no bounds checking on arrays, no automatic memory management, and no exceptions — just functions, pointers, and a very small standard library. Modern languages like Rust and Go exist largely as reactions to how much that trust costs in practice, but C's directness is also why it remains the lingua franca that nearly every other language's runtime is implemented in.

## A minimal C program

```c
#include <stdio.h>

int main(void) {
    printf("Hello, nullbase!\n");
    return 0;
}
```

`#include <stdio.h>` pulls in declarations for standard I/O functions like `printf`. `main` is the entry point every C program must have; returning `0` tells the operating system the program exited successfully (a nonzero value signals an error to whatever invoked it — a shell script, a build tool, and so on).

## Compiling and running it

C is compiled ahead of time, not interpreted — there's no C runtime reading your source line by line. A compiler (`gcc` or `clang`) translates source into a native executable *before* it ever runs:

```c
#include <stdio.h>

int square(int n) {
    return n * n;
}

int main(void) {
    for (int i = 1; i <= 5; i++) {
        printf("%d squared is %d\n", i, square(i));
    }
    return 0;
}
```

Saved as `squares.c`, this becomes a runnable binary with:

```bash
gcc squares.c -o squares
./squares
```

There's no package manager step, no interpreter to invoke — `gcc` reads the `.c` file, resolves the `#include`s, and emits a standalone executable. That compile-then-run split (rather than a JIT or interpreter) is why C programs start instantly and why a bug like reading past the end of an array is a runtime crash, not a compile error the compiler could have caught for you.
