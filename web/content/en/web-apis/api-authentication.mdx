Authentication answers one question: **who is making this request?** (Not what they're allowed to do once identified — that's [API Authorization](/en/web-apis/api-authorization).) Nearly every scheme below boils down to "attach a credential to the request, on every request, since APIs are stateless" — see [REST](/en/web-apis/rest)'s statelessness constraint for why nothing gets remembered between calls.

## Bearer tokens and JWTs

A **JWT** (JSON Web Token) is the most common shape a Bearer token takes: three base64url segments — a header, a payload (claims like the user's ID and an expiry time), and a signature — joined by dots. The server verifies the signature to trust the claims without needing a database lookup on every request, which is why JWTs are popular for stateless APIs specifically.

```
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiI0MiIsImV4cCI6MTcwMDAwMDAwMH0.4f8s...
       header                    payload                  signature
```
