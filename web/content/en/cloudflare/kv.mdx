**Workers KV** stores simple key-value pairs, replicated to Cloudflare's edge locations worldwide so a read from anywhere is fast and local — the explicit trade-off is that a write isn't immediately visible everywhere at once, unlike a traditional single-region database.

## Basic usage

```js
export default {
  async fetch(request, env) {
    await env.MY_KV.put("theme:user-42", "dark");
    const theme = await env.MY_KV.get("theme:user-42");
    return new Response(theme);
  },
};
```

`env.MY_KV` is a [binding](/en/cloudflare/workers-bindings) to a specific KV namespace; `put`/`get`/`delete`/`list` are the entire core API — deliberately minimal compared to a relational database's query language, since KV isn't trying to support relational queries at all.

## Eventual consistency, concretely

A `put()` from one edge location can take up to roughly 60 seconds to propagate to every other location globally — a read for that same key from a *different* location shortly after the write may still return the old value (or no value at all, if it's a new key). This isn't a bug; it's the mechanism that makes KV reads fast everywhere without every read needing to check a single authoritative source first. Workloads that need every reader to see a write immediately, everywhere, are a poor fit for KV specifically because of this.
