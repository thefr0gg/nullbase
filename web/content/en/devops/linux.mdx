Nearly every server on the internet — cloud VMs, containers, the machines behind most backends — runs some Linux distribution. Not because Linux is required, but because it's free, stable, well-understood, and has decades of tooling built around exactly this use case. Knowing your way around a Linux shell is close to a prerequisite for backend and DevOps work generally.

## Permissions

Every file has an owner, a group, and three permission sets (owner/group/others), each with read, write, and execute bits — shown by `ls -l` as a string like `-rwxr-xr--`. `chmod 755 script.sh` sets owner to read/write/execute (7), group and others to read/execute (5 each) — the numeric form is just those three permission bits read as octal digits. A script that isn't executable (`chmod +x`) will refuse to run directly even if its contents are perfectly valid.

## Commands worth knowing cold

```bash
ls -la          # list files, including hidden ones, with details
cd /var/log      # change directory
pwd              # print working directory
cat file.txt     # print a file's contents
grep -r "TODO" . # search recursively for a pattern
ps aux           # list running processes
kill -9 1234     # forcibly terminate process 1234
chmod +x run.sh  # make a file executable
tail -f app.log  # follow a log file as it grows
```

`tail -f` in particular is a daily tool for anyone operating a service — watching a log file update in real time as a server handles requests.
