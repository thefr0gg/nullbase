Writing correct application logic is only part of the job — this section covers the tooling around it: tracking changes to code over time, pulling in and managing dependencies, and the automated checks (linting, formatting, testing, debugging) that catch mistakes before they ship.

## Version control

- **[Git](/en/developer-tools/git)** — the distributed version control system nearly everyone uses.
- **[GitHub](/en/developer-tools/github)** — the most widely used place to host Git repositories and collaborate around them.
- **[GitLab](/en/developer-tools/gitlab)** — GitHub's major alternative, with an integrated CI/CD platform built in.

## Dependencies

- **[npm](/en/developer-tools/npm)** — the default package manager and registry for JavaScript.
- **[Package Managers](/en/developer-tools/package-managers)** — the general pattern npm is one implementation of.
- **[Semantic Versioning](/en/developer-tools/semantic-versioning)** — the version-number convention that makes automated dependency updates possible at all.

## Code quality

- **[Linters](/en/developer-tools/linters)** — catching likely bugs and style issues without running the code.
- **[Formatters](/en/developer-tools/formatters)** — ending arguments about code style by automating it entirely.
- **[Testing](/en/developer-tools/testing)** — verifying code behaves correctly, automatically, on every change.

## Finding out what's actually happening

- **[Debugging](/en/developer-tools/debugging)** — figuring out why code isn't doing what it's supposed to.
- **[Profiling](/en/developer-tools/profiling)** — figuring out why code is slower than it should be.
