**TCP (Transmission Control Protocol)** turns [IP](/en/networking/ip)'s best-effort delivery into a reliable, ordered, connection-oriented stream. Before any application data moves, the two sides complete a three-way handshake (`SYN`, `SYN-ACK`, `ACK`) — covered in [TCP/IP](/en/web-fundamentals/tcp-ip) — and from then on every byte is numbered and acknowledged.

## What's inside a TCP segment

A TCP header carries far more than a normal packet needs, because reliability has to be tracked somewhere:

```text
Source Port | Destination Port
Sequence Number
Acknowledgment Number
Flags (SYN, ACK, FIN, RST, PSH, URG)
Window Size
Checksum
```

The **sequence number** lets the receiver reassemble bytes in the right order even if segments arrive out of order; the **acknowledgment number** tells the sender exactly how much has safely arrived, so only the missing part ever needs retransmitting.

## Flow control and congestion control

TCP throttles itself in two independent ways. **Flow control** uses the receiver's advertised **window size** so a fast sender can't overwhelm a slow receiver's buffer. **Congestion control** is about the *network* rather than the receiver: TCP starts sending slowly (slow start), ramps up while acknowledgments keep arriving on time, and backs off sharply the moment it detects loss — a dropped or delayed ACK is treated as a signal that something in the path is congested, not just that one packet got unlucky.

## Closing a connection

Unlike opening, closing is asymmetric — each direction shuts down independently with its own `FIN`/`ACK` pair, since one side might still have data left to send after the other is done. A connection that skips this and gets torn down with `RST` instead is being abandoned, not finished.
