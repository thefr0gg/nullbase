**ICMP (Internet Control Message Protocol)** is how routers and hosts report problems that [IP](/en/networking/ip) itself has no way to signal — a destination that can't be reached, a packet that expired, a network that's unreachable. It isn't a transport protocol like [TCP](/en/networking/tcp) or [UDP](/en/networking/udp): there's no port number, no connection, and it's not something application code typically sends directly.

## How `ping` actually works

`ping` sends an ICMP Echo Request to a target and waits for an Echo Reply — round-trip time and packet loss are just measured directly from whether and how fast the reply comes back. No handshake, no port, nothing but "did you answer, and how long did it take."

## How `traceroute` abuses TTL exceeded

`traceroute` sends a series of packets with **TTL = 1, then 2, then 3**, and so on. Each one dies at the router that many hops away, and that router sends back a Time Exceeded message — revealing its own address in the process. By collecting one such message per hop, traceroute reconstructs the entire path to the destination without any single router needing to cooperate beyond standard ICMP behavior.

## Why some pings never come back

Many networks rate-limit or block ICMP entirely at firewalls, since ICMP has occasionally been abused for reconnaissance or denial-of-service traffic. A host that never responds to ping isn't necessarily down — it may simply be configured to ignore ICMP while still serving TCP traffic on other ports perfectly normally.
