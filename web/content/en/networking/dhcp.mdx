**DHCP (Dynamic Host Configuration Protocol)** is why a laptop or phone gets a working IP address the instant it joins a Wi-Fi network, with no one typing an address in by hand. A DHCP server on the network hands out addresses from a configured pool, along with the subnet mask, default gateway, and DNS server the device needs to actually communicate.

## The DORA process

A device with no address yet can't be reached directly, so DHCP starts with a broadcast — this exchange is traditionally remembered by the acronym **DORA**:

## Leases aren't permanent

An assigned address is a **lease**, not a permanent grant — it expires after a configured duration, and the client has to renew it before then (typically at 50% of the lease time) or risk losing the address to another device. This is what lets a DHCP pool serve far more devices over time than it has addresses, as laptops and phones come and go.

## What else DHCP hands out

Beyond the IP address itself, a DHCP response typically includes the subnet mask (so the device knows which addresses are local vs. need routing), the default gateway (where to send traffic leaving the local network), and one or more DNS server addresses — without which a device could reach IPs but couldn't resolve any domain name at all.
