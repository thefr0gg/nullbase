Web Components is a set of browser-native APIs for building custom, reusable elements — `<user-card>`, `<rating-stars>` — that behave like any other [HTML](/en/web-platform/html) element (they can be used in any markup, with any framework, or none at all) while encapsulating their own internal structure and [CSS](/en/web-platform/css) so page styles can't accidentally leak in or out.

```html
<my-counter start="5"></my-counter>
```

```js
class MyCounter extends HTMLElement {
  connectedCallback() {
    this.attachShadow({ mode: "open" }).innerHTML = `<button>Count: ${this.getAttribute("start")}</button>`;
  }
}
customElements.define("my-counter", MyCounter);
```

## The three technologies

Web Components isn't one API — it's three separate browser features that are almost always used together.

## Why encapsulation matters here

A regular `<div class="counter">` is fully exposed to every page-level CSS rule and every `document.querySelector` — a page-wide `button { color: red; }` rule affects it whether the component's author wanted that or not. Shadow DOM's boundary means a Web Component's internal styles never leak out, and page styles never leak in (unless deliberately exposed via CSS custom properties), which is what makes a component genuinely drop-in-safe regardless of what CSS the host page already has.

## Framework-agnostic by design

Because Custom Elements are just HTML tags under the hood, a Web Component built once can be used inside a React app, a Vue app, plain HTML, or any future framework, without a framework-specific wrapper — this is the main pitch over a component built in a specific framework's own component model, which only that framework's apps can consume.
