CSS (Cascading Style Sheets) describes how [HTML](/en/web-platform/html)'s structure gets a visual presentation — colors, layout, spacing, typography. The same element can be targeted by rules from more than one place at once (a stylesheet, a `<style>` tag, an inline `style` attribute, the browser's own defaults), so CSS needs a deterministic way to decide which one actually wins. That's the "cascade" in the name.

## The box model

Every element the browser lays out is a rectangular box made of four nested layers — this is the single most load-bearing mental model in CSS layout.

By default, `width`/`height` size only the content box — padding and border are added on top, which is why `box-sizing: border-box` (sizing `width` to include padding and border instead) is close to universal in real stylesheets; without it, adding padding to an element silently makes it bigger than the width you set.

## Selectors and specificity

A selector's specificity is what the cascade compares when more than one rule matches with equal importance/origin — an ID (`#header`) always beats any number of classes, and any number of classes always beats any number of element selectors, regardless of how many of the weaker kind are stacked together.

```css
#header .nav a { }      /* 1 id, 1 class, 1 element  -> wins over the line below */
.nav .nav-link a.active { }  /* 0 ids, 3 classes, 1 element */
```

## Layout: flow, flex, and grid

Normal document flow (block elements stack vertically, inline elements flow horizontally) is CSS's default — `display: flex` and `display: grid` opt an element's children out of that default into a one-dimensional (flex) or two-dimensional (grid) layout algorithm instead, which is why almost no modern layout is built on floats anymore.
