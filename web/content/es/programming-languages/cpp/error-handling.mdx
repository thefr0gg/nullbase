C++ tiene dos formas superpuestas de lidiar con el fallo: las **excepciones**, que desenrollan la pila de llamadas hasta que algo las captura, y **RAII** (Resource Acquisition Is Initialization), un patrón de diseño que ata la limpieza de recursos a la vida útil de un objeto para que ocurra automáticamente — incluso cuando hay una excepción en curso.

## `try` / `catch` / `throw`

```cpp
#include <iostream>
#include <stdexcept>

double divide(double a, double b) {
    if (b == 0) {
        throw std::invalid_argument("division by zero");
    }
    return a / b;
}

int main() {
    try {
        std::cout << divide(10, 2) << "\n"; // 5
        std::cout << divide(10, 0) << "\n"; // throws
        std::cout << "This line never runs\n";
    } catch (const std::invalid_argument& e) {
        std::cout << "Caught: " << e.what() << "\n";
    }

    std::cout << "Program continues normally\n";
    return 0;
}
```

`throw` lanza una excepción — aquí, un `std::invalid_argument` del header `<stdexcept>`, uno de varios tipos de excepción estándar incorporados a la biblioteca. Lanzar detiene inmediatamente la ejecución normal y comienza a desenrollar la pila de llamadas, saltándose cada sentencia restante en `divide` y en el bloque `try` de `main`, hasta que alcanza un `catch` que coincide. `catch (const std::invalid_argument& e)` captura excepciones de exactamente ese tipo (o un tipo derivado de él); `e.what()` devuelve el mensaje pasado al constructor. Una vez que el bloque `catch` termina, la ejecución se reanuda normalmente después de todo el `try`/`catch` — el programa no se cae, y el código posterior (como el `std::cout` final) igual se ejecuta.

## RAII en lugar de limpieza manual

```cpp
#include <iostream>
#include <fstream>

void writeLog(const std::string& message) {
    std::ofstream logFile("app.log", std::ios::app); // resource acquired here

    if (!logFile.is_open()) {
        throw std::runtime_error("could not open log file");
    }

    logFile << message << "\n";
    // no explicit close() call needed — logFile's destructor closes the
    // file automatically when it goes out of scope, even if an exception
    // is thrown somewhere after this point
}

int main() {
    try {
        writeLog("Application started");
    } catch (const std::runtime_error& e) {
        std::cout << "Logging failed: " << e.what() << "\n";
    }
    return 0;
}
```

`std::ofstream` adquiere su recurso (un descriptor de archivo abierto) en su constructor y lo libera (cierra el archivo) en su destructor. Como C++ garantiza que el destructor de un objeto local se ejecuta cuando sale de ámbito — ya sea que ese ámbito termine normalmente, mediante `return`, o porque una excepción se está propagando a través de él — `logFile` nunca deja escapar un descriptor de archivo abierto, sin necesidad de `try`/`finally` ni de una llamada explícita a `close()` en ningún lugar. Este es el patrón que sigue la mayoría de los tipos de la biblioteca estándar de C++ (`std::vector`, `std::string`, `std::unique_ptr`), y es por eso que el C++ moderno idiomático rara vez necesita código de limpieza manual: envuelve un recurso en un tipo cuyo destructor lo libere, y la corrección se sigue automáticamente del ámbito.
