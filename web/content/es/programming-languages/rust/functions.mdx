Las funciones en Rust se declaran con `fn`, y cada parámetro necesita una anotación de tipo explícita — a diferencia de los bindings `let`, Rust no infiere los tipos de parámetros o de retorno a partir de cómo se llama a una función, porque eso haría que la firma de una función dependiera de sus sitios de llamada en vez de ser un contrato fijo.

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b // no semicolon: this is the returned expression
}

fn main() {
    let sum = add(3, 4);
    println!("{sum}");
}
```

## Expresiones frente a instrucciones como valores de retorno

La última expresión en el cuerpo de una función es automáticamente su valor de retorno, *siempre que no tenga un punto y coma al final*. Añade un punto y coma y se convierte en una instrucción que evalúa a `()`, cambiando silenciosamente lo que la función devuelve:

```rust
fn add_broken(a: i32, b: i32) -> i32 {
    a + b; // semicolon turns this into a statement, not a return value
} // error: mismatched types — expected i32, found ()
```

Todavía puedes usar una palabra clave `return` explícita — es necesaria para retornar anticipadamente desde la mitad de una función — pero depender de la expresión final para el camino de salida "normal" es el estilo idiomático.

```rust
fn classify(n: i32) -> &'static str {
    if n < 0 {
        return "negative"; // early return, semicolon required after return
    }
    if n == 0 {
        "zero"
    } else {
        "positive"
    } // trailing expression: the normal-path return value
}
```

## Closures

Un **closure** es una función anónima que puede capturar variables del ámbito en el que se define — escrito con barras verticales alrededor de sus parámetros (`|x| ...`) en vez de `fn name(x: T)`. Los closures se usan intensamente con métodos de iterador como `map` y `filter`.

```rust
fn main() {
    let threshold = 10;
    let numbers = vec![4, 12, 7, 15, 3];

    // the closure captures `threshold` from the surrounding scope
    let above: Vec<i32> = numbers.into_iter().filter(|n| *n > threshold).collect();

    println!("{above:?}"); // [12, 15]
}
```

A diferencia de un `fn` normal, este closure puede ver `threshold` sin que se le pase explícitamente — los closures toman prestadas o mueven las variables que referencian de su entorno, que es exactamente lo que permite que el closure de `filter` compare contra un valor definido fuera de él.
