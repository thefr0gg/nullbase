El código Rust se organiza en **módulos** (`mod`), que controlan tanto el namespacing como la visibilidad, y los proyectos se gestionan con **Cargo**, la herramienta de build y gestor de paquetes de Rust. Casi nadie invoca directamente al compilador `rustc` para un proyecto real — Cargo lo envuelve, además de la resolución de dependencias, las pruebas, y la publicación.

## `mod`: namespacing y privacidad

Un módulo agrupa elementos relacionados (funciones, structs, otros módulos) y, por defecto, los oculta del código externo — todo en Rust es **privado a menos que se marque `pub`**, el valor por defecto opuesto al de la mayoría de los lenguajes.

```rust
mod shapes {
    pub struct Circle {
        pub radius: f64,
    }

    impl Circle {
        pub fn area(&self) -> f64 {
            std::f64::consts::PI * self.radius * self.radius
        }
    }

    fn internal_helper() {
        // not pub — invisible outside this module, even to code in the same file
    }
}

fn main() {
    let c = shapes::Circle { radius: 2.0 };
    println!("area: {}", c.area());
}
```

Sin `pub` en `Circle`, `radius`, y `area`, ninguno de ellos sería accesible desde `main` — el compilador rechazaría `shapes::Circle { radius: 2.0 }` como acceso a un struct privado. La privacidad en Rust es aplicada por el compilador en cada frontera, no solo una convención de documentación.

## `use`: traer rutas al ámbito

Referirse a algo por su ruta completa (`shapes::Circle`) cada vez se vuelve tedioso. `use` trae una ruta al ámbito actual para que pueda nombrarse directamente:

```rust
mod shapes {
    pub struct Circle {
        pub radius: f64,
    }
}

use shapes::Circle;

fn main() {
    let c = Circle { radius: 3.0 }; // no shapes:: prefix needed
    println!("radius: {}", c.radius);
}
```

En un proyecto multiarchivo real, los módulos típicamente viven en sus propios archivos (`shapes.rs` o `shapes/mod.rs`), y las instrucciones `use` traen elementos de otros módulos en el mismo crate, o de dependencias externas.

## Cargo y crates.io

**Cargo** es la herramienta de build y gestor de paquetes de Rust, inicializado con `cargo new my_project`. Lee las dependencias de `Cargo.toml` y las descarga desde **crates.io**, el registro de paquetes de la comunidad (un "crate" es el término de Rust para una biblioteca o paquete compilado — aproximadamente lo que npm llama un paquete).

```toml
# Cargo.toml
[package]
name = "my_project"
version = "0.1.0"
edition = "2021"

[dependencies]
serde = "1.0"
rand = "0.8"
```

Con eso en su lugar, `use serde::Serialize;` o `use rand::Rng;` se vuelve disponible en cualquier parte del proyecto — `cargo build` resuelve y compila el grafo de dependencias automáticamente. Los comandos cotidianos de Cargo cubren todo el ciclo de vida: `cargo build` compila, `cargo run` compila y ejecuta, `cargo test` ejecuta pruebas, y `cargo publish` sube un crate a crates.io para que otros dependan de él.
