Rust separa "cuántos elementos, conocido en tiempo de compilación" de "cuántos elementos, decidido en tiempo de ejecución" a nivel de tipo. Un **array** es de tamaño fijo y vive en el stack; un **`Vec`** (vector) puede crecer y posee una asignación en el heap. Recurrir al equivocado es un error común al principio — los arrays no pueden crecer, así que cualquier cosa construida elemento por elemento necesita un `Vec`.

## Arrays

```rust
fn main() {
    let scores: [i32; 3] = [90, 85, 78];
    println!("first score: {}", scores[0]);
    println!("total scores: {}", scores.len());

    // scores.push(100); // error: no method named `push` on array [i32; 3]
}
```

El tipo `[i32; 3]` incorpora la longitud en el propio tipo — un array de 3 `i32` es un tipo diferente de uno de 4, y ninguno tiene un método `push`, porque su tamaño nunca puede cambiar después de crearse.

## `Vec<T>`

`Vec<T>` es la alternativa que puede crecer y está asignada en el heap — la colección a la que recurres por defecto cuando el número de elementos no está fijado de antemano.

```rust
fn main() {
    let mut scores: Vec<i32> = Vec::new();
    scores.push(90);
    scores.push(85);
    scores.push(78);

    // vec! macro is the more common way to write this
    let scores = vec![90, 85, 78];

    let average: i32 = scores.iter().sum::<i32>() / scores.len() as i32;
    println!("average: {average}");
}
```

Indexar un `Vec` fuera de límites (`scores[10]` en un vec de 3 elementos) hace panic en tiempo de ejecución en vez de devolver basura silenciosamente — Rust prefiere fallar ruidosamente antes que dejarte leer memoria que no es tuya. Para una búsqueda que no haga panic, `scores.get(10)` devuelve `Option<&i32>` — `None` en vez de un valor cuando el índice no existe.

## `HashMap<K, V>`

`HashMap` almacena pares clave-valor, similar a un diccionario en Python o un objeto usado como mapa en JavaScript. Tiene que importarse explícitamente desde `std::collections` — a diferencia de `Vec` y los arrays, no está en el prelude por defecto.

```rust
use std::collections::HashMap;

fn main() {
    let mut inventory: HashMap<String, i32> = HashMap::new();
    inventory.insert(String::from("apples"), 12);
    inventory.insert(String::from("bananas"), 6);

    match inventory.get("apples") {
        Some(count) => println!("apples: {count}"),
        None => println!("no apples tracked"),
    }

    // entry API: increment if present, insert 1 if not
    *inventory.entry(String::from("apples")).or_insert(0) += 1;
    println!("apples now: {}", inventory["apples"]);
}
```

`get` devuelve `Option<&V>` en vez del valor directamente, porque la clave podría no existir — este es el mismo patrón `Option` que usa `Vec::get`, y es central en cómo Rust evita errores de referencia nula (cubierto por completo en la página de [Manejo de Errores](/es/programming-languages/rust/error-handling)). La API `entry` de arriba es la forma idiomática de hacer "actualizar si está presente, insertar un valor por defecto si no" en una línea sin buscar la clave dos veces.
