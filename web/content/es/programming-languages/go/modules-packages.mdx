Go organiza el código en dos niveles: los **paquetes** agrupan archivos
fuente relacionados dentro de un directorio, y los **módulos** agrupan
paquetes en una unidad versionada y distribuible con su propia lista de
dependencias.

## Paquetes

Todo archivo `.go` empieza con una declaración `package`. Todos los archivos
en el mismo directorio deben declarar el mismo nombre de paquete, y ese
nombre se convierte en el espacio de nombres que otro código importa:

```go
package geometry

func Area(width, height float64) float64 {
	return width * height
}
```

Otro archivo en cualquier otro lugar lo importa por su ruta de módulo y
llama al nombre exportado (con mayúscula):

```go
package main

import (
	"fmt"

	"example.com/myapp/geometry"
)

func main() {
	fmt.Println(geometry.Area(3, 4)) // 12
}
```

`import` puede traer múltiples paquetes a la vez dentro de paréntesis, como
arriba. La librería estándar se distribuye como paquetes ordinarios que
importas de la misma manera — `"fmt"`, `"strings"`, `"net/http"` — sin ningún
paso de instalación aparte.

## go.mod y los módulos de Go

Un **módulo** es la unidad de versionado y gestión de dependencias —
normalmente un repositorio Git. `go mod init` crea un archivo `go.mod` que
declara la ruta del módulo y la versión de Go a la que apunta:

```bash
go mod init example.com/myapp
```

```go
module example.com/myapp

go 1.22
```

Añadir un import a una dependencia real y ejecutar `go build` (o `go mod
tidy`) la descarga y registra la versión exacta en `go.mod`, con una suma de
verificación criptográfica de cada dependencia en `go.sum`:

```go
module example.com/myapp

go 1.22

require github.com/google/uuid v1.6.0
```

`go.sum` no está pensado para editarse a mano — es un archivo de bloqueo que
Go mantiene para garantizar compilaciones reproducibles: el mismo `go.mod`
siempre resuelve al mismo código de dependencias, byte por byte.

## Comandos útiles de módulos

```bash
go mod init example.com/myapp   # iniciar un nuevo módulo
go mod tidy                      # añadir dependencias faltantes / eliminar las que no se usan
go get github.com/some/pkg@v1.2.0  # añadir o actualizar una dependencia
go build ./...                    # compilar todos los paquetes del módulo
```

## Paquetes internos

Un directorio llamado `internal` restringe quién puede importarlo: los
paquetes bajo `internal/` solo pueden importarse desde código dentro del
árbol de módulos con raíz en el padre de `internal`. Este es el mecanismo
integrado de Go para marcar código como "detalle de implementación, no parte
de tu API pública", impuesto por el compilador y no solo por convención.
