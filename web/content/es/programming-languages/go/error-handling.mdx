Go no tiene excepciones ni `try`/`catch`. Los errores son valores
ordinarios, devueltos junto al resultado normal de una función, y
comprobados con una simple sentencia `if`. Esta es una decisión de diseño
deliberada: obliga a que las rutas de error sean visibles en el código en
vez de estar ocultas en un salto de flujo de control que puede capturarse en
cualquier punto de la pila de llamadas.

## El tipo `error` y `if err != nil`

`error` es una interfaz integrada con un único método, `Error() string`.
Cualquier tipo que la implemente puede usarse como un error. Por convención,
una función que puede fallar devuelve su resultado más un `error` como su
último valor de retorno, y `nil` significa "sin error":

```go
func divide(a, b float64) (float64, error) {
	if b == 0 {
		return 0, errors.New("cannot divide by zero")
	}
	return a / b, nil
}

func main() {
	result, err := divide(10, 0)
	if err != nil {
		fmt.Println("error:", err)
		return
	}
	fmt.Println("result:", result)
}
```

`if err != nil` inmediatamente después de una llamada es el idioma más común
en el código Go. Parece repetitivo si vienes de un lenguaje con try/catch,
pero significa que cada llamada que puede fallar tiene un punto de decisión
explícito y visible justo donde ocurre — nada se propaga de forma invisible.

## Construir errores

`errors.New` crea un error simple a partir de una cadena. `fmt.Errorf` hace
lo mismo pero soporta formateo, y `%w` envuelve un error existente para que
pueda desenvolverse más tarde:

```go
import (
	"errors"
	"fmt"
)

var ErrNotFound = errors.New("item not found")

func find(id int) error {
	if id != 1 {
		return fmt.Errorf("looking up id %d: %w", id, ErrNotFound)
	}
	return nil
}

func main() {
	err := find(99)
	if errors.Is(err, ErrNotFound) {
		fmt.Println("not found, as expected")
	}
}
```

`errors.Is` comprueba si un error (o cualquier cosa que envuelva) coincide
con un error centinela conocido como `ErrNotFound` — así es como Go te deja
comprobar condiciones de error específicas sin excepciones ni jerarquías de
tipos.

## Tipos de error personalizados

Cualquier tipo con un método `Error() string` satisface la interfaz `error`,
así que puedes adjuntar datos estructurados a tus errores:

```go
type ValidationError struct {
	Field string
}

func (e *ValidationError) Error() string {
	return "invalid field: " + e.Field
}

func validate(age int) error {
	if age < 0 {
		return &ValidationError{Field: "age"}
	}
	return nil
}
```

## panic y recover existen, pero no son para errores normales

Go sí tiene `panic` y `recover`, pero están reservados para situaciones
verdaderamente irrecuperables (un bug de programación como un índice fuera
de rango), no para el manejo de errores cotidiano. El código Go idiomático
casi nunca entra en pánico deliberadamente por algo que quien lo llama
podría razonablemente querer manejar — eso pertenece a un `error` devuelto.
