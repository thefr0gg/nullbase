La historia de módulos de PHP tiene dos capas fáciles de confundir al
principio: las instrucciones de inclusión de archivos de bajo nivel
(`require`/`include`), que han estado en el lenguaje desde el principio, y
los namespaces más Composer, que llegaron después y ahora forman la columna
vertebral de cómo se organiza y comparte realmente el código PHP moderno.

## require e include

Estas instrucciones traen el código de otro archivo PHP al actual, más o
menos como `#include` en C pero evaluado en tiempo de ejecución, no en
tiempo de compilación:

```php
<?php
// math.php
function square(int $n): int {
    return $n * $n;
}
```

```php
<?php
require "math.php";

echo square(5) . "\n"; // 25
```

`require` genera un error fatal si falta el archivo; `include` solo genera
una advertencia y deja que el script continúe. `require_once`/
`include_once` añaden una comprobación que evita volver a incluir un archivo
ya cargado — importante para evitar errores de "función ya declarada" cuando
varios archivos podrían traer la misma dependencia.

```php
<?php
require_once "math.php";
require_once "math.php"; // silently skipped, already loaded
```

En la práctica, los proyectos PHP modernos rara vez escriben `require` a
mano para su propio código — el autoloader de Composer (a continuación) lo
hace innecesario — pero sigue siendo exactamente lo que se ejecuta por
debajo.

## Namespaces

Un `namespace` agrupa clases/funciones/constantes relacionadas bajo un
prefijo común, evitando colisiones de nombres entre tu código y el de una
biblioteca (o entre dos bibliotecas) de la misma forma en que lo hacen los
paquetes de Java o los namespaces de C++:

```php
<?php
// src/Billing/Invoice.php
namespace App\Billing;

class Invoice {
    public function __construct(public float $amount) {}
}
```

```php
<?php
require "src/Billing/Invoice.php";

use App\Billing\Invoice;

$invoice = new Invoice(150.0);
echo $invoice->amount . "\n"; // 150
```

`use` importa un nombre con namespace para que puedas referirte a él sin
calificar; sin ella, tendrías que escribir el nombre completamente
calificado `App\Billing\Invoice` cada vez.

## Composer y composer.json

Composer es el gestor de dependencias estándar de facto de PHP — casi todo
proyecto PHP moderno, y todo framework importante (Laravel, Symfony), lo
asume. Un proyecto declara sus dependencias en `composer.json`:

```json
{
    "name": "acme/billing-app",
    "require": {
        "php": ">=8.2",
        "monolog/monolog": "^3.0"
    },
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    }
}
```

`composer require monolog/monolog` añade una dependencia y actualiza este
archivo automáticamente; `composer install` lo lee (junto con el archivo de
bloqueo, `composer.lock`) y descarga versiones exactas y reproducibles en
`vendor/`.

La sección `autoload` es lo que reemplaza las llamadas manuales a `require`:
Composer genera un **autoloader PSR-4** que mapea un prefijo de namespace a
un directorio, así que las clases se cargan bajo demanda la primera vez que
se referencian:

```php
<?php
require "vendor/autoload.php"; // the one require you still write by hand

use App\Billing\Invoice;
use Monolog\Logger;

$invoice = new Invoice(200.0);
$logger = new Logger("billing");
```

Con esa única línea `require "vendor/autoload.php"`, tanto tus propias
clases con namespace bajo `src/` como cada paquete instalado por Composer
quedan disponibles sin más includes manuales.
