PHP comenzó en 1994 como un pequeño conjunto de scripts en Perl que Rasmus
Lerdorf escribió para rastrear las visitas a su currículum en línea —
"Personal Home Page Tools." Creció, un poco por accidente, hasta convertirse
en uno de los lenguajes del lado del servidor más ampliamente desplegados en
internet. WordPress, gran parte del código base original de Facebook,
Wikipedia, y una gran parte de los sistemas de gestión de contenido de la web
están construidos sobre PHP.

A diferencia de Go o Rust, PHP nunca fue diseñado de arriba hacia abajo como
un lenguaje cohesivo. Creció característica por característica para resolver
problemas reales que la gente tenía al construir sitios web, y esa historia
se nota: PHP tiene algunas esquinas genuinamente incómodas (nombres de
funciones de la biblioteca estándar inconsistentes, comparaciones de tipos
históricamente laxas) junto a características modernas y bien diseñadas
añadidas en PHP 7 y 8 (declaraciones de tipo escalar, compilación JIT, enums,
propiedades readonly). El PHP moderno — el PHP que escribirías hoy con
Composer, estándares PSR, y un framework como Laravel o Symfony — se ve muy
diferente del PHP de principios de los 2000, aunque ambos siguen siendo
compatibles a nivel de código fuente en la mayoría de los aspectos.

## Lo que hace distintivo a PHP

- **Construido para el ciclo de solicitud/respuesta.** Un script PHP se
  ejecuta una vez por solicitud HTTP y luego todo el estado de su proceso
  desaparece — no hay un servidor de aplicación de larga duración que
  mantenga objetos en memoria entre solicitudes como sí ocurre en Node.js o
  una app JVM, a menos que recurras a algo como Swoole o FrankenPHP.
- **Se incrusta directamente en HTML.** PHP fue originalmente un lenguaje de
  plantillas: entras en etiquetas `<?php ?>` dentro de un archivo HTML por
  lo demás ordinario, y todo lo que está fuera de esas etiquetas se emite tal
  cual.
- **Cada variable empieza con `$`.** No hay ambigüedad entre una palabra
  suelta (un nombre de función, una constante) y una variable — el sigilo lo
  aclara de un vistazo.
- **Los arrays hacen doble función.** Un único tipo `array` en PHP sirve
  tanto de lista como de mapa hash, lo cual es conveniente pero tiene su
  propia curva de aprendizaje (más sobre esto en
  [Arrays](/es/programming-languages/php/data-structures)).
- **Una biblioteca estándar enorme y desigual.** PHP incluye cientos de
  funciones integradas que cubren cadenas, arrays, fechas, y más — pero el
  nombrado y el orden de los argumentos son inconsistentes entre ellas
  (`strpos($haystack, $needle)` frente a `array_search($needle, $haystack)`),
  una verruga bien conocida del crecimiento orgánico de PHP.

Aquí tienes un script PHP mínimo y completo:

```php
<?php

echo "Hello, nullbase!\n";
```

Guarda eso como `hello.php` y ejecútalo con `php hello.php`, o colócalo en un
servidor con un runtime de PHP y solicítalo por HTTP — ambos funcionan con
exactamente el mismo archivo.

## Cuándo recurrirías a PHP

PHP sigue siendo una excelente opción para sitios web renderizados en el
servidor, gestión de contenido, y cualquier cosa donde "llega una solicitud,
se consulta la base de datos, sale HTML" sea el bucle principal. Su modelo de
no compartir nada entre solicitudes también lo hace tolerante con las fugas
de memoria en el código de la aplicación — cada solicitud empieza desde cero.
Es menos natural para procesos en segundo plano de larga duración o cargas de
trabajo genuinamente concurrentes, aunque las extensiones y runtimes
alternativos han ido reduciendo esa limitación a lo largo de los años.
