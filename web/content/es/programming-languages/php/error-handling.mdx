El PHP moderno maneja los fallos con excepciones, de forma muy parecida a
Java o Python. Pero la historia de PHP hace que aún te encuentres con un
mecanismo más antiguo y separado — los "errores" y "advertencias" de PHP —
especialmente en código heredado o cuando una función integrada falla de una
manera anterior al modelo de excepciones de PHP. Conocer ambos importa para
leer bases de código PHP reales.

## try / catch / finally

```php
<?php

function divide(int $a, int $b): float {
    if ($b === 0) {
        throw new InvalidArgumentException("Cannot divide by zero");
    }
    return $a / $b;
}

try {
    echo divide(10, 0);
} catch (InvalidArgumentException $e) {
    echo "Error: " . $e->getMessage() . "\n";
} finally {
    echo "Division attempt finished\n";
}
```

`finally` se ejecuta se haya lanzado o capturado una excepción o no — útil
para limpieza como cerrar un descriptor de archivo o una conexión a base de
datos.

## Capturar múltiples tipos de excepción

Un único bloque `catch` puede listar varios tipos de excepción con `|`, y
los bloques catch se prueban en orden, así que pon los tipos más específicos
primero:

```php
<?php

function parseConfig(string $json): array {
    $data = json_decode($json, true, flags: JSON_THROW_ON_ERROR);
    return $data;
}

try {
    parseConfig("{not valid json");
} catch (JsonException | TypeError $e) {
    echo "Could not parse config: " . $e->getMessage() . "\n";
}
```

## Excepciones personalizadas

Las excepciones son clases ordinarias que extienden `Exception` (o una
subclase integrada más específica como `RuntimeException`). Esto te permite
llevar datos estructurados y capturar un fallo específico a nivel de
aplicación por tipo:

```php
<?php

class InsufficientFundsException extends RuntimeException {
    public function __construct(public readonly float $shortfall) {
        parent::__construct("Insufficient funds, short by $shortfall");
    }
}

function withdraw(float $balance, float $amount): float {
    if ($amount > $balance) {
        throw new InsufficientFundsException($amount - $balance);
    }
    return $balance - $amount;
}

try {
    withdraw(50.0, 75.0);
} catch (InsufficientFundsException $e) {
    echo "Short by: " . $e->shortfall . "\n";
}
```

## El modelo de reporte de errores más antiguo, brevemente

Antes de que las excepciones fueran plenamente adoptadas (y aún hoy para
muchas funciones integradas), PHP reportaba problemas como **errores,
advertencias, y avisos** — eventos que no son excepciones y que podían
registrarse, mostrarse en línea en la salida, o ignorarse silenciosamente
según la configuración de `error_reporting`, en vez de desenrollar la pila
de llamadas como lo hace una excepción lanzada:

```php
<?php

$value = @$undefinedArray["missing"]; // @ suppresses the warning
echo $value === null ? "null, no exception thrown\n" : "found\n";
```

Ese operador de "supresión de errores" `@` es un patrón heredado que la
mayoría de las guías de estilo modernas de PHP desaconsejan — oculta bugs
genuinos junto con el ruido. PHP 8 convirtió muchas de estas antiguas
advertencias en excepciones `Error` apropiadas (una jerarquía hermana de
`Exception`, ambas implementando `Throwable`), razón por la cual llamar a
una función indefinida ahora lanza un `Error` que puedes capturar con
`catch`, en vez de simplemente emitir una advertencia y continuar con
`null`.
