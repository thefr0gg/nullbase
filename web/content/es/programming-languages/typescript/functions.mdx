Las funciones de JavaScript aceptan cualquier argumento que les des, y una llamada con el número o tipo de argumentos equivocado normalmente falla silenciosamente (los argumentos extra se ignoran, los faltantes se vuelven `undefined`) o lanza una excepción en lo profundo del cuerpo de la función. Las firmas de función de TypeScript declaran exactamente qué se espera, y el compilador verifica cada sitio de llamada contra esa declaración antes de que el código se ejecute siquiera.

## Parámetros y tipos de retorno tipados

```ts
function add(a: number, b: number): number {
  return a + b;
}

add(2, 3); // 5
add(2, "3"); // Type error: Argument of type 'string' is not assignable to parameter of type 'number'
add(2); // Type error: Expected 2 arguments, but got 1
```

`a: number` y `b: number` restringen los parámetros; `: number` después de la lista de parámetros restringe lo que la función puede `return`. Si el cuerpo de la función intentara `return a + b + "!"` (una cadena), el compilador también lo rechazaría — el tipo de retorno declarado se verifica contra las instrucciones return reales, no solo se infiere y se deja sin verificar.

También puedes dejar que TypeScript infiera el tipo de retorno en vez de escribirlo explícitamente:

```ts
function multiply(a: number, b: number) {
  return a * b; // return type inferred as number
}
```

Los tipos de retorno explícitos siguen valiendo la pena escribirse en funciones exportadas/públicas — actúan como un contrato que no cambia silenciosamente si alguien edita el cuerpo de la función más tarde.

## Parámetros opcionales

Añadir `?` al nombre de un parámetro lo hace opcional — quienes llaman pueden omitirlo, y dentro de la función su tipo incluye `undefined`:

```ts
function greet(name: string, title?: string): string {
  if (title) {
    return `Hello, ${title} ${name}!`;
  }
  return `Hello, ${name}!`;
}

greet("Ada"); // "Hello, Ada!"
greet("Ada", "Dr."); // "Hello, Dr. Ada!"
```

Los parámetros opcionales deben venir después de todos los requeridos en la lista de parámetros — `function f(a?: string, b: string)` es un error en tiempo de compilación, ya que no habría forma de saber a qué argumento estaba destinado a llenar una llamada con un solo valor.

## Parámetros por defecto

Un valor por defecto hace que un parámetro sea opcional en el sitio de la llamada mientras le da un valor concreto dentro del cuerpo de la función — sin necesidad de comprobación de `undefined`:

```ts
function createUser(name: string, role: string = "member") {
  return { name, role };
}

createUser("Ada"); // { name: "Ada", role: "member" }
createUser("Ada", "admin"); // { name: "Ada", role: "admin" }
```

Debido a que el tipo de `role` se infiere de su valor por defecto (`string`), pasar cualquier cosa que no sea `string | undefined` sigue sin compilar — `createUser("Ada", 1)` es un error de tipo, aunque `role` tenga un valor por defecto.
