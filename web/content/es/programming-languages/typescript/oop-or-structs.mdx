Las clases de JavaScript soportan `class`, `constructor`, y métodos desde ES2015, pero no tienen ningún concepto de que un campo sea privado o público — cada propiedad es alcanzable desde fuera de la instancia. TypeScript añade **modificadores de acceso** que el compilador aplica, más `interface`, una forma de declaración dedicada a describir formas para la cual JavaScript plano no tiene ningún equivalente.

## Clases con modificadores de acceso

```ts
class BankAccount {
  public owner: string;
  private balance: number;
  readonly accountId: string;

  constructor(owner: string, accountId: string, startingBalance: number) {
    this.owner = owner;
    this.accountId = accountId;
    this.balance = startingBalance;
  }

  deposit(amount: number): void {
    this.balance += amount;
  }

  getBalance(): number {
    return this.balance;
  }
}

const acct = new BankAccount("Ada", "acc-1", 100);
acct.deposit(50); // OK — public method
console.log(acct.balance); // Type error: Property 'balance' is private and only accessible within class 'BankAccount'
acct.accountId = "acc-2"; // Type error: Cannot assign to 'accountId' because it is a read-only property
```

- `public` (el valor por defecto) — accesible desde cualquier parte.
- `private` — accesible solo dentro del propio cuerpo de la clase, no desde instancias o subclases.
- `readonly` — asignable solo una vez, en el constructor.

Estas comprobaciones desaparecen por completo del JavaScript compilado emitido — `private` y `readonly` son garantías exclusivamente en tiempo de compilación. (TypeScript también soporta campos verdaderamente privados en tiempo de ejecución mediante la sintaxis `#field`, que el propio JavaScript define y aplica en tiempo de ejecución, a diferencia de `private`.)

## Propiedades de constructor abreviadas

Escribir un campo, y luego reasignarlo desde un parámetro de constructor con el mismo nombre, es lo suficientemente común como para que TypeScript te permita colapsar ambos en una sola declaración añadiendo un modificador de acceso directamente a un parámetro del constructor:

```ts
class Point {
  constructor(
    public x: number,
    public y: number,
  ) {}
}

const p = new Point(3, 4);
console.log(p.x, p.y); // 3 4
```

Esto declara `x` y `y` como campos públicos en la clase *y* los asigna desde los argumentos del constructor, sin necesidad de declaraciones de campo separadas ni líneas `this.x = x`.

## interface frente a type

Tanto `interface` como `type` pueden describir la forma de un objeto, y para formas de objeto simples suelen ser intercambiables:

```ts
interface UserI {
  id: number;
  name: string;
}

type UserT = {
  id: number;
  name: string;
};
```

Las diferencias que importan en la práctica:

- **Fusión de declaraciones**: dos declaraciones `interface` con el mismo nombre se fusionan en una; dos alias `type` con el mismo nombre son un error en tiempo de compilación (identificador duplicado).
- **Qué pueden describir**: `type` puede aliasar cualquier cosa — uniones, tuplas, primitivos (`type Id = string | number`) — mientras que `interface` solo puede describir formas de objeto/clase.
- **Extender**: `interface` extiende otra con `extends`; `type` combina formas con una intersección (`&`).

```ts
interface Animal {
  name: string;
}
interface Dog extends Animal {
  breed: string;
}

type Vehicle = { wheels: number };
type Car = Vehicle & { brand: string };
```

Una clase puede hacer `implements` de cualquiera de las dos formas, siempre que la forma sea un tipo objeto — `class Labrador implements Dog { ... }` funciona igual que `class Labrador implements Car { ... }` lo haría, estructuralmente.
