**TypeScript** es un lenguaje de tipado estático que compila a JavaScript plano. No introduce un nuevo runtime, un nuevo recolector de basura, ni nueva semántica de ejecución — todo programa JavaScript válido es (casi) TypeScript válido, y todo programa TypeScript eventualmente se convierte en JavaScript que se ejecuta en los mismos motores en los que JavaScript ya se ejecuta (V8, Node, navegadores). Lo que TypeScript añade es un **verificador de tipos**: un paso separado en tiempo de compilación que lee tus anotaciones y tipos inferidos, señala discrepancias, y luego borra toda esa información de tipo antes de que el código se ejecute siquiera.

Esa última parte importa. Los tipos en TypeScript tienen **costo cero en tiempo de ejecución y presencia cero en tiempo de ejecución** — `interface`, `type`, y la mayoría de las anotaciones de tipo desaparecen por completo durante la compilación (`tsc`, o un transpilador como esbuild/SWC). Por eso TypeScript puede detectar toda una categoría de bugs — pasar un `string` donde se espera un `number`, llamar a un método que no existe en un objeto, olvidar manejar `null` — antes incluso de ejecutar el programa, sin cambiar cómo se comporta el programa una vez que se ejecuta.

## Por qué añadir un sistema de tipos a JavaScript

El tipado dinámico de JavaScript es flexible pero significa que muchos errores solo salen a la superficie en tiempo de ejecución, a menudo en producción. El compilador de TypeScript verifica las formas de tus datos mientras escribes código:

```ts
function greet(name: string) {
  return `Hello, ${name.toUpperCase()}!`;
}

greet("Ada");
greet(42); // Type error: Argument of type 'number' is not assignable to parameter of type 'string'
```

La segunda llamada habría lanzado un `TypeError` en tiempo de ejecución en JavaScript plano (`42.toUpperCase is not a function`) — pero solo una vez que esa línea realmente se ejecutara, quizás en lo profundo de una ruta de código rara vez alcanzada. TypeScript lo detecta inmediatamente, en el momento en que lo escribes, en tu editor.

## Tipado estructural

A diferencia de lenguajes basados en clases como Java o C#, el sistema de tipos de TypeScript es **estructural**, no nominal: dos tipos son compatibles si tienen la misma forma, sin importar el nombre o la relación declarada.

```ts
interface Point {
  x: number;
  y: number;
}

function printPoint(p: Point) {
  console.log(`(${p.x}, ${p.y})`);
}

const coord = { x: 3, y: 4, label: "origin-ish" };
printPoint(coord); // OK — coord has at least x and y as numbers
```

`coord` nunca se declaró como un `Point`, e incluso tiene un campo extra `label`, pero satisface estructuralmente la forma de `Point`, así que la asignación se permite. Esta es una decisión de diseño deliberada que refleja cómo los objetos de JavaScript realmente se pasan de un lado a otro.
