La programación asíncrona es el tema intermedio distintivo de JavaScript —
el punto donde el diseño de un solo hilo y orientado a eventos del lenguaje
se convierte en algo sobre lo que tienes que razonar activamente en vez de
algo que permanece invisible. Entender las Promises, `async`/`await`, y más
o menos cómo el bucle de eventos las programa es lo que separa "puedo
escribir JavaScript" de "puedo predecir qué hará mi JavaScript".

## Promises

Una `Promise` representa un valor que todavía no está disponible — el
resultado eventual de una operación asíncrona como una solicitud de red.
Siempre está en uno de tres estados: pendiente, cumplida (fulfilled, con un
valor), o rechazada (rejected, con un error), y una vez que se resuelve (se
cumple o se rechaza), permanece así permanentemente.

```js
function delay(ms, value) {
  return new Promise(resolve => {
    setTimeout(() => resolve(value), ms);
  });
}

delay(1000, "done!")
  .then(result => console.log(result)) // "done!" después de ~1 segundo
  .catch(err => console.error(err));
```

`.then()` registra un callback para el cumplimiento, `.catch()` para el
rechazo, y ambos devuelven una nueva Promise, que es lo que te permite
encadenarlos:

```js
delay(500, 5)
  .then(n => n * 2)
  .then(n => n + 1)
  .then(result => console.log(result)) // 11
  .catch(err => console.error("Something failed:", err));
```

`Promise.all` ejecuta varias Promises concurrentemente y se resuelve una
vez que todas lo han hecho, en el orden original — útil cuando las
operaciones no dependen entre sí y de otro modo estarías esperándolas una a
la vez sin razón.

```js
Promise.all([delay(100, "a"), delay(50, "b"), delay(200, "c")]).then(
  results => console.log(results) // ["a", "b", "c"] después de ~200ms en total, no 350ms
);
```

## async/await

`async`/`await` es sintaxis construida sobre las Promises que permite que
el código asíncrono se lea como código síncrono ordinario. Una función
`async` siempre devuelve una Promise, y `await` pausa la ejecución *dentro
de esa función* (no del programa entero) hasta que la Promise a la que se
le hizo await se resuelve.

```js
async function getUserSummary(id) {
  const response = await fetch(`/api/users/${id}`);
  const user = await response.json();
  return `${user.name} (${user.email})`;
}

getUserSummary(1).then(summary => console.log(summary));
```

Esto es exactamente equivalente a la cadena `.then()`, solo que más fácil
de leer y de envolver en `try`/`catch` para el manejo de errores. Ejecutar
`await`s independientes secuencialmente desperdicia tiempo de la misma
manera que lo haría una cadena `.then()` ingenua — usa `Promise.all` cuando
las operaciones no dependan entre sí:

```js
// Secuencial — espera a que la primera solicitud termine completamente antes de iniciar la segunda.
async function slow() {
  const a = await delay(100, "a");
  const b = await delay(100, "b");
  return [a, b]; // toma ~200ms
}

// Concurrente — ambas solicitudes están en curso al mismo tiempo.
async function fast() {
  const [a, b] = await Promise.all([delay(100, "a"), delay(100, "b")]);
  return [a, b]; // toma ~100ms
}
```

## El bucle de eventos, brevemente

JavaScript se ejecuta en un solo hilo, así que no puede literalmente hacer
dos cosas a la vez. En su lugar, el runtime (un navegador o Node.js) delega
las operaciones lentas — temporizadores, E/S de red, acceso a archivos —
para que se manejen fuera de ese hilo, y el **bucle de eventos** es el
mecanismo que trae de vuelta sus resultados como callbacks una vez que tu
código actualmente en ejecución termina. Crucialmente, la pila de llamadas
siempre se ejecuta hasta completarse antes de que el bucle de eventos
procese cualquier cosa en cola detrás de ella — por esto `setTimeout(fn,
0)` no se ejecuta inmediatamente, se ejecuta después de que todo el código
síncrono actualmente en cola haya terminado.

```js
console.log("1: start");

setTimeout(() => console.log("2: timeout"), 0);

Promise.resolve().then(() => console.log("3: promise"));

console.log("4: end");

// Orden de salida: 1, 4, 3, 2
```

El código síncrono (`1` y `4`) siempre se ejecuta primero, en orden. Luego
los callbacks de Promise en cola (la "cola de microtareas") se ejecutan
antes que los callbacks de temporizador en cola (la "cola de macrotareas")
— por lo que `3` se imprime antes que `2` aunque la Promise se haya
programado después del timeout.
