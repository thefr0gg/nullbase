Las funciones se definen con `def`, y Python no exige declarar un tipo de retorno ni tipos de parámetros — sin embargo, a los parámetros se les pueden dar valores por defecto, lo cual los hace opcionales en el sitio de la llamada.

```python
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

print(greet("Sam"))                 # Hello, Sam!
print(greet("Sam", greeting="Hey"))  # Hey, Sam!
```

`greeting="Hello"` le da a ese parámetro un valor por defecto, así que quienes llaman pueden omitirlo por completo. Los argumentos también pueden pasarse por nombre (`greeting="Hey"`) en vez de por posición, lo cual es útil una vez que una función toma varios parámetros y el sitio de la llamada, de otro modo, sería una lista confusa de valores sueltos.

A veces el número de argumentos que una función debería aceptar no está fijado de antemano. `*args` recolecta cualquier argumento posicional adicional en una tupla, y `**kwargs` recolecta cualquier argumento con nombre adicional en un dict — los nombres `args`/`kwargs` son solo convención, los prefijos `*`/`**` son lo que importa.

```python
def total(*args, **kwargs):
    print("positional:", args)     # (1, 2, 3)
    print("keyword:", kwargs)       # {'label': 'sum'}
    return sum(args)

result = total(1, 2, 3, label="sum")
print(result)  # 6
```

Este patrón aparece constantemente en código de bibliotecas — una función envoltorio que necesita aceptar "cualesquiera argumentos que acepte lo que envuelve" sin conocer esa firma de antemano usa `def wrapper(*args, **kwargs)` y los reenvía con `wrapped(*args, **kwargs)`.

Las funciones también son objetos ordinarios: pueden asignarse a variables, pasarse como argumentos, y devolverse desde otras funciones, que es lo que hace posibles a los closures.

```python
def make_multiplier(factor):
    def multiplier(x):
        return x * factor
    return multiplier

double = make_multiplier(2)
triple = make_multiplier(3)
print(double(5), triple(5))  # 10 15
```

`multiplier` "recuerda" el valor de `factor` de la llamada que lo creó, incluso después de que `make_multiplier` ya ha retornado — eso es un closure, y es el mecanismo detrás de los decoradores de Python.
