Cualquier archivo `.py` es un **módulo**, y su código de nivel superior (funciones, clases, variables) se vuelve disponible en otros lugares mediante `import`.

```python
import math
from datetime import date

print(math.sqrt(16))   # 4.0
print(date.today())      # 2026-09-01, for example
```

`import math` trae todo el módulo, y su contenido se accede con `math.sqrt(...)`; `from datetime import date` trae un nombre específico directamente al ámbito, así que se usa como `date` en vez de `datetime.date`. Tanto `math` como `datetime` vienen en la biblioteca estándar de Python — no se necesita instalación.

Tus propios archivos funcionan de la misma manera: cualquier nombre definido en el nivel superior de `mymodule.py` se vuelve importable como `mymodule.name` (o mediante `from mymodule import name`) desde otro archivo del mismo proyecto.

```python
# mymodule.py
def add(a, b):
    return a + b
```

```python
# main.py
from mymodule import add
print(add(2, 3))  # 5
```

Para código más allá de la biblioteca estándar, `pip` instala **paquetes** publicados en el Python Package Index (PyPI). Debido a que diferentes proyectos en la misma máquina a menudo necesitan versiones conflictivas del mismo paquete, los proyectos Python casi siempre usan un **entorno virtual** — un conjunto aislado y local al proyecto de paquetes instalados — en vez de instalar todo de forma global.

```bash
python -m venv .venv
source .venv/bin/activate   # .venv\Scripts\activate on Windows
pip install requests
pip freeze > requirements.txt
```

`python -m venv .venv` crea el entorno aislado en una carpeta `.venv`; `activate` hace que la shell use el Python y `pip` de ese entorno en vez de los del sistema; `pip freeze > requirements.txt` captura exactamente lo que está instalado (con versiones fijadas) para que el entorno pueda recrearse en otro lugar con `pip install -r requirements.txt`.

Los proyectos más nuevos declaran cada vez más las dependencias en `pyproject.toml` en vez de un `requirements.txt` desnudo, ya que también captura el nombre, versión, y configuración de build del proyecto en un único archivo estandarizado:

```toml
[project]
name = "my-app"
version = "0.1.0"
dependencies = ["requests>=2.31"]
```
