Python señala fallos lanzando excepciones, y manejar una significa envolver el código riesgoso en un bloque `try` con una o más cláusulas `except` que capturan tipos de excepción específicos.

```python
try:
    value = int(input("Enter a number: "))
except ValueError:
    print("That wasn't a valid number.")
else:
    print(f"You entered {value}")
finally:
    print("Done processing input.")
```

Cada cláusula tiene un trabajo distinto: el bloque `try` contiene el código que podría fallar; `except ValueError` solo captura ese error específico (un `TypeError` en otra parte del bloque se propagaría sin capturar); `else` se ejecuta solo si el bloque `try` se completó sin ninguna excepción en absoluto; `finally` siempre se ejecuta — haya excepción o no, haya `return` o no — lo cual lo convierte en el lugar correcto para limpieza como cerrar un archivo o liberar un bloqueo.

Capturar `except ValueError` específicamente, en vez de un `except:` desnudo, importa: un `except` desnudo se traga *todo*, incluidos errores tipográficos que lanzan `NameError` e interrupciones como `KeyboardInterrupt`, lo cual hace que bugs reales desaparezcan silenciosamente en vez de salir a la superficie.

Las excepciones personalizadas son solo clases que heredan de `Exception` (o de una excepción incorporada más específica), lo cual permite que el código que llama capture tu modo de fallo específico por nombre en vez de adivinar mensajes de cadena.

```python
class InsufficientFundsError(Exception):
    """Raised when a withdrawal exceeds the account balance."""

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError(f"Cannot withdraw {amount}, balance is {balance}")
    return balance - amount

try:
    withdraw(100, 150)
except InsufficientFundsError as e:
    print(e)  # Cannot withdraw 150, balance is 100
```

`raise` es cómo el código señala un fallo explícitamente; `except ... as e` vincula la instancia de excepción capturada a un nombre para que su mensaje (o cualquier dato extra adjunto a ella) pueda inspeccionarse.

```python
def read_config(path):
    try:
        with open(path) as f:
            return f.read()
    except FileNotFoundError:
        return "{}"
```

Aquí un modo de fallo específico y esperado (el archivo aún no existe) se maneja con un fallback razonable, mientras que cualquier otro error — un problema de permisos, un fallo de disco — se deja propagar, ya que tragárselos silenciosamente ocultaría un problema real.
