Un **decorador** es una función que toma una función y devuelve una nueva función que la envuelve — usado para añadir comportamiento (registro, cronometraje, comprobaciones de acceso) sin tocar el cuerpo de la función original. La sintaxis `@decorator` encima de un `def` es solo una forma abreviada de reasignar la función al valor de retorno del decorador.

```python
def logged(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@logged
def add(a, b):
    return a + b

print(add(2, 3))
# Calling add
# 5
```

`@logged` encima de `def add(...)` es equivalente a escribir `add = logged(add)` justo después de definirlo — cada llamada a `add` ahora realmente llama a `wrapper`, que imprime, luego llama a la `add` original mediante el closure sobre `func`, y devuelve su resultado. Este es el mismo mecanismo de closure cubierto en [Funciones](/es/programming-languages/python/functions), aplicado para envolver comportamiento en vez de simplemente capturar un valor.

Un **generador** es una función que produce una secuencia de valores perezosamente, uno a la vez, usando `yield` en vez de `return`. Llamar a una función generadora no ejecuta su cuerpo inmediatamente — devuelve un objeto generador, y el cuerpo solo avanza hasta el siguiente `yield` cada vez que se solicita un valor.

```python
def countdown(n):
    while n > 0:
        yield n
        n -= 1

for number in countdown(3):
    print(number)
# 3
# 2
# 1
```

Cada iteración del bucle `for` reanuda `countdown` justo después de su `yield`, en vez de volver a ejecutar toda la función desde cero — el estado local de la función (`n`, y su posición en el bucle `while`) se preserva entre yields. Esto hace que los generadores sean eficientes en memoria para secuencias grandes o sin límite: no hace falta que exista en memoria a la vez nada más allá del valor actual.

Una **expresión generadora** — `(expr for item in iterable)` — es la contraparte perezosa de una comprensión de lista, produciendo el mismo tipo de generador uno-a-la-vez sin ningún `def` ni `yield` en absoluto.

```python
squares = (x * x for x in range(5))
print(next(squares))       # 0
print(next(squares))       # 1
print(list(squares))       # [4, 9, 16] — the rest, in one go
```

`next()` extrae exactamente un valor del generador cada vez que se llama; `list()` drena lo que quede. Nota que los dos primeros valores (`0`, `1`) ya han desaparecido para cuando `list()` se ejecuta — un generador solo produce cada valor una vez, y no hay forma de "rebobinarlo."
