Python tiene cuatro tipos de contenedor incorporados en el propio lenguaje, sin necesidad de import, y elegir el correcto es sobre todo una cuestión de si el orden importa, si el contenido necesita cambiar, y si estás buscando cosas por posición o por nombre.

Una **lista** es una secuencia ordenada y mutable — la elección por defecto cuando tienes una colección de cosas que podría crecer, encogerse, o reordenarse.

```python
numbers = [3, 1, 4, 1, 5, 9]
numbers.append(2)
numbers.sort()
print(numbers)  # [1, 1, 2, 3, 4, 5, 9]
```

Una **tupla** se parece a una lista pero es inmutable — una vez creada, no se le pueden añadir elementos ni reasignar uno. Esa inmutabilidad hace que las tuplas puedan usarse como claves de dict (las listas no pueden) y señala intención: una tupla dice "este es un grupo fijo y pequeño de valores," como coordenadas.

```python
point = (10, 20)  # tuples are immutable
x, y = point       # unpacking works the same as with lists
print(x, y)  # 10 20
```

Un **dict** almacena pares clave-valor y busca valores por clave en vez de por posición, lo cual lo hace la elección natural para cualquier cosa que de otro modo describirías como "un registro con campos con nombre."

```python
user = {"name": "Rae", "age": 29}
user["email"] = "rae@example.com"
for key, value in user.items():
    print(key, value)
```

Un **set** almacena valores únicos y sin orden y descarta automáticamente los duplicados al insertar — útil para pruebas de pertenencia (`x in my_set` es rápido) y para deduplicar una colección.

```python
unique_ids = {1, 2, 2, 3, 3, 3}
print(unique_ids)  # {1, 2, 3}
```

Lo único que hay que internalizar sobre las listas (y los dicts, y los sets) es que son *objetos* mutables — una variable que contiene una de ellas no contiene una copia de su contenido, contiene una referencia a la misma lista subyacente a la que también apunta cualquier otra persona que tenga esa variable.
