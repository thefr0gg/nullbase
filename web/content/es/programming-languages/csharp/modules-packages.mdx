C# organiza el código con **espacios de nombres** (una agrupación lógica, independiente de la disposición de los archivos) y gestiona las dependencias externas con paquetes de **NuGet** declarados en el archivo `.csproj` de un proyecto. A diferencia de algunos lenguajes, un espacio de nombres en C# no tiene que coincidir con la estructura de carpetas en disco, aunque la mayoría de los proyectos las mantienen alineadas por convención.

## Espacios de nombres y using

Un espacio de nombres agrupa tipos relacionados y evita colisiones de nombres entre bibliotecas que casualmente definen un tipo con el mismo nombre:

```csharp
namespace Nullbase.Payments
{
    public class Invoice
    {
        public decimal Amount { get; set; }
    }
}

namespace Nullbase.App
{
    using Nullbase.Payments; // brings Invoice into scope unqualified

    class Program
    {
        static void Main()
        {
            var invoice = new Invoice { Amount = 42.50m };
            Console.WriteLine(invoice.Amount);
        }
    }
}
```

Sin la directiva `using Nullbase.Payments;`, `Invoice` tendría que escribirse completo como `Nullbase.Payments.Invoice` en cada lugar donde se use.

El C# moderno (10+) también soporta **espacios de nombres con ámbito de archivo**, que evitan un nivel extra de sangría para el caso común de un espacio de nombres por archivo:

```csharp
namespace Nullbase.Payments; // applies to the rest of the file — no braces

public class Invoice
{
    public decimal Amount { get; set; }
}
```

## Usings globales

Un proyecto puede declarar directivas `using` una sola vez, para todo el proyecto, en lugar de repetirlas en cada archivo — útil para espacios de nombres como `System` que casi todo archivo necesita:

```csharp
// GlobalUsings.cs
global using System;
global using System.Collections.Generic;
global using System.Linq;
```

## .csproj y NuGet

Todo proyecto en C# se describe mediante un archivo XML `.csproj`: el framework de destino, los archivos fuente (incluidos implícitamente por carpeta en el formato de estilo SDK), y las referencias de paquetes. NuGet es el gestor de paquetes y el registro público de .NET, jugando el mismo papel que `npm` juega para Node.js:

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net8.0</TargetFramework>
    <Nullable>enable</Nullable>
  </PropertyGroup>

  <ItemGroup>
    <PackageReference Include="Newtonsoft.Json" Version="13.0.3" />
  </ItemGroup>

</Project>
```

Agregar una dependencia usualmente se hace desde la línea de comandos en lugar de editar el XML a mano:

```bash
dotnet add package Newtonsoft.Json
dotnet restore
dotnet build
dotnet run
```

`dotnet add package` escribe la entrada `<PackageReference>` en el `.csproj` y `dotnet restore` descarga el paquete (y sus dependencias transitivas) en una caché local de NuGet, de forma similar a como `npm install` puebla `node_modules` a partir de `package.json`.
