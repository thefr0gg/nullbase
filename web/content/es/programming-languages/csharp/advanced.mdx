La característica de concurrencia distintiva de C# es `async`/`await` construida sobre
`Task` y `Task<T>` — operaciones asíncronas que representan "un valor que
estará disponible más adelante" (de forma muy similar a una `Promise` de JavaScript, aunque `Task`
es anterior al uso generalizado de ese patrón y está respaldada por el thread
pool de .NET en lugar de un bucle de eventos de un solo hilo).

## Task y Task\<T\>

Un `Task` representa una operación en curso sin resultado; `Task<T>` representa
una que eventualmente producirá un valor de tipo `T`:

```csharp
using System.Threading;
using System.Threading.Tasks;

Task<int> task = Task.Run(() =>
{
    Thread.Sleep(1000); // simulate slow work
    return 42;
});

Console.WriteLine("Started, doing other work...");
int result = task.Result; // blocks until the task completes
Console.WriteLine(result); // 42
```

Bloquear en `.Result` anula buena parte del propósito de la asincronía — el código
asíncrono real usa `await` en su lugar, lo cual suspende el método actual sin
bloquear el hilo subyacente.

## async / await

Marcar un método como `async` le permite usar `await` para suspenderse hasta que un `Task`
se complete, sin bloquear el hilo llamador. Un método `async` en sí mismo
devuelve un `Task` (o `Task<T>`), así que los llamadores pueden hacerle `await` a su vez:

```csharp
using System.Net.Http;
using System.Threading.Tasks;

async Task<string> FetchGreetingAsync()
{
    await Task.Delay(500); // simulates an I/O-bound wait, non-blocking
    return "Hello from the async world";
}

async Task RunAsync()
{
    Console.WriteLine("Before await");
    string greeting = await FetchGreetingAsync();
    Console.WriteLine(greeting);
    Console.WriteLine("After await");
}

await RunAsync();
```

El método no bloquea un hilo mientras espera a `Task.Delay` — el control
regresa al llamador, y el resto de `FetchGreetingAsync` se reanuda en un
hilo del thread pool una vez que termina el retraso. Por esto `async`/`await` es
el idioma preferido para trabajo limitado por E/S (llamadas de red, acceso a archivos, consultas
a bases de datos): los hilos no se desperdician esperando ociosos por E/S.

## Ejecutar tareas concurrentemente

Esperar tareas de una en una las ejecuta secuencialmente. `Task.WhenAll` inicia
varias tareas y las espera todas juntas, ejecutando el trabajo independiente
de forma concurrente:

```csharp
async Task<int> FetchLengthAsync(string url)
{
    await Task.Delay(300); // stands in for an HTTP call
    return url.Length;
}

async Task RunAllAsync()
{
    Task<int> t1 = FetchLengthAsync("https://a.example");
    Task<int> t2 = FetchLengthAsync("https://b.example");
    Task<int> t3 = FetchLengthAsync("https://c.example");

    int[] lengths = await Task.WhenAll(t1, t2, t3);
    Console.WriteLine(string.Join(", ", lengths));
}

await RunAllAsync();
```

Como `t1`, `t2`, y `t3` se inician todos antes de cualquier `await`, sus
llamadas a `Task.Delay(300)` se solapan — el método completo toma aproximadamente 300ms en total,
no 900ms, a diferencia de esperar a cada una inmediatamente después de iniciarla.
