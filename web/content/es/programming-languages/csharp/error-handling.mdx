C# usa excepciones para el manejo de errores en lugar de valores de retorno de error. Cualquier cosa, desde un índice de array inválido hasta una llamada de red fallida, lanza un objeto derivado de `System.Exception`, y el código más arriba en la pila de llamadas puede capturarlo.

## try / catch / finally

```csharp
try
{
    int[] numbers = { 1, 2, 3 };
    Console.WriteLine(numbers[10]); // throws IndexOutOfRangeException
}
catch (IndexOutOfRangeException ex)
{
    Console.WriteLine($"Caught: {ex.Message}");
}
finally
{
    Console.WriteLine("This always runs, exception or not.");
}
```

`finally` se ejecuta tanto si se lanzó una excepción como si no, e incluso si el bloque `try` o `catch` retorna antes de tiempo — es el lugar para limpieza como cerrar un archivo o una conexión.

Varios bloques `catch` te permiten manejar distintos tipos de excepción de forma diferente; se verifican de arriba a abajo, así que pon primero los tipos más específicos:

```csharp
try
{
    string input = "not a number";
    int value = int.Parse(input);
}
catch (FormatException ex)
{
    Console.WriteLine($"Bad format: {ex.Message}");
}
catch (Exception ex)
{
    Console.WriteLine($"Something else went wrong: {ex.Message}");
}
```

Un filtro de excepción (`when`) le permite a una sola cláusula `catch` activarse solo bajo condiciones adicionales, sin tragarse excepciones que no coinciden:

```csharp
try
{
    throw new InvalidOperationException("disk full");
}
catch (InvalidOperationException ex) when (ex.Message.Contains("disk"))
{
    Console.WriteLine("Handling a disk-related failure specifically.");
}
```

## Excepciones personalizadas

Derivar tu propio tipo de excepción de `Exception` (o de una clase base más específica) le permite al código llamador capturar precisamente el fallo que le importa, y te permite adjuntar datos específicos del dominio:

```csharp
class InsufficientFundsException : Exception
{
    public decimal Shortfall { get; }

    public InsufficientFundsException(decimal shortfall)
        : base($"Insufficient funds: short by {shortfall:C}")
    {
        Shortfall = shortfall;
    }
}

class Account
{
    public decimal Balance { get; private set; } = 100m;

    public void Withdraw(decimal amount)
    {
        if (amount > Balance)
        {
            throw new InsufficientFundsException(amount - Balance);
        }
        Balance -= amount;
    }
}

var account = new Account();
try
{
    account.Withdraw(150m);
}
catch (InsufficientFundsException ex)
{
    Console.WriteLine(ex.Message);      // Insufficient funds: short by $50.00
    Console.WriteLine(ex.Shortfall);    // 50
}
```

Las excepciones personalizadas siempre deberían llamar al constructor base (`: base(message)`) para que la propiedad estándar `.Message` y la maquinaria de la pila de llamadas sigan funcionando como se espera.
