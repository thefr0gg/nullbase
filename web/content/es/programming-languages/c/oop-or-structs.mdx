C es anterior a la programación orientada a objetos como idea popular, y no tiene `class`, ni herencia, ni una sintaxis de métodos incorporada. Lo que sí tiene es `struct` para agrupar datos relacionados, y el hecho de que las funciones son valores direccionables significa que puedes guardar un puntero a una función dentro de un struct — así es como las bases de código en C simulan "objetos con métodos" cuando lo necesitan. Es un sustituto deliberado y hecho a mano, no una característica oculta que indique que C fuera secretamente orientado a objetos todo el tiempo.

## struct: agrupar datos relacionados

Un `struct` agrupa campos con nombre, posiblemente de tipos distintos, en un solo tipo:

```c
#include <stdio.h>

struct Point {
    double x;
    double y;
};

double distanceFromOrigin(struct Point p) {
    /* passed by value: this receives a copy of the whole struct */
    double dx = p.x;
    double dy = p.y;
    return dx * dx + dy * dy; /* squared distance, skipping sqrt for brevity */
}

int main(void) {
    struct Point origin = {0.0, 0.0};
    struct Point p1 = {3.0, 4.0};

    printf("p1 = (%.1f, %.1f)\n", p1.x, p1.y);
    printf("squared distance: %.1f\n", distanceFromOrigin(p1));

    return 0;
}
```

Como cualquier otro valor, un `struct` se copia al asignarse y se pasa por valor a las funciones a menos que explícitamente pases un puntero al mismo — para un struct grande, pasar `struct Point *p` y usar `p->x` evita copiar todo el struct en cada llamada.

## typedef y punteros a función como "métodos"

`typedef` le da a un struct un alias más corto, y un campo de puntero a función le permite a un struct llevar comportamiento junto a sus datos — lo más parecido que C tiene a un método:

```c
#include <stdio.h>

typedef struct Account {
    double balance;
    void (*deposit)(struct Account *self, double amount);
} Account;

void depositImpl(Account *self, double amount) {
    self->balance += amount;
}

int main(void) {
    Account acc = {0.0, depositImpl};

    acc.deposit(&acc, 100.0); /* looks like a method call, but it's just a function pointer */
    acc.deposit(&acc, 50.0);

    printf("balance: %.2f\n", acc.balance);

    return 0;
}
```

`acc.deposit(&acc, 100.0)` se lee casi como lo haría `acc.deposit(100.0)` en un lenguaje orientado a objetos, salvo que C requiere que el objeto (`&acc`) se pase explícitamente como el primer argumento — no hay un `this` implícito. Bases de código reales en C usan exactamente este patrón (un struct de punteros a función actuando como una "vtable") para implementar interfaces y polimorfismo — el struct `file_operations` del kernel de Linux es un ejemplo bien conocido.

## Composición en lugar de herencia

C no tiene forma de decir "este struct extiende a aquel struct." En su lugar, un struct incorpora a otro como un campo con nombre, y el comportamiento compartido se expresa escribiendo funciones que operan sobre la pieza incorporada:

```c
#include <stdio.h>

typedef struct {
    double x;
    double y;
} Point;

typedef struct {
    Point position; /* composition: a Circle "has a" Point, not "is a" Point */
    double radius;
} Circle;

void printPoint(Point p) {
    printf("(%.1f, %.1f)", p.x, p.y);
}

int main(void) {
    Circle c = {{1.0, 2.0}, 5.0};

    printf("circle at ");
    printPoint(c.position); /* reuse the function written for Point */
    printf(" with radius %.1f\n", c.radius);

    return 0;
}
```

Como no hay herencia, la reutilización de código en C proviene de componer structs más pequeños y escribir funciones que operan sobre las piezas, en lugar de construir una jerarquía de clases — una restricción que empujó a estilos posteriores de "OOP sin clases" (como el embedding de Go) hacia la misma idea.
