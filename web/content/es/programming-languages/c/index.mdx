**C** fue creado por Dennis Ritchie en los Bell Labs a principios de la década de 1970, originalmente para reescribir el kernel de Unix en algo más portable que el ensamblador. Más de cincuenta años después, sigue siendo el lenguaje en el que están escritos la mayoría de los kernels de sistemas operativos, el firmware embebido, los runtimes de otros lenguajes (CPython, el núcleo de la JVM, Lua) y las librerías de bajo nivel (`libc`, SQLite, zlib). C compila directamente a código máquina, no tiene recolector de basura ni red de seguridad en tiempo de ejecución, y le da al programador un control casi total sobre el diseño de memoria y el comportamiento de la CPU — precisamente por eso es a la vez extremadamente rápido y extremadamente fácil de usar para dispararse en el pie.

Todo lo que este sitio cubre sobre C se deriva de una sola decisión de diseño: C confía completamente en el programador. No hay verificación de límites en los arrays, no hay gestión automática de memoria, y no hay excepciones — solo funciones, punteros, y una biblioteca estándar muy pequeña. Lenguajes modernos como Rust y Go existen en gran parte como reacciones a lo costosa que resulta esa confianza en la práctica, pero la franqueza de C es también la razón por la que sigue siendo la lingua franca en la que está implementado el runtime de casi cualquier otro lenguaje.

## Un programa mínimo en C

```c
#include <stdio.h>

int main(void) {
    printf("Hello, nullbase!\n");
    return 0;
}
```

`#include <stdio.h>` incorpora las declaraciones de funciones estándar de E/S como `printf`. `main` es el punto de entrada que todo programa en C debe tener; devolver `0` le indica al sistema operativo que el programa terminó con éxito (un valor distinto de cero señala un error a quien sea que lo haya invocado — un script de shell, una herramienta de compilación, etc.).

## Compilarlo y ejecutarlo

C se compila por adelantado, no se interpreta — no hay un runtime de C leyendo tu código fuente línea por línea. Un compilador (`gcc` o `clang`) traduce el código fuente a un ejecutable nativo *antes* de que se ejecute:

```c
#include <stdio.h>

int square(int n) {
    return n * n;
}

int main(void) {
    for (int i = 1; i <= 5; i++) {
        printf("%d squared is %d\n", i, square(i));
    }
    return 0;
}
```

Guardado como `squares.c`, esto se convierte en un binario ejecutable con:

```bash
gcc squares.c -o squares
./squares
```

No hay un paso de gestor de paquetes, ni un intérprete que invocar — `gcc` lee el archivo `.c`, resuelve los `#include`, y genera un ejecutable independiente. Esa separación entre compilar y ejecutar (en lugar de un JIT o un intérprete) es la razón por la que los programas en C arrancan instantáneamente, y por la que un bug como leer más allá del final de un array es un fallo en tiempo de ejecución, no un error de compilación que el compilador pudiera haber detectado.

## Lo que viene

El resto de esta sección recorre la sintaxis y variables de C, el flujo de control, las funciones, los arrays y strings, los structs (el sustituto de C para las clases), el manejo de errores por código de retorno, cómo se construyen los programas multi-archivo, y finalmente los punteros y la gestión manual de memoria — la parte de C que la mayoría de los demás lenguajes han eliminado deliberadamente.
