Java te ofrece dos niveles de contenedor: los **arrays** integrados, que
tienen un tamaño fijo una vez creados, y el **Collections Framework**
(`java.util`), cuyos tipos genéricos y redimensionables como `ArrayList` y
`HashMap` son a los que la mayoría del código cotidiano realmente recurre.

## Arrays

Un array contiene un número fijo de elementos de un único tipo, asignado por
adelantado:

```java
int[] scores = new int[3];
scores[0] = 70;
scores[1] = 85;
scores[2] = 92;

int[] literal = {70, 85, 92}; // literal de array, tamaño inferido

System.out.println(scores.length); // 3, un campo, no una llamada a método
```

Los arrays se indexan desde cero, y leer o escribir fuera de `[0, length)`
lanza `ArrayIndexOutOfBoundsException` en tiempo de ejecución en vez de
corromper la memoria silenciosamente. `length` es un campo `final` en el
objeto array, no un método — a diferencia de `String.length()` o
`List.size()`, que son métodos.

## ArrayList

`ArrayList<T>` es una lista redimensionable respaldada por un array, de
`java.util`. Como los genéricos de Java no pueden contener primitivos
directamente, `T` debe ser un tipo de referencia — usa la clase envoltorio
(`Integer`, no `int`) para tipos de elemento primitivos:

```java
import java.util.ArrayList;
import java.util.List;

List<String> names = new ArrayList<>();
names.add("Ada");
names.add("Linus");
names.add(1, "Grace"); // insertar en el índice 1, desplazando los elementos posteriores a la derecha

System.out.println(names);       // [Ada, Grace, Linus]
System.out.println(names.get(0)); // Ada
System.out.println(names.size()); // 3

names.remove("Linus");
System.out.println(names); // [Ada, Grace]
```

Declarar la variable como `List<String>` (la interfaz) en vez de
`ArrayList<String>` (la clase concreta) es idiomático — te permite
intercambiar más adelante una implementación de `List` distinta sin tocar
código que solo llama a métodos de la interfaz.

## HashMap

`HashMap<K, V>` almacena pares clave-valor con búsqueda, inserción, y
eliminación de O(1) en promedio, respaldado por una tabla hash. No garantiza
nada sobre el orden de iteración:

```java
import java.util.HashMap;
import java.util.Map;

Map<String, Integer> ages = new HashMap<>();
ages.put("Ada", 36);
ages.put("Linus", 54);

System.out.println(ages.get("Ada"));          // 36
System.out.println(ages.get("Grace"));         // null: la clave no existe
System.out.println(ages.getOrDefault("Grace", 0)); // 0: valor por defecto seguro
System.out.println(ages.containsKey("Linus")); // true

for (Map.Entry<String, Integer> entry : ages.entrySet()) {
    System.out.println(entry.getKey() + " is " + entry.getValue());
}
```

`get` sobre una clave ausente devuelve `null` en vez de lanzar una
excepción, lo cual es una fuente común de bugs de `NullPointerException` si
el resultado se usa sin una comprobación de null o `getOrDefault`. Si
necesitas un orden de iteración predecible, `LinkedHashMap` conserva el
orden de inserción y `TreeMap` mantiene las claves ordenadas.
