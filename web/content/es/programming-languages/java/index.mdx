Java fue lanzado por Sun Microsystems en 1995 (ahora mantenido por Oracle)
bajo el lema "write once, run anywhere" (escribe una vez, ejecuta en
cualquier lugar). El código fuente compila a **bytecode** independiente de la
plataforma, que se ejecuta en la Máquina Virtual de Java (JVM) en vez de
directamente sobre un sistema operativo concreto. El mismo archivo `.class`
se ejecuta sin modificaciones en Windows, Linux, o macOS siempre que haya
instalada una JVM compatible.

Java es de tipado estático, con recolección de basura, y profundamente
orientado a objetos: casi todo lo que escribes vive dentro de una clase. Ha
impulsado una enorme parte de los sistemas backend empresariales, las
aplicaciones Android (mediante una cadena de herramientas compatible con
Java), y los sistemas distribuidos a gran escala durante tres décadas, y su
ecosistema de librerías y herramientas maduras (Maven, Gradle, Spring) es uno
de los más grandes de la industria.

## Qué hace distintivo a Java

- **La JVM.** El código compila a bytecode, no a código máquina. El
  compilador just-in-time de la JVM luego convierte el bytecode "caliente"
  en instrucciones nativas en tiempo de ejecución, y el mismo bytecode se
  ejecuta sin modificaciones en cualquier plataforma con una JVM.
- **Todo es una clase (casi).** No hay funciones flotantes. Todo método vive
  dentro de una clase o interfaz, incluso el punto de entrada `main` de un
  programa.
- **Excepciones comprobadas (checked).** Java distingue las excepciones que
  el compilador te obliga a manejar o declarar (checked) de aquellas que no
  (unchecked) — una distinción que la mayoría de los otros lenguajes
  principales abandonó.
- **Herencia simple, múltiples interfaces.** Una clase extiende como máximo
  una superclase pero puede implementar cualquier número de interfaces,
  evitando el problema del diamante que crea la herencia múltiple completa.
- **Gestión automática de memoria.** Un recolector de basura generacional
  recupera los objetos inalcanzables; no hay `free` ni `delete` manual.
- **Fuerte compatibilidad hacia atrás.** El código escrito para Java 1.2 a
  finales de los años 90 en gran medida todavía compila hoy — una política
  de evolución del lenguaje deliberada y muy vigilada.

Aquí tienes un programa Java mínimo y completo:

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, nullbase!");
    }
}
```

El archivo debe llamarse `Main.java` para coincidir con el nombre de la
clase pública, y `main` debe tener exactamente esta firma — `public static
void main(String[] args)` — para que la JVM lo reconozca como el punto de
entrada.

## Cuándo recurrir a Java

Java es una opción por defecto sólida para sistemas backend grandes y de
larga vida donde el tamaño del equipo, la madurez de las herramientas, y la
mantenibilidad a largo plazo importan más que una latencia de arranque
mínima: servicios empresariales, aplicaciones Android, e infraestructura de
big data (Hadoop, Kafka, y Spark están todos escritos en Java o en su
hermano de la JVM, Scala). Se recurre a él con menos frecuencia cuando
quieres un único binario pequeño sin runtime que instalar, que es donde
lenguajes compilados como Go o Rust suelen ganar.
