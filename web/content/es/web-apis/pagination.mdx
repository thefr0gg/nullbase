Un endpoint de listado que devuelve todo de golpe no escala — una tabla con un millón de filas significaría una respuesta de un millón de filas para un cliente que solo necesita mostrar 20. La paginación divide una lista en páginas, devueltas una solicitud a la vez, con algún marcador que le indica al cliente cómo obtener la siguiente.

## Pruébalo

El endpoint simulado `/api/items` admite tanto paginación por offset (`page`/`limit`) como por cursor (`cursor`/`limit`) sobre la misma lista de 24 elementos — prueba los chips de abajo, o edita tú mismo la cadena de consulta.

La paginación por cursor y por keyset son efectivamente la misma idea (paginar por "después de este marcador" en lugar de "saltar N filas") — keyset simplemente usa el campo de ordenamiento real como marcador en lugar de un ID opaco, que es lo que hace que se mantenga rápido a gran escala: la base de datos puede saltar directamente a ese valor usando un índice en lugar de contar filas desde el principio.

## Dando forma a la respuesta

Sea cual sea la estrategia usada, la respuesta debería indicarle al cliente cómo obtener la siguiente página sin que tenga que adivinar — un `next_cursor` (o un enlace `next` completo, `_links.next`) junto con un booleano `has_more` es suficiente para que un cliente itere hasta quedarse sin páginas, sin adivinar errores de desplazamiento sobre si acaba de obtener la última.

```json
{ "data": [ /* ... */ ], "next_cursor": "42", "has_more": true }
```
