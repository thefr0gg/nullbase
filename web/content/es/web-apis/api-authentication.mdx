La autenticación responde una sola pregunta: **¿quién está haciendo esta solicitud?** (No qué se le permite hacer una vez identificado — eso es [Autorización de API](/es/web-apis/api-authorization).) Casi todos los esquemas de abajo se reducen a "adjunta una credencial a la solicitud, en cada solicitud, ya que las APIs no tienen estado" — mira la restricción de ausencia de estado de [REST](/es/web-apis/rest) para entender por qué no se recuerda nada entre llamadas.

## Pruébalo

## Tokens Bearer y JWTs

Un **JWT** (JSON Web Token) es la forma más común que adopta un token Bearer: tres segmentos en base64url — un header, un payload (claims como el ID del usuario y una hora de expiración), y una firma — unidos por puntos. El servidor verifica la firma para confiar en los claims sin necesitar una consulta a la base de datos en cada solicitud, razón por la cual los JWT son populares específicamente para APIs sin estado.

```
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiI0MiIsImV4cCI6MTcwMDAwMDAwMH0.4f8s...
       header                    payload                  signature
```
