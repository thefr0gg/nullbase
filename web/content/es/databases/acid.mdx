ACID es el conjunto de cuatro garantías que se supone que debe proveer una [transacción](/es/databases/transactions) correctamente implementada. Es una lista de comprobación de lo que "seguro" realmente significa para una escritura en una base de datos — cada letra cubre una forma específica en que una implementación ingenua podría, de otro modo, corromper o perder datos.

## Niveles de aislamiento: una garantía deliberadamente ajustable

El aislamiento total (cada transacción comportándose como si se ejecutara completamente sola) es costoso de implementar — los motores ofrecen niveles de aislamiento más débiles y rápidos como un compromiso explícito, y elegir uno es una decisión de ingeniería real, no solo una distinción académica.

## No toda base de datos elige ACID completo

Algunas bases de datos (particularmente muchos almacenes [NoSQL](/es/databases/nosql)) relajan deliberadamente una o más de estas garantías — normalmente consistencia o aislamiento — a cambio de disponibilidad o rendimiento a través de muchas máquinas. Esto no es un defecto; es un compromiso legítimo para cargas de trabajo donde la consistencia eventual es aceptable y el costo de coordinación de ACID completo a través de un sistema distribuido no vale la pena pagar.
