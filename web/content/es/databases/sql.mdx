SQL (Structured Query Language) describe **qué** datos quieres, no **cómo** obtenerlos — escribes `SELECT name FROM users WHERE age > 18`, y el motor de base de datos decide por sí mismo la estrategia real de recuperación (un escaneo completo, una búsqueda por índice, un orden de join). Esta es la diferencia definitoria frente al código imperativo: no hay ningún bucle que escribir, ningún puntero que recorrer — declaras la forma del resultado que quieres.

El playground de abajo es real: es SQLite compilado a WebAssembly, ejecutándose por completo en tu navegador. Cada consulta se ejecuta de verdad contra una base de datos en memoria real y pequeña.

Prueba a cambiar el umbral de `WHERE`, quitar el `JOIN`, o ejecutar `SELECT department_id, AVG(salary) FROM employees GROUP BY department_id;` para ver una agregación.

## Orden de escritura vs. orden de ejecución

Las cláusulas de SQL se *escriben* en un orden pero se *ejecutan* en otro distinto — este desajuste es una fuente común de confusión, especialmente en torno a por qué no puedes referenciar una columna con alias de `SELECT` en su propia cláusula `WHERE`.

Esto es exactamente por qué `WHERE` no puede filtrar sobre un agregado (`WHERE COUNT(*) > 5` no es válido — usa `HAVING`) — `WHERE` se ejecuta antes de que ocurra siquiera el agrupamiento, así que todavía no existe ningún valor agregado sobre el que filtrar.

## Joins, brevemente

Un `JOIN` combina filas de dos tablas basándose en una condición de coincidencia. `INNER JOIN` (el `JOIN` por defecto) conserva solo las filas que tienen coincidencia en ambos lados; `LEFT JOIN` conserva cada fila de la tabla izquierda sin importar si existe una coincidencia, rellenando las columnas sin coincidencia con `NULL` — prueba a cambiar `JOIN` por `LEFT JOIN` en el playground de arriba y añadir un empleado sin `department_id` para ver la diferencia.

## SQL no está totalmente estandarizado

ANSI SQL define un núcleo común, pero cada motor real añade sus propias extensiones y diverge en casos límite — ver [PostgreSQL](/es/databases/postgresql) y [MySQL](/es/databases/mysql) para sintaxis específica de cada motor que no necesariamente funciona en los demás.
