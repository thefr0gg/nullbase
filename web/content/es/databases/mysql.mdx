MySQL es una base de datos relacional cliente-servidor, como [PostgreSQL](/es/databases/postgresql) — ambas son las dos opciones de código abierto dominantes y se comparan constantemente, pero divergieron a partir de prioridades de diseño distintas: MySQL priorizó la velocidad de lectura pura y la simplicidad para el caso común de una app web (impulsó la "M" del clásico stack LAMP — Linux, Apache, MySQL, PHP), mientras que Postgres priorizó primero el cumplimiento de estándares y la corrección.

## Pruébalo (SQL estándar, ejecutándose en el motor del navegador)

Esa consulta usa `ON CONFLICT ... DO UPDATE` (la sintaxis estándar de "upsert" de SQLite y Postgres) ya que eso es lo que realmente soporta el motor del navegador — el equivalente de MySQL, mostrado abajo, no es ejecutable aquí pero hace lo mismo.

## Qué es realmente específico de MySQL

```sql
-- AUTO_INCREMENT: MySQL's spelling of an auto-incrementing primary key
CREATE TABLE users (id INT AUTO_INCREMENT PRIMARY KEY, email VARCHAR(255) UNIQUE);

-- MySQL's own upsert syntax
INSERT INTO page_views (path, views) VALUES ('/home', 1)
ON DUPLICATE KEY UPDATE views = views + 1;

-- Storage engine selection, per table
CREATE TABLE logs (id INT PRIMARY KEY, message TEXT) ENGINE=InnoDB;

-- LIMIT with an offset, comma form (also valid in Postgres, not standard SQL)
SELECT * FROM users LIMIT 10, 20; -- skip 10, take 20
```

Ambas son opciones excelentes y probadas en producción para la abrumadora mayoría de las cargas de trabajo relacionales — la decisión real suele reducirse a la familiaridad del equipo, el soporte del proveedor de hosting, y si una función específica (las extensiones de Postgres, la historia de replicación más simple de MySQL) es un factor decisivo para el proyecto en cuestión, más que cualquiera de las dos bases de datos siendo categóricamente "mejor".
