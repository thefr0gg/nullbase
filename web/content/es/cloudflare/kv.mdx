**Workers KV** almacena pares clave-valor simples, replicados a las ubicaciones de borde de Cloudflare en todo el mundo, de modo que una lectura desde cualquier lugar sea rápida y local — la contrapartida explícita es que una escritura no es visible en todas partes inmediatamente, a diferencia de una base de datos tradicional de una sola región.

## Uso básico

```js
export default {
  async fetch(request, env) {
    await env.MY_KV.put("theme:user-42", "dark");
    const theme = await env.MY_KV.get("theme:user-42");
    return new Response(theme);
  },
};
```

`env.MY_KV` es un [binding](/es/cloudflare/workers-bindings) a un namespace de KV específico; `put`/`get`/`delete`/`list` son toda la API central — deliberadamente mínima comparada con el lenguaje de consulta de una base de datos relacional, ya que KV no pretende soportar consultas relacionales en absoluto.

## Consistencia eventual, en concreto

Un `put()` desde una ubicación de borde puede tardar hasta unos 60 segundos aproximadamente en propagarse a cada otra ubicación a nivel global — una lectura de esa misma clave desde una ubicación *distinta* poco después de la escritura puede seguir devolviendo el valor antiguo (o ningún valor, si es una clave nueva). Esto no es un error; es el mecanismo que hace que las lecturas de KV sean rápidas en todas partes sin que cada lectura necesite comprobar primero una única fuente autoritativa. Las cargas de trabajo que necesitan que cada lector vea una escritura de inmediato, en todas partes, encajan mal con KV precisamente por esto.
