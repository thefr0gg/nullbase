Escribir lógica de aplicación correcta es solo parte del trabajo — esta sección cubre las herramientas que lo rodean: rastrear los cambios al código a lo largo del tiempo, incorporar y gestionar dependencias, y las comprobaciones automatizadas (linting, formateo, testing, depuración) que detectan errores antes de que lleguen a producción.

## Control de versiones

- **[Git](/es/developer-tools/git)** — el sistema de control de versiones distribuido que casi todo el mundo usa.
- **[GitHub](/es/developer-tools/github)** — el lugar más usado para alojar repositorios Git y colaborar en torno a ellos.
- **[GitLab](/es/developer-tools/gitlab)** — la principal alternativa a GitHub, con una plataforma de CI/CD integrada.

## Dependencias

- **[npm](/es/developer-tools/npm)** — el gestor de paquetes y registro por defecto de JavaScript.
- **[Gestores de paquetes](/es/developer-tools/package-managers)** — el patrón general del que npm es una implementación.
- **[Versionado semántico](/es/developer-tools/semantic-versioning)** — la convención de números de versión que hace posible las actualizaciones automatizadas de dependencias.

## Calidad del código

- **[Linters](/es/developer-tools/linters)** — detectar posibles errores y problemas de estilo sin ejecutar el código.
- **[Formateadores](/es/developer-tools/formatters)** — acabar con las discusiones sobre el estilo del código automatizándolo por completo.
- **[Testing](/es/developer-tools/testing)** — verificar que el código se comporta correctamente, de forma automática, en cada cambio.

## Descubrir qué está pasando realmente

- **[Depuración](/es/developer-tools/debugging)** — averiguar por qué el código no hace lo que se supone que debe hacer.
- **[Profiling](/es/developer-tools/profiling)** — averiguar por qué el código es más lento de lo que debería ser.
