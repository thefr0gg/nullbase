El **testing automatizado** ejecuta código contra entradas conocidas y comprueba que la salida coincide con lo esperado, sin que un humano tenga que ir haciendo clic manualmente por la aplicación cada vez. El valor se acumula a lo largo de la vida de un proyecto: un test escrito una vez sigue comprobando ese comportamiento en cada cambio futuro, detectando regresiones que un revisor humano no tendría motivo para notar.

La forma de «pirámide» es una recomendación, no una ley: muchos tests unitarios rápidos en la base, menos tests de integración, y solo un pequeño número de costosos tests E2E en la cima — porque una suite de tests que es mayoritariamente tests E2E lentos tarda demasiado en ejecutarse en cada cambio como para realmente ejecutarse en cada cambio, anulando el propósito.

## Mocking

Un **mock** sustituye una dependencia real (una base de datos, una API de terceros, la hora actual) por un sustituto falso y controlable — permitiendo que un test unitario aísle exactamente la lógica que se está probando sin depender de que una base de datos real esté disponible, de que una API real no limite la tasa de la ejecución del test, o de que el resultado de un test cambie según qué día se ejecute. Abusar de los mocks también tiene un coste real: un test que simula tanto que ya no se parece a cómo se comporta el código de verdad puede pasar mientras la integración real está rota — un equilibrio que cada equipo tiene que buscar deliberadamente en lugar de simularlo todo por defecto.

## Tests inestables (flaky)

Un **test inestable (flaky)** pasa y falla de forma inconsistente sin que haya habido ningún cambio de código entre medio — normalmente causado por una condición de carrera, una dependencia de los tiempos, o un estado compartido/remanente entre ejecuciones de tests. Los tests inestables son peores que no tener ningún test en un sentido concreto: entrenan a un equipo para volver a ejecutar los fallos y asumir que son espurios, lo que eventualmente hace que un test genuinamente roto (o un código genuinamente roto) se descarte de la misma manera.
