Un `<form>` HTML no envía sus campos como [JSON](/es/data-serialization/json) por defecto — usa una de dos codificaciones más antiguas, elegida mediante el atributo `enctype` del formulario, que son anteriores a JSON como formato web.

## Pruébalo

`/api/form-submit` en la API simulada de este sitio analiza cualquier codificación que realmente envíes — prueba el ejemplo urlencoded, y luego cambia la cabecera `Content-Type` y el cuerpo a JSON y envíalo de nuevo.

`application/x-www-form-urlencoded` es la opción por defecto y es lo que envía el ejemplo anterior — es compacto pero no puede transportar datos binarios en absoluto, ya que todo tiene que ser texto codificado con porcentajes (ver [Codificación de URL](/es/data-serialization/url-encoding)). Un formulario con `<input type="file">` tiene que usar en su lugar `multipart/form-data`, razón por la cual los formularios de subida de archivos siempre necesitan tener `enctype="multipart/form-data"` fijado explícitamente.

```http
POST /upload HTTP/1.1
Content-Type: multipart/form-data; boundary=----abc123

------abc123
Content-Disposition: form-data; name="username"

grace
------abc123
Content-Disposition: form-data; name="avatar"; filename="photo.png"
Content-Type: image/png

<binary bytes>
------abc123--
```

## FormData en JavaScript

El objeto `FormData` del navegador construye cualquiera de las dos codificaciones por ti al enviarlo mediante `fetch` — en código moderno nunca construyes a mano la cadena de límite (boundary) ni la codificación de porcentajes:

```js
const form = new FormData();
form.append("username", "grace");
form.append("avatar", fileInput.files[0]);
fetch("/upload", { method: "POST", body: form }); // browser sets Content-Type + boundary automatically
```

## Ver también

- **[Codificación de URL](/es/data-serialization/url-encoding)** — el esquema de codificación de porcentajes que usan los valores de `application/x-www-form-urlencoded`.
- **[JSON](/es/data-serialization/json)** — el formato que la mayoría de las APIs modernas prefieren sobre cualquiera de las dos codificaciones de formulario, para envíos sin archivos.
