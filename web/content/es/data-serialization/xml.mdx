XML (eXtensible Markup Language) representa datos estructurados como etiquetas anidadas y nombradas — más cercano en forma a [HTML](/es/web-platform/html) que a [JSON](/es/data-serialization/json), ya que usa la misma sintaxis de marcado. Antes de que JSON se convirtiera en el formato por defecto, XML era el formato estándar de intercambio de datos para APIs web (SOAP, RSS, primeras APIs con estilo REST); hoy sobrevive principalmente en sistemas empresariales, formatos de documentos y configuración.

```xml
<user id="42">
  <name>Grace Hopper</name>
  <active>true</active>
  <roles>
    <role>admin</role>
    <role>editor</role>
  </roles>
</user>
```

## Atributos vs. elementos

Los mismos datos se pueden expresar de dos formas distintas en XML, lo cual es una fuente real de ambigüedad que JSON no tiene:

```xml
<user id="42" name="Grace Hopper" />
<!-- vs. -->
<user>
  <id>42</id>
  <name>Grace Hopper</name>
</user>
```

Ninguna es "más correcta" — las convenciones varían según el proyecto, lo cual es en sí mismo una crítica habitual hacia XML en comparación con la única forma obvia que tiene JSON de escribir un par clave-valor.

## Dónde sigue siendo el estándar

XML sigue siendo el estándar real, no un remanente heredado, en varios lugares: servicios web SOAP (comunes en integraciones empresariales, financieras y de salud), los formatos de archivo de Microsoft Office y OpenDocument (un `.docx` es un zip de archivos XML), los feeds RSS/Atom, y SVG (que es XML, no un formato de imagen separado).
