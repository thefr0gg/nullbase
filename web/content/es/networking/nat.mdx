**NAT (Network Address Translation)** reescribe la dirección de origen de los paquetes salientes, cambiándola de una dirección [IPv4](/es/networking/ipv4) privada a la dirección pública de un router, y la vuelve a reescribir en el camino de vuelta. Es la razón por la que una red doméstica con una docena de dispositivos de rango privado solo necesita nunca una única IP pública — e históricamente, una de las mayores razones por las que el agotamiento de direcciones IPv4 no se convirtió en una crisis décadas antes.

## Cómo PAT distingue realmente a los dispositivos

Como cada dispositivo comparte la única IP pública del router, este tiene que distinguir las respuestas de alguna otra forma — lo hace reescribiendo también el **puerto de origen**, y manteniendo una tabla de traducción:

```text
Private side                Public side
192.168.1.10:51000   <-->   203.0.113.5:40001
192.168.1.11:51000   <-->   203.0.113.5:40002
```

Dos dispositivos internos pueden usar el mismo puerto privado (`51000`) al mismo tiempo, porque el router mapea cada uno a un puerto público distinto. Una respuesta que llega a `203.0.113.5:40002` se traduce de vuelta a `192.168.1.11:51000` buscando esa entrada en la tabla — exactamente la misma idea de emparejamiento `(IP, puerto)` que hay detrás de un [socket](/es/web-fundamentals/ports-sockets).

## Qué rompe NAT

Como un host externo solo ve nunca la dirección pública del router, no puede iniciar una conexión *hacia* un dispositivo con NAT a menos que el router esté configurado explícitamente para reenviar un puerto hasta él. Esto es, por accidente, una forma de cortafuegos — pero también es por lo que los protocolos punto a punto (VoIP, algunos juegos multijugador) necesitan técnicas adicionales (STUN, TURN, hole punching) solo para establecer una conexión directa a través de NAT.
