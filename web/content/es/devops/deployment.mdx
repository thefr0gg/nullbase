El **despliegue** es el acto de reemplazar la versión antigua de una aplicación en ejecución por una nueva. Hecho de forma ingenua — parar la versión antigua, arrancar la nueva — esto provoca un hueco visible en el que el servicio queda completamente caído; la mayoría de las estrategias de despliegue reales existen específicamente para evitar ese hueco, o para limitar el radio de impacto si la nueva versión resulta estar rota.

## Rollbacks

Por muy cuidadoso que sea el rollout, una nueva versión puede resultar estar rota de una forma que solo se manifiesta bajo tráfico real de producción. Un **rollback** rápido y fiable — volver a la última versión conocida como buena — importa tanto como el propio mecanismo de despliegue; los despliegues blue-green hacen que esto sea lo más parecido a instantáneo (devolver el tráfico al entorno que nunca se tocó), mientras que el rollback de un despliegue rolling es en sí mismo otro despliegue rolling, solo que a la inversa.

## Las migraciones de base de datos complican todo esto

El código normalmente puede desplegarse y revertirse con libertad, pero un cambio de esquema de base de datos a menudo no puede revertirse de forma tan limpia — eliminar una columna que el código nuevo necesita rompe el código nuevo, pero un rollback al código antiguo después de que la columna ya se haya eliminado también rompe el código antiguo. Por eso los cambios de esquema normalmente se hacen en pasos retrocompatibles (añadir una columna nueva sin eliminar todavía la antigua, desplegar código que pueda manejar ambas, eliminar la columna antigua solo en un despliegue posterior y separado) en lugar de como un único cambio atómico junto con el código que la usa.

## Feature flags

Un **feature flag** desacopla desplegar código de activar realmente una funcionalidad — el código nuevo se envía a producción detrás de un flag que está desactivado por defecto, y se activa para un subconjunto de usuarios (o para todos) con independencia de cualquier despliegue posterior. Esto permite activar gradualmente una funcionalidad arriesgada, o desactivarla al instante si algo sale mal, sin necesitar un redespliegue o rollback completo en ninguna de las dos direcciones.
