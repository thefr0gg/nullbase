Casi todos los servidores de internet — VMs en la nube, contenedores, las máquinas detrás de la mayoría de los backends — ejecutan alguna distribución de Linux. No porque Linux sea obligatorio, sino porque es gratuito, estable, bien conocido, y tiene décadas de herramientas construidas precisamente en torno a este caso de uso. Saber moverse por un shell de Linux es casi un requisito previo para el trabajo de backend y DevOps en general.

## Permisos

Todo archivo tiene un propietario, un grupo, y tres conjuntos de permisos (propietario/grupo/otros), cada uno con bits de lectura, escritura y ejecución — mostrados por `ls -l` como una cadena tipo `-rwxr-xr--`. `chmod 755 script.sh` establece el propietario en lectura/escritura/ejecución (7), el grupo y los demás en lectura/ejecución (5 cada uno) — la forma numérica es solo esos tres bits de permisos leídos como dígitos octales. Un script que no sea ejecutable (`chmod +x`) se negará a ejecutarse directamente aunque su contenido sea perfectamente válido.

## Comandos que merece la pena saberse de memoria

```bash
ls -la          # list files, including hidden ones, with details
cd /var/log      # change directory
pwd              # print working directory
cat file.txt     # print a file's contents
grep -r "TODO" . # search recursively for a pattern
ps aux           # list running processes
kill -9 1234     # forcibly terminate process 1234
chmod +x run.sh  # make a file executable
tail -f app.log  # follow a log file as it grows
```

`tail -f` en particular es una herramienta diaria para cualquiera que opere un servicio — observar cómo se actualiza un archivo de log en tiempo real mientras un servidor gestiona solicitudes.
