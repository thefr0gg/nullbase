Antes de que un navegador pueda enviar una sola solicitud HTTP, tienen que pasar muchas cosas: un nombre de dominio debe resolverse a una dirección IP, una conexión debe abrirse, y — para cualquier cosa en la web moderna — esa conexión debe cifrarse. Esta sección cubre las capas por debajo de HTTP, y la infraestructura que atraviesa la mayor parte del tráfico real en el camino.

## Empieza aquí

- **[HTTP](/es/web-fundamentals/http)** — el protocolo sobre el que está construida la mayor parte de la web.
- **[URL y URI](/es/web-fundamentals/urls)** — la anatomía de una URL y qué hace cada parte.
- **[DNS](/es/web-fundamentals/dns)** — cómo un nombre de host se convierte en una dirección IP.
- **[TLS y HTTPS](/es/web-fundamentals/tls)** — cómo se cifra una conexión antes de que HTTP fluya sobre ella.

## Redes

- **[TCP/IP](/es/web-fundamentals/tcp-ip)** — el modelo por capas sobre el que se sustenta cada conexión a Internet.
- **[Puertos y sockets](/es/web-fundamentals/ports-sockets)** — cómo una sola dirección IP sirve a cientos de aplicaciones a la vez.

## Infraestructura

- **[Proxies](/es/web-fundamentals/proxies)** — Forward Proxy frente a Reverse Proxy, y cómo un Reverse Proxy enruta una solicitud.
- **[CDN](/es/web-fundamentals/cdns)** — servir contenido desde servidores cercanos al usuario en lugar de un único origen lejano.
