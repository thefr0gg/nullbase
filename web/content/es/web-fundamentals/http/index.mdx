El **protocolo de transferencia de hipertexto (HTTP)** es la base de la comunicación web. Cada solicitud de tu navegador, cada llamada a una API, cada interacción con un servidor pasa por HTTP.

Esta referencia enseña HTTP no a través de datos aislados, sino a través de **herramientas interactivas** — compón solicitudes reales, explora códigos de estado, inspecciona encabezados, y entiende por qué HTTP se comporta como lo hace.

## Conceptos fundamentales

### Métodos (verbos)
Cada solicitud usa un método. Estos son los más importantes:

- **[GET](/es/web-fundamentals/http/methods/get)** — Obtener un recurso.
- **[POST](/es/web-fundamentals/http/methods/post)** — Enviar datos, crear recursos, disparar acciones.
- **[PUT](/es/web-fundamentals/http/methods/put)** — Reemplazar o crear un recurso por completo.
- **[PATCH](/es/web-fundamentals/http/methods/patch)** — Actualizaciones parciales.
- **[DELETE](/es/web-fundamentals/http/methods/delete)** — Eliminar un recurso.
- **[HEAD](/es/web-fundamentals/http/methods/head)** — Como GET, pero solo encabezados (sin cuerpo).
- **[OPTIONS](/es/web-fundamentals/http/methods/options)** — Describir las opciones de comunicación para un recurso.
- **[Referencia de todos los métodos](/es/web-fundamentals/http/methods)** — Propiedades de seguridad, idempotencia, cacheabilidad.

### Códigos de estado
Cada respuesta comienza con un código. Domínalos todos:

- **[2xx Éxito](/es/web-fundamentals/http/status-codes/2xx)** — 200 OK, 201 Created, 204 No Content, etc.
- **[3xx Redirección](/es/web-fundamentals/http/status-codes/3xx)** — 301 Moved, 302 Found, 304 Not Modified, etc.
- **[4xx Error del cliente](/es/web-fundamentals/http/status-codes/4xx)** — 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, etc.
- **[5xx Error del servidor](/es/web-fundamentals/http/status-codes/5xx)** — 500 Internal Server Error, 502 Bad Gateway, 503 Service Unavailable, etc.

**[Explorador de códigos de estado en vivo](/es/web-fundamentals/http/status-codes)** — Descubre qué significa cada código y cuándo lo usan los servidores.

### Encabezados
Metadatos que controlan el comportamiento. Lo esencial:

**Encabezados de solicitud:**
- **[Authorization](/es/web-fundamentals/http/headers/authorization)** — Demostrar quién eres (Basic, Bearer, claves de API).
- **[Content-Type](/es/web-fundamentals/http/headers/content-type)** — Formato del cuerpo de la solicitud (application/json, form-data, etc.).
- **[Accept](/es/web-fundamentals/http/headers/accept)** — Qué formatos de respuesta puedes entender.
- **[User-Agent](/es/web-fundamentals/http/headers/user-agent)** — Identificar al cliente.

**Encabezados de respuesta:**
- **[Content-Type](/es/web-fundamentals/http/headers/content-type)** — Formato del cuerpo de la respuesta.
- **[Cache-Control](/es/web-fundamentals/http/headers/cache-control)** — Cuánto tiempo cachear esta respuesta.
- **[Set-Cookie](/es/web-fundamentals/http/headers/set-cookie)** — Almacenar datos en el cliente.
- **[Location](/es/web-fundamentals/http/headers/location)** — Dónde redirigir (respuestas 3xx).

**[Referencia de todos los encabezados](/es/web-fundamentals/http/headers)** — Más de 50 encabezados con ejemplos y casos de uso.

## Versiones del protocolo

Entender la evolución importa — las funcionalidades han cambiado, el rendimiento ha mejorado.

- **[HTTP/1.0](/es/web-fundamentals/http/http1-0)** — El original (1991). Sin estado, simple.
- **[HTTP/1.1](/es/web-fundamentals/http/http1-1)** — El estándar (1997–hoy). Keep-Alive, pipelining, cacheo.
- **[HTTP/2](/es/web-fundamentals/http/http2)** — Multiplexación y server push (2015). Más rápido con una sola conexión.
- **[HTTP/3](/es/web-fundamentals/http/http3)** — Basado en QUIC, aún más rápido (2022).
