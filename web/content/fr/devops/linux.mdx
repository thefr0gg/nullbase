Presque tous les serveurs sur internet — VMs cloud, conteneurs, les machines derrière la plupart des backends — font tourner une distribution Linux. Pas parce que Linux est requis, mais parce qu'il est gratuit, stable, bien compris, et dispose de décennies d'outillage construit exactement pour ce cas d'usage. Savoir se débrouiller dans un shell Linux est presque un prérequis pour le travail backend et DevOps en général.

## Permissions

Chaque fichier a un propriétaire, un groupe, et trois ensembles de permissions (propriétaire/groupe/autres), chacun avec des bits de lecture, écriture, et exécution — affichés par `ls -l` sous forme d'une chaîne comme `-rwxr-xr--`. `chmod 755 script.sh` définit le propriétaire en lecture/écriture/exécution (7), le groupe et les autres en lecture/exécution (5 chacun) — la forme numérique n'est que ces trois bits de permission lus comme des chiffres octaux. Un script qui n'est pas exécutable (`chmod +x`) refusera de s'exécuter directement même si son contenu est parfaitement valide.

## Commandes à connaître par cœur

```bash
ls -la          # list files, including hidden ones, with details
cd /var/log      # change directory
pwd              # print working directory
cat file.txt     # print a file's contents
grep -r "TODO" . # search recursively for a pattern
ps aux           # list running processes
kill -9 1234     # forcibly terminate process 1234
chmod +x run.sh  # make a file executable
tail -f app.log  # follow a log file as it grows
```

`tail -f` en particulier est un outil quotidien pour quiconque exploite un service — observer un fichier de log se mettre à jour en temps réel pendant qu'un serveur traite des requêtes.
