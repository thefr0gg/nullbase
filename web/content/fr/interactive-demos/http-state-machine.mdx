Un seul cycle requête/réponse n'est pas instantané — il traverse un petit nombre d'états distincts, et toutes les transitions ne sont pas disponibles depuis tous les états (impossible de passer directement d'« inactif » à « réception »). Cliquez sur une transition pour la déclencher, ou utilisez **Étape** pour suivre automatiquement la première disponible.

Cette même structure — un petit ensemble d'états, un ensemble fixe de transitions valides entre eux — décrit bien plus que HTTP : voir le cycle de vie de connexion [TCP](/en/networking/tcp), les états connexion/ouvert/fermeture/fermé d'un WebSocket, ou un flux d'autorisation OAuth.
