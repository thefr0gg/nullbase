Écrire une logique applicative correcte n'est qu'une partie du travail — cette section couvre l'outillage qui l'entoure : suivre les modifications du code dans le temps, récupérer et gérer les dépendances, et les vérifications automatisées (linting, formatage, tests, débogage) qui détectent les erreurs avant qu'elles ne partent en production.

## Contrôle de version

- **[Git](/fr/developer-tools/git)** — le système de contrôle de version distribué qu'utilise presque tout le monde.
- **[GitHub](/fr/developer-tools/github)** — l'endroit le plus utilisé pour héberger des dépôts Git et collaborer autour d'eux.
- **[GitLab](/fr/developer-tools/gitlab)** — la principale alternative à GitHub, avec une plateforme CI/CD intégrée.

## Dépendances

- **[npm](/fr/developer-tools/npm)** — le gestionnaire de paquets et le registre par défaut pour JavaScript.
- **[Gestionnaires de paquets](/fr/developer-tools/package-managers)** — le modèle général dont npm est une implémentation.
- **[Versionnage sémantique](/fr/developer-tools/semantic-versioning)** — la convention de numérotation des versions qui rend possibles les mises à jour automatisées des dépendances.

## Qualité du code

- **[Linters](/fr/developer-tools/linters)** — détecter les bugs probables et les problèmes de style sans exécuter le code.
- **[Formateurs](/fr/developer-tools/formatters)** — mettre fin aux discussions sur le style de code en l'automatisant entièrement.
- **[Tests](/fr/developer-tools/testing)** — vérifier que le code se comporte correctement, automatiquement, à chaque modification.

## Découvrir ce qui se passe réellement

- **[Débogage](/fr/developer-tools/debugging)** — comprendre pourquoi le code ne fait pas ce qu'il est censé faire.
- **[Profilage](/fr/developer-tools/profiling)** — comprendre pourquoi le code est plus lent qu'il ne devrait l'être.
