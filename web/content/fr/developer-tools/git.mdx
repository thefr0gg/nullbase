**Git** suit les modifications d'une base de code dans le temps sous forme d'une série de **commits** — chacun étant un instantané de l'ensemble du projet à ce moment-là, relié à son commit parent, formant un historique. Il est **distribué**, ce qui signifie que chaque clone d'un dépôt porte l'*intégralité* de l'historique, pas seulement un pointeur vers un serveur central — c'est pourquoi la plupart des opérations Git (consulter l'historique, créer une branche, committer) fonctionnent entièrement hors ligne.

## Les branches ne sont que des pointeurs

Une **branche** n'est rien de plus qu'un pointeur mobile vers un commit précis — en créer une (`git branch feature-x`) est instantané quelle que soit la taille du dépôt, car cela ne copie aucun fichier, ajoute simplement un nouveau pointeur. `git checkout feature-x` fait pointer votre répertoire de travail vers le commit que pointe actuellement ce pointeur ; committer alors qu'on est sur une branche fait avancer le pointeur de cette branche vers le nouveau commit.

## Fusion (merge) contre rebasage (rebase)

Le **merge** combine les historiques de deux branches en créant un nouveau commit avec deux parents, préservant exactement ce qui s'est passé et quand sur les deux branches. Le **rebase** réécrit les commits d'une branche pour qu'ils apparaissent comme s'ils avaient été faits par-dessus le dernier commit de l'autre branche, produisant un historique linéaire sans aucun commit de fusion — plus propre à lire, mais cela réécrit l'historique des commits, ce qui est risqué sur toute branche dont d'autres personnes ont déjà tiré (leur historique local divergerait alors de l'historique réécrit).

## L'utilité réelle de la zone d'index

Le fait que `git add` existe comme étape séparée de `git commit` semble redondant jusqu'au moment où on en a besoin : cela permet de construire un commit à partir de seulement *certaines* de vos modifications actuelles (`git add -p` permet même d'indexer une partie d'un seul fichier), gardant les commits centrés sur un seul changement logique plutôt que de regrouper toutes les modifications présentes sur le disque en un seul commit, qu'elles soient liées ou non.
