L'authentification répond à une seule question : **qui fait cette requête ?** (Pas ce qu'il a le droit de faire une fois identifié — c'est [l'Autorisation API](/fr/web-apis/api-authorization).) Presque tous les schémas ci-dessous se résument à « attacher un identifiant à la requête, à chaque requête, puisque les API sont sans état » — voir la contrainte d'absence d'état de [REST](/fr/web-apis/rest) pour comprendre pourquoi rien n'est mémorisé entre les appels.

## Tokens Bearer et JWT

Un **JWT** (JSON Web Token) est la forme la plus courante que prend un token Bearer : trois segments en base64url — un header, un payload (des claims comme l'ID de l'utilisateur et une date d'expiration), et une signature — joints par des points. Le serveur vérifie la signature pour faire confiance aux claims sans avoir besoin d'un lookup en base de données à chaque requête, ce qui explique pourquoi les JWT sont populaires spécifiquement pour les API sans état.

```
eyJhbGciOiJIUzI1NiJ9.eyJzdWIiOiI0MiIsImV4cCI6MTcwMDAwMDAwMH0.4f8s...
       header                    payload                  signature
```
