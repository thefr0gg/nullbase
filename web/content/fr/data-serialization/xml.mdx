XML (eXtensible Markup Language) représente des données structurées sous forme de balises nommées et imbriquées — plus proche dans sa forme du [HTML](/fr/web-platform/html) que du [JSON](/fr/data-serialization/json), puisqu'il utilise la même syntaxe de balisage. Avant que JSON ne devienne le standard par défaut, XML était le format d'échange de données standard pour les API web (SOAP, RSS, premières API de style REST) ; aujourd'hui il survit principalement dans les systèmes d'entreprise, les formats de document, et la configuration.

```xml
<user id="42">
  <name>Grace Hopper</name>
  <active>true</active>
  <roles>
    <role>admin</role>
    <role>editor</role>
  </roles>
</user>
```

## Attributs vs. éléments

La même donnée peut être exprimée de deux façons différentes en XML, ce qui constitue une véritable source d'ambiguïté que JSON n'a pas :

```xml
<user id="42" name="Grace Hopper" />
<!-- vs. -->
<user>
  <id>42</id>
  <name>Grace Hopper</name>
</user>
```

Aucune n'est « plus correcte » — les conventions varient selon les projets, ce qui est en soi une critique courante adressée à XML par rapport à la façon unique et évidente de JSON d'écrire une paire clé-valeur.

## Là où c'est toujours le standard

XML reste le standard réel, pas un simple vestige hérité, dans plusieurs domaines : les services web SOAP (courants dans les intégrations entreprise/finance/santé), les formats de fichier Microsoft Office et OpenDocument (un `.docx` est une archive zip de fichiers XML), les flux RSS/Atom, et le SVG (qui est du XML, pas un format d'image séparé).
