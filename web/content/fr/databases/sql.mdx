SQL (Structured Query Language) décrit **quelles** données vous voulez, pas **comment** les récupérer — vous écrivez `SELECT name FROM users WHERE age > 18`, et le moteur de base de données décide lui-même de la stratégie de récupération réelle (un balayage complet, une recherche par index, un ordre de jointure). C'est la différence fondamentale avec le code impératif : il n'y a aucune boucle à écrire, aucun pointeur à parcourir — vous déclarez la forme du résultat que vous voulez.

Le playground ci-dessous est réel : c'est SQLite compilé en WebAssembly, s'exécutant entièrement dans votre navigateur. Chaque requête s'exécute réellement contre une vraie petite base de données en mémoire.

## Ordre d'écriture vs. ordre d'exécution

Les clauses SQL sont *écrites* dans un ordre mais *exécutées* dans un ordre différent — cette discordance est une source fréquente de confusion, notamment sur la raison pour laquelle on ne peut pas référencer une colonne aliasée dans un `SELECT` depuis sa propre clause `WHERE`.

C'est exactement pourquoi `WHERE` ne peut pas filtrer sur un agrégat (`WHERE COUNT(*) > 5` est invalide — utilisez `HAVING`) — `WHERE` s'exécute avant même que le regroupement n'ait lieu, donc aucune valeur agrégée n'existe encore pour filtrer dessus.

## Les jointures, brièvement

Un `JOIN` combine des lignes de deux tables selon une condition de correspondance. `INNER JOIN` (le `JOIN` par défaut) ne conserve que les lignes ayant une correspondance des deux côtés ; `LEFT JOIN` conserve chaque ligne de la table de gauche, qu'une correspondance existe ou non, en remplissant les colonnes non appariées avec `NULL` — essayez de changer `JOIN` en `LEFT JOIN` dans le playground ci-dessus et d'ajouter un employé sans `department_id` pour voir la différence.

## SQL n'est pas totalement standardisé

ANSI SQL définit un socle commun, mais chaque moteur réel ajoute ses propres extensions et diverge sur les cas limites — voir [PostgreSQL](/fr/databases/postgresql) et [MySQL](/fr/databases/mysql) pour une syntaxe spécifique à un moteur qui ne s'exécute pas forcément sur les autres.
