Un **Proxy** est un serveur qui se place entre un client et le serveur qu'il essaie réellement d'atteindre, transmettant le trafic pour le compte de quelqu'un. Le camp qu'il représente fait toute la distinction :

- Un **Forward Proxy** agit pour le compte du *client* — c'est pourquoi le service informatique de votre entreprise peut bloquer certains sites, ou un VPN peut faire croire que votre trafic vient d'ailleurs.
- Un **Reverse Proxy** agit pour le compte du *serveur* — c'est pourquoi nullbase.wiki peut être soutenu par n'importe quel nombre de serveurs réels sans que vous le sachiez jamais.

## Pourquoi en utiliser un

- **Le routage** — un seul nom d'hôte, de nombreux services backend, répartis par chemin ou sous-domaine.
- **L'équilibrage de charge** — répartir les requêtes entre plusieurs instances backend identiques.
- **La terminaison TLS** — le Proxy gère HTTPS, si bien que les services backend n'ont besoin de parler qu'en HTTP simple en interne.
- **Le Cache** — servir les requêtes répétées depuis le Proxy sans jamais atteindre le backend.
- **La sécurité** — les vrais serveurs backend ne sont jamais directement accessibles depuis Internet.
