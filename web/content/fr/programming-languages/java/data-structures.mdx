Java vous offre deux niveaux de conteneur : les **tableaux** intégrés, qui
sont de taille fixe une fois créés, et le **Collections Framework**
(`java.util`), dont les types génériques redimensionnables comme
`ArrayList` et `HashMap` sont ce vers quoi la plupart du code quotidien se
tourne réellement.

## Tableaux

Un tableau contient un nombre fixe d'éléments d'un seul type, alloué à
l'avance :

```java
int[] scores = new int[3];
scores[0] = 70;
scores[1] = 85;
scores[2] = 92;

int[] literal = {70, 85, 92}; // littéral de tableau, taille inférée

System.out.println(scores.length); // 3, un champ, pas un appel de méthode
```

Les tableaux sont indexés à partir de zéro, et lire ou écrire en dehors de
`[0, length)` lève une `ArrayIndexOutOfBoundsException` à l'exécution
plutôt que de corrompre silencieusement la mémoire. `length` est un champ
`final` sur l'objet tableau, pas une méthode — à la différence de
`String.length()` ou `List.size()`, qui sont des méthodes.

## ArrayList

`ArrayList<T>` est une liste redimensionnable adossée à un tableau, issue
de `java.util`. Parce que les génériques Java ne peuvent pas contenir de
primitifs directement, `T` doit être un type référence — utilisez la
classe wrapper (`Integer`, pas `int`) pour des types d'éléments primitifs :

```java
import java.util.ArrayList;
import java.util.List;

List<String> names = new ArrayList<>();
names.add("Ada");
names.add("Linus");
names.add(1, "Grace"); // insertion à l'index 1, décalant les éléments suivants vers la droite

System.out.println(names);       // [Ada, Grace, Linus]
System.out.println(names.get(0)); // Ada
System.out.println(names.size()); // 3

names.remove("Linus");
System.out.println(names); // [Ada, Grace]
```

Déclarer la variable comme `List<String>` (l'interface) plutôt que
`ArrayList<String>` (la classe concrète) est idiomatique — cela vous
permet d'échanger plus tard une autre implémentation de `List` sans
toucher au code qui n'appelle que des méthodes de l'interface.

## HashMap

`HashMap<K, V>` stocke des paires clé-valeur avec une recherche, une
insertion, et une suppression en O(1) en moyenne, adossée à une table de
hachage. Elle ne garantit aucun ordre d'itération :

```java
import java.util.HashMap;
import java.util.Map;

Map<String, Integer> ages = new HashMap<>();
ages.put("Ada", 36);
ages.put("Linus", 54);

System.out.println(ages.get("Ada"));          // 36
System.out.println(ages.get("Grace"));         // null : clé absente
System.out.println(ages.getOrDefault("Grace", 0)); // 0 : valeur par défaut sûre
System.out.println(ages.containsKey("Linus")); // true

for (Map.Entry<String, Integer> entry : ages.entrySet()) {
    System.out.println(entry.getKey() + " is " + entry.getValue());
}
```

`get` sur une clé manquante renvoie `null` plutôt que de lever une
exception, ce qui est une source courante de bugs `NullPointerException`
si le résultat est utilisé sans vérification de nullité ou
`getOrDefault`. Si vous avez besoin d'un ordre d'itération prévisible,
`LinkedHashMap` préserve l'ordre d'insertion et `TreeMap` garde les clés
triées.
