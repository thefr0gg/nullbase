Java a été publié par Sun Microsystems en 1995 (aujourd'hui maintenu par
Oracle) sous le slogan « write once, run anywhere » (écrire une fois,
exécuter partout). Le code source compile vers un **bytecode**
indépendant de la plate-forme, qui s'exécute sur la machine virtuelle Java
(JVM) plutôt que directement sur un système d'exploitation donné. Le même
fichier `.class` s'exécute sans modification sous Windows, Linux, ou macOS
tant qu'une JVM compatible est installée.

Java est statiquement typé, avec ramasse-miettes, et profondément orienté
objet : presque tout ce que vous écrivez vit à l'intérieur d'une classe. Il
a alimenté une énorme part des systèmes backend d'entreprise, des
applications Android (via une chaîne d'outils compatible Java), et des
systèmes distribués à grande échelle pendant trois décennies, et son
écosystème de bibliothèques et d'outillage matures (Maven, Gradle, Spring)
est l'un des plus vastes de l'industrie.

## Ce qui rend Java distinctif

- **La JVM.** Le code compile vers du bytecode, pas du code machine. Le
  compilateur just-in-time de la JVM transforme ensuite le bytecode chaud
  en instructions natives à l'exécution, et le même bytecode s'exécute sans
  modification sur toute plate-forme dotée d'une JVM.
- **Presque tout est une classe.** Il n'y a pas de fonctions flottant
  librement. Chaque méthode vit à l'intérieur d'une classe ou d'une
  interface, même le point d'entrée `main` d'un programme.
- **Exceptions vérifiées.** Java distingue les exceptions que le
  compilateur vous force à gérer ou à déclarer (checked) de celles qu'il ne
  force pas (unchecked) — une distinction que la plupart des autres
  langages grand public ont abandonnée.
- **Héritage simple, interfaces multiples.** Une classe étend au plus une
  superclasse mais peut implémenter n'importe quel nombre d'interfaces,
  contournant le problème du diamant que crée l'héritage multiple complet.
- **Gestion automatique de la mémoire.** Un ramasse-miettes générationnel
  récupère les objets inaccessibles ; il n'y a pas de `free` ou de
  `delete` manuel.
- **Forte rétrocompatibilité.** Du code écrit pour Java 1.2 à la fin des
  années 1990 compile encore largement aujourd'hui — une politique
  d'évolution du langage délibérée et fortement surveillée.

Voici un programme Java minimal et complet :

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, nullbase!");
    }
}
```

Le fichier doit être nommé `Main.java` pour correspondre au nom de la
classe publique, et `main` doit avoir exactement cette signature —
`public static void main(String[] args)` — pour que la JVM la reconnaisse
comme point d'entrée.

## Quand se tourner vers Java

Java est un solide choix par défaut pour les grands systèmes backend à
longue durée de vie où la taille de l'équipe, la maturité de l'outillage,
et la maintenabilité à long terme comptent plus que la latence de démarrage
minimale : services d'entreprise, applications Android, et infrastructure
de big data (Hadoop, Kafka, et Spark sont tous écrits en Java ou dans son
cousin JVM Scala). Il est moins souvent choisi quand vous voulez un unique
petit binaire sans runtime à installer, ce qui est là où des langages
compilés comme Go ou Rust ont tendance à gagner.
