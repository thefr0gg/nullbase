C# est résolument orienté objet : les classes supportent l'héritage simple,
les interfaces supportent des contrats d'implémentation multiples, et
l'encapsulation est intégrée au langage à travers les **propriétés** plutôt
que laissée à la convention.

## Classes et champs

Une classe regroupe l'état (champs) et le comportement (méthodes) :

```csharp
class Dog
{
    private string name;

    public Dog(string name)
    {
        this.name = name;
    }

    public void Bark()
    {
        Console.WriteLine($"{name} says Woof!");
    }
}

var rex = new Dog("Rex");
rex.Bark(); // Rex says Woof!
```

Un simple champ `private` comme `name` n'a aucune validation et aucun moyen
d'intercepter les lectures ou écritures depuis l'extérieur de la classe —
c'est à cela que servent les propriétés.

## Les propriétés : une fonctionnalité du langage, pas une convention

Contrairement à Java ou C++, où « encapsuler des champs » signifie écrire à
la main des méthodes `getName()`/`setName()`, C# intègre directement la
syntaxe getter/setter dans le langage. Une propriété ressemble à un champ
pour les appelants mais peut exécuter du code à chaque lecture ou écriture :

```csharp
class Person
{
    private int age;

    public string Name { get; set; } // auto-implemented property: compiler
                                      // generates the backing field for you

    public int Age
    {
        get => age;
        set
        {
            if (value < 0)
            {
                throw new ArgumentException("Age cannot be negative");
            }
            age = value;
        }
    }

    public string Greeting => $"Hi, I'm {Name}"; // read-only, expression-bodied

    public Person(string name, int age)
    {
        Name = name;
        Age = age;
    }
}

var p = new Person("Ada", 36);
Console.WriteLine(p.Greeting); // Hi, I'm Ada
p.Age = -5; // throws ArgumentException
```

Les appelants écrivent `p.Age = 30;` exactement comme si `Age` était un
champ — la logique de validation dans le bloc `set` s'exécute de manière
transparente. C'est pourquoi le style C# favorise fortement les propriétés
publiques plutôt que les champs publics : vous pouvez commencer avec une
propriété auto-implémentée et ajouter de la logique plus tard sans casser
aucun appelant.

## Interfaces et héritage

Une interface déclare un contrat sans implémentation (méthodes d'interface
par défaut mises à part) ; une classe implémente une ou plusieurs interfaces
et hérite d'au plus une classe de base :

```csharp
interface IShape
{
    double Area();
}

class Circle : IShape
{
    public double Radius { get; }

    public Circle(double radius) => Radius = radius;

    public double Area() => Math.PI * Radius * Radius;
}

class Square : IShape
{
    public double Side { get; }

    public Square(double side) => Side = side;

    public double Area() => Side * Side;
}

List<IShape> shapes = new List<IShape> { new Circle(2), new Square(3) };
foreach (IShape shape in shapes)
{
    Console.WriteLine(shape.Area());
}
```

L'héritage de classe de base utilise la même syntaxe `:` et le mot-clé
`override` pour le polymorphisme :

```csharp
class Animal
{
    public virtual string Speak() => "...";
}

class Cat : Animal
{
    public override string Speak() => "Meow";
}

Animal a = new Cat();
Console.WriteLine(a.Speak()); // Meow — resolved at runtime via the actual type
```
