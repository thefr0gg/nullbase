La fonctionnalité de concurrence emblématique de C# est `async`/`await`
construite au-dessus de `Task` et `Task<T>` — des opérations asynchrones qui
représentent « une valeur qui sera disponible plus tard » (un peu comme une
`Promise` JavaScript, bien que `Task` précède l'usage répandu de ce motif et
soit porté par le pool de threads .NET plutôt que par une boucle
d'événements mono-thread).

## Task et Task\<T\>

Une `Task` représente une opération en cours sans résultat ; `Task<T>`
représente une opération qui produira éventuellement une valeur de type
`T` :

```csharp
using System.Threading;
using System.Threading.Tasks;

Task<int> task = Task.Run(() =>
{
    Thread.Sleep(1000); // simulate slow work
    return 42;
});

Console.WriteLine("Started, doing other work...");
int result = task.Result; // blocks until the task completes
Console.WriteLine(result); // 42
```

Bloquer sur `.Result` va à l'encontre d'une grande partie de l'intérêt de
l'asynchronie — le vrai code asynchrone utilise plutôt `await`, qui suspend
la méthode actuelle sans bloquer le thread sous-jacent.

## async / await

Marquer une méthode `async` lui permet d'utiliser `await` pour se suspendre
jusqu'à ce qu'une `Task` se termine, sans bloquer le thread appelant. Une
méthode `async` retourne elle-même une `Task` (ou `Task<T>`), donc les
appelants peuvent l'`await` à leur tour :

```csharp
using System.Net.Http;
using System.Threading.Tasks;

async Task<string> FetchGreetingAsync()
{
    await Task.Delay(500); // simulates an I/O-bound wait, non-blocking
    return "Hello from the async world";
}

async Task RunAsync()
{
    Console.WriteLine("Before await");
    string greeting = await FetchGreetingAsync();
    Console.WriteLine(greeting);
    Console.WriteLine("After await");
}

await RunAsync();
```

La méthode ne bloque pas un thread en attendant `Task.Delay` — le contrôle
revient à l'appelant, et le reste de `FetchGreetingAsync` reprend sur un
thread du pool de threads une fois le délai terminé. C'est pourquoi
`async`/`await` est l'idiome de choix pour le travail lié aux E/S (appels
réseau, accès fichier, requêtes base de données) : aucun thread n'est
gaspillé à attendre les E/S sans rien faire.

## Exécuter des tâches en parallèle

Attendre des tâches une par une les exécute séquentiellement.
`Task.WhenAll` démarre plusieurs tâches et les attend toutes ensemble,
exécutant le travail indépendant de manière concurrente :

```csharp
async Task<int> FetchLengthAsync(string url)
{
    await Task.Delay(300); // stands in for an HTTP call
    return url.Length;
}

async Task RunAllAsync()
{
    Task<int> t1 = FetchLengthAsync("https://a.example");
    Task<int> t2 = FetchLengthAsync("https://b.example");
    Task<int> t3 = FetchLengthAsync("https://c.example");

    int[] lengths = await Task.WhenAll(t1, t2, t3);
    Console.WriteLine(string.Join(", ", lengths));
}

await RunAllAsync();
```

Comme `t1`, `t2`, et `t3` sont tous démarrés avant tout `await`, leurs appels
`Task.Delay(300)` se chevauchent — la méthode entière prend environ 300 ms au
total, pas 900 ms, contrairement au fait d'attendre chacune immédiatement
après l'avoir démarrée.
