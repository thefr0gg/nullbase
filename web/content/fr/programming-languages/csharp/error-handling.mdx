C# utilise des exceptions pour la gestion des erreurs plutôt que des valeurs
de retour d'erreur. N'importe quoi, d'un index de tableau invalide à un
appel réseau échoué, lève un objet dérivé de `System.Exception`, et du code
plus haut dans la pile d'appels peut l'intercepter.

## try / catch / finally

```csharp
try
{
    int[] numbers = { 1, 2, 3 };
    Console.WriteLine(numbers[10]); // throws IndexOutOfRangeException
}
catch (IndexOutOfRangeException ex)
{
    Console.WriteLine($"Caught: {ex.Message}");
}
finally
{
    Console.WriteLine("This always runs, exception or not.");
}
```

`finally` s'exécute qu'une exception ait été levée ou non, et même si le
bloc `try` ou `catch` retourne prématurément — c'est l'endroit pour du
nettoyage comme fermer un fichier ou une connexion.

Plusieurs blocs `catch` vous permettent de traiter différents types
d'exception différemment ; ils sont vérifiés de haut en bas, donc placez les
types les plus spécifiques en premier :

```csharp
try
{
    string input = "not a number";
    int value = int.Parse(input);
}
catch (FormatException ex)
{
    Console.WriteLine($"Bad format: {ex.Message}");
}
catch (Exception ex)
{
    Console.WriteLine($"Something else went wrong: {ex.Message}");
}
```

Un filtre d'exception (`when`) permet à une seule clause `catch` de se
déclencher uniquement sous des conditions supplémentaires, sans avaler les
exceptions qui ne correspondent pas :

```csharp
try
{
    throw new InvalidOperationException("disk full");
}
catch (InvalidOperationException ex) when (ex.Message.Contains("disk"))
{
    Console.WriteLine("Handling a disk-related failure specifically.");
}
```

## Exceptions personnalisées

Dériver votre propre type d'exception depuis `Exception` (ou une classe de
base plus spécifique) permet au code appelant d'intercepter précisément
l'échec qui l'intéresse, et vous permet d'y attacher des données spécifiques
au domaine :

```csharp
class InsufficientFundsException : Exception
{
    public decimal Shortfall { get; }

    public InsufficientFundsException(decimal shortfall)
        : base($"Insufficient funds: short by {shortfall:C}")
    {
        Shortfall = shortfall;
    }
}

class Account
{
    public decimal Balance { get; private set; } = 100m;

    public void Withdraw(decimal amount)
    {
        if (amount > Balance)
        {
            throw new InsufficientFundsException(amount - Balance);
        }
        Balance -= amount;
    }
}

var account = new Account();
try
{
    account.Withdraw(150m);
}
catch (InsufficientFundsException ex)
{
    Console.WriteLine(ex.Message);      // Insufficient funds: short by $50.00
    Console.WriteLine(ex.Shortfall);    // 50
}
```

Les exceptions personnalisées devraient toujours appeler le constructeur de
base (`: base(message)`) pour que la propriété `.Message` standard et la
mécanique de trace de pile continuent de fonctionner comme prévu.
