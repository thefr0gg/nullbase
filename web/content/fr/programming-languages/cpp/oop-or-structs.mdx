Une **classe** C++ regroupe des données (variables membres) et du comportement (fonctions membres) dans un seul type. Contrairement à un simple `struct` en C, une classe C++ contrôle exactement quelles parties de ce regroupement le code extérieur est autorisé à toucher — le mécanisme qui rend l'encapsulation possible.

## Constructeurs et modificateurs d'accès

```cpp
#include <iostream>
#include <string>

class BankAccount {
private:
    std::string owner;
    double balance;

public:
    // constructor: runs automatically when a BankAccount is created
    BankAccount(std::string ownerName, double startingBalance) {
        owner = ownerName;
        balance = startingBalance;
    }

    void deposit(double amount) {
        balance += amount;
    }

    double getBalance() const {
        return balance;
    }
};

int main() {
    BankAccount account("Ada", 100.0);
    account.deposit(50.0);
    std::cout << account.getBalance() << "\n"; // 150

    // account.balance = 1000000;  // would fail to compile: balance is private
    return 0;
}
```

Les membres `private` (`owner`, `balance`) ne sont accessibles que depuis l'intérieur des fonctions membres de la classe elle-même ; les membres `public` forment l'interface externe de la classe. C'est pourquoi `account.balance` ne peut pas être touché directement depuis `main` — tout accès doit passer par `deposit()` et `getBalance()`, ce qui permet à la classe d'imposer ses propres règles (par exemple, rejeter un dépôt négatif) au lieu de faire confiance à chaque appelant pour faire la bonne chose. Le **constructeur** — une fonction portant le même nom que la classe et sans type de retour — s'exécute automatiquement chaque fois qu'un objet est créé, garantissant que chaque `BankAccount` démarre dans un état valide plutôt que de dépendre d'un appel `init()` séparé qu'il est facile d'oublier.

## Héritage

```cpp
#include <iostream>
#include <string>

class Animal {
protected:
    std::string name;

public:
    Animal(std::string animalName) : name(animalName) {}

    virtual std::string speak() const {
        return name + " makes a sound.";
    }
};

class Dog : public Animal {
public:
    Dog(std::string dogName) : Animal(dogName) {}

    std::string speak() const override {
        return name + " barks.";
    }
};

int main() {
    Animal generic("Creature");
    Dog rex("Rex");

    std::cout << generic.speak() << "\n"; // Creature makes a sound.
    std::cout << rex.speak() << "\n";     // Rex barks.
    return 0;
}
```

`class Dog : public Animal` fait hériter `Dog` des membres d'`Animal` — les membres `protected` (comme `name`) sont visibles pour les classes dérivées mais toujours cachés au code extérieur, un intermédiaire entre `private` et `public`. `Animal(dogName)` dans la liste d'initialisation du constructeur de `Dog` appelle explicitement le constructeur de la classe de base, puisqu'une classe dérivée ne sait pas automatiquement comment initialiser la partie base d'elle-même. Marquer `speak()` comme `virtual` dans la classe de base et `override` dans la classe dérivée active le **polymorphisme** : appeler `speak()` via une référence ou un pointeur de classe de base dispatche vers la version du type dérivé réel à l'exécution, plutôt que d'appeler toujours `Animal::speak()`.
