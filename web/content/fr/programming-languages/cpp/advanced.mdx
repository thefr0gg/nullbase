Le compromis qui définit C++ est l'accès direct aux adresses mémoire — puissant, puisqu'il vous permet de construire des structures de données et de contrôler l'agencement à un niveau que la plupart des langages cachent, et dangereux, puisqu'une erreur ici (non ramassée par un garbage collector, non vérifiée automatiquement) produit des bugs qui peuvent corrompre la mémoire silencieusement plutôt que d'échouer bruyamment.

## Pointeurs et références

```cpp
#include <iostream>

int main() {
    int value = 42;

    int* ptr = &value;   // ptr holds the address of value
    int& ref = value;    // ref is another name for value itself

    std::cout << "value: " << value << "\n";
    std::cout << "*ptr: " << *ptr << "\n";  // dereference: follow the pointer
    std::cout << "ref: " << ref << "\n";

    *ptr = 100;  // changes value, through the pointer
    ref = 200;   // changes value, through the reference

    std::cout << "value is now: " << value << "\n"; // 200
    return 0;
}
```

`&value` prend l'adresse de `value` ; `int* ptr` déclare `ptr` comme une variable qui stocke cette adresse, et `*ptr` la **déréférence** — suivant l'adresse pour lire ou écrire l'`int` réel qu'elle pointe. `int& ref = value` déclare une **référence**, qui se comporte comme un alias pour `value` plutôt que comme une variable séparée contenant une adresse : aucun déréférencement explicite n'est nécessaire, et contrairement à un pointeur, une référence ne peut pas être réassignée pour désigner autre chose après son initialisation, et ne peut pas être nulle. Les pointeurs sont plus flexibles (ils peuvent être réassignés, et un pointeur nul peut représenter « ne pointe vers rien ») ; les références sont plus sûres chaque fois que cette flexibilité n'est pas réellement nécessaire.

## Mémoire manuelle : `new` et `delete`

```cpp
#include <iostream>

int main() {
    int* single = new int(10);       // allocate one int on the heap
    int* array = new int[5]{1,2,3,4,5}; // allocate an array on the heap

    std::cout << *single << "\n";
    std::cout << array[2] << "\n";

    delete single;      // free the single int
    delete[] array;      // free the array — note the [] to match new[]

    return 0;
}
```

`new` alloue de la mémoire sur le tas qui survit à la fonction dans laquelle elle a été allouée, et rend un pointeur vers celle-ci ; cette mémoire reste allouée jusqu'à ce que quelque chose appelle explicitement `delete` (ou `delete[]` pour un tableau alloué avec `new[]` — les mélanger est un comportement indéfini). Oublier d'appeler `delete` du tout est une **fuite de mémoire** : la mémoire n'est jamais récupérée pour le reste de la vie du programme. Appeler `delete` deux fois sur le même pointeur, ou utiliser un pointeur après qu'il a été supprimé, sont tout aussi dangereux et sont les deux catégories de bugs mémoire les plus courantes dans la gestion manuelle de mémoire de style C.

## Smart pointers : RAII pour le tas

```cpp
#include <iostream>
#include <memory>

class Resource {
public:
    Resource() { std::cout << "Resource acquired\n"; }
    ~Resource() { std::cout << "Resource released\n"; }
    void use() { std::cout << "Using resource\n"; }
};

int main() {
    std::unique_ptr<Resource> res = std::make_unique<Resource>();
    res->use();
    // no delete needed — res's destructor runs automatically here,
    // releasing the Resource exactly once, even if an exception
    // had been thrown between make_unique and this closing brace
    return 0;
}
```

`std::unique_ptr<Resource>` possède une `Resource` allouée sur le tas et la supprime automatiquement dans son propre destructeur quand elle sort de sa portée — le même motif RAII qu'utilisent `std::ofstream` et `std::vector`, appliqué directement à la mémoire dynamique brute. Il n'y a de `delete` nulle part dans cet exemple, et il n'a pas besoin d'y en avoir : la propriété est exactement un `unique_ptr` à la fois (en copier un est une erreur de compilation ; il peut seulement être *déplacé*), ce qui rend structurellement impossible de faire un double free ou d'oublier de libérer la `Resource` sous-jacente. La recommandation du C++ moderne est de recourir à `new`/`delete` directement uniquement dans des cas rares et bas niveau — `std::unique_ptr` (propriété unique) et `std::shared_ptr` (propriété partagée, comptée par référence) couvrent presque tout le reste sans aucune comptabilité manuelle.
