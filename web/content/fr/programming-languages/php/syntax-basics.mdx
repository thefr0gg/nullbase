Le code PHP vit à l'intérieur de balises `<?php ... ?>`. Tout ce qui est en
dehors de ces balises — même au milieu d'un fichier — est transmis
directement comme sortie, ce qui est ce qui rend PHP pratique pour mélanger
markup et logique dans le même fichier.

## La balise `<?php`

```php
<html>
<body>
<?php
$name = "Ada";
echo "<p>Hello, $name!</p>";
?>
</body>
</html>
```

En pratique, les fichiers qui ne contiennent *que* du PHP (sans HTML à la
suite) devraient omettre entièrement la balise fermante `?>`. Elle est
optionnelle, et l'omettre évite un bug subtil : tout espace blanc ou saut de
ligne après `?>` est envoyé à la sortie, ce qui peut casser des choses comme
la définition d'en-têtes HTTP après que le script « se termine ».

```php
<?php

echo "No closing tag needed for a pure-PHP file.\n";
```

## Les variables commencent toujours par `$`

Chaque variable en PHP est préfixée par un signe dollar, sans exception —
c'est l'une des choses les plus immédiatement reconnaissables de la syntaxe
PHP. Les variables sont aussi à typage dynamique : on ne déclare pas de type
à l'avance, et une variable peut détenir un type de valeur différent après
une assignation ultérieure.

```php
<?php

$age = 30;          // int
$age = "thirty";     // now a string — perfectly legal
$isAdmin = true;      // bool
$price = 19.99;        // float
```

Les noms de variables sont sensibles à la casse (`$Name` et `$name` sont des
variables différentes) et doivent commencer par une lettre ou un
underscore, jamais un chiffre.

## Constantes

`define()` et le plus moderne `const` créent tous deux des valeurs qui ne
peuvent pas être réassignées. `const` est préféré pour les valeurs scalaires
simples et fonctionne à la fois au premier niveau et à l'intérieur des
classes :

```php
<?php

const MAX_RETRIES = 3;
define("APP_NAME", "nullbase");

echo MAX_RETRIES . " retries allowed for " . APP_NAME . "\n";
```

Notez que les constantes sont référencées *sans* le sigil `$` — un autre
endroit où la règle du sigil de PHP a une exception bien connue.

## Interpolation de chaîne

Les chaînes entre guillemets doubles interpolent les variables directement ;
les chaînes entre apostrophes ne le font jamais. C'est une source courante de
bugs subtils quand un `$` littéral est voulu, donc ça vaut la peine de bien
le connaître :

```php
<?php

$user = "grace";
echo "Logged in as $user\n";   // Logged in as grace
echo 'Logged in as $user\n';    // Logged in as $user\n  (literal, no newline)
```

Les accolades désambiguïsent une variable du texte environnant, et sont
requises pour interpoler proprement une propriété ou un accès à un tableau :

```php
<?php

$user = ["name" => "grace"];
echo "Hello, {$user['name']}!\n";
```

## Typage laxiste et jonglage de types

Par défaut, PHP convertira les types à la volée pour faire fonctionner une
opération — c'est ce qu'on appelle le **jonglage de types**. `declare(strict_types=1)`
en haut d'un fichier désactive cela pour les vérifications de type des
arguments et des valeurs de retour de fonction (bien que les opérateurs de
comparaison laxistes comme `==` jonglent quand même) :

```php
<?php
declare(strict_types=1);

function double(int $n): int {
    return $n * 2;
}

echo double(5) . "\n";   // 10
// double("5") would now throw a TypeError instead of silently converting
```
