Go organise le code sur deux niveaux : les **paquets** regroupent des
fichiers source liés à l'intérieur d'un répertoire, et les **modules**
regroupent des paquets en une unité versionnée et distribuable, avec sa
propre liste de dépendances.

## Paquets

Chaque fichier `.go` commence par une déclaration `package`. Tous les
fichiers d'un même répertoire doivent déclarer le même nom de package, et
ce nom devient l'espace de noms que le reste du code importe :

```go
package geometry

func Area(width, height float64) float64 {
	return width * height
}
```

Un autre fichier ailleurs l'importe par son chemin de module et appelle le
nom exporté (avec une majuscule) :

```go
package main

import (
	"fmt"

	"example.com/myapp/geometry"
)

func main() {
	fmt.Println(geometry.Area(3, 4)) // 12
}
```

`import` peut importer plusieurs paquets à la fois à l'intérieur de
parenthèses, comme ci-dessus. La bibliothèque standard est livrée sous
forme de paquets ordinaires que vous importez de la même façon —
`"fmt"`, `"strings"`, `"net/http"` — sans étape d'installation séparée.

## go.mod et les modules Go

Un **module** est l'unité de gestion de version et de dépendances —
habituellement un dépôt Git. `go mod init` crée un fichier `go.mod`
déclarant le chemin du module et la version de Go qu'il cible :

```bash
go mod init example.com/myapp
```

```go
module example.com/myapp

go 1.22
```

Ajouter un import vers une véritable dépendance et exécuter `go build` (ou
`go mod tidy`) la récupère et enregistre la version exacte dans `go.mod`,
avec une somme de contrôle cryptographique de chaque dépendance dans
`go.sum` :

```go
module example.com/myapp

go 1.22

require github.com/google/uuid v1.6.0
```

`go.sum` n'est pas destiné à être édité à la main — c'est un fichier de
verrouillage que Go maintient pour garantir des builds reproductibles : le
même `go.mod` résout toujours vers un code de dépendance identique
octet pour octet.

## Commandes de module utiles

```bash
go mod init example.com/myapp   # démarrer un nouveau module
go mod tidy                      # ajouter les dépendances manquantes / retirer celles inutilisées
go get github.com/some/pkg@v1.2.0  # ajouter ou mettre à jour une dépendance
go build ./...                    # construire tous les paquets du module
```

## Paquets internes

Un répertoire nommé `internal` restreint ce qui peut l'importer : les
paquets sous `internal/` ne sont importables que par du code à l'intérieur
de l'arbre du module enraciné au parent d'`internal`. C'est le mécanisme
intégré de Go pour marquer du code comme « détail d'implémentation, pas
une partie de votre API publique », imposé par le compilateur plutôt que
par la seule convention.
