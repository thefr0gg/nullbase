Les constructions de flux de contrôle de Rust paraîtront familières venant
des langages de la famille C, mais avec une torsion récurrente : `if`,
`loop`, et `match` sont des **expressions** — elles produisent une valeur —
plutôt que de simples instructions. Cette valeur peut être assignée
directement à une variable, ce qui supprime toute une catégorie de code
répétitif « déclarer la variable, puis l'assigner conditionnellement dans
chaque branche ».

## `if`/`else` comme expression

```rust
fn main() {
    let temperature = 15;

    let description = if temperature > 25 {
        "hot"
    } else if temperature > 10 {
        "mild"
    } else {
        "cold"
    };

    println!("It's {description} today");
}
```

Chaque branche doit produire le même type (ici, `&str`), et il n'y a pas de
point-virgule final sur les expressions de branche — un point-virgule
transformerait `"mild"` en une instruction qui s'évalue en `()` (unit), ce
qui ne correspondrait pas au type des autres branches et échouerait à la
compilation.

## Boucles : `loop`, `while`, `for`

`loop` s'exécute pour toujours jusqu'à un `break` explicite, et — comme
`if` — un `loop` peut aussi produire une valeur, en la passant à `break` :

```rust
fn main() {
    let mut attempts = 0;

    let result = loop {
        attempts += 1;
        if attempts == 3 {
            break attempts * 10; // loop evaluates to this value
        }
    };

    println!("Succeeded on attempt {attempts}, result = {result}");
}
```

`while` est la boucle conditionnelle attendue de n'importe quel langage de
la famille C, et `for` est la façon préférée de Rust d'itérer — presque
toujours sur une plage ou un itérateur, plutôt que sur un index géré
manuellement :

```rust
fn main() {
    let numbers = [10, 20, 30, 40];

    // while: keep going as long as a condition holds
    let mut i = 0;
    while i < numbers.len() {
        println!("index {i}: {}", numbers[i]);
        i += 1;
    }

    // for: iterate directly over the collection, no index bookkeeping
    for n in numbers.iter() {
        println!("value: {n}");
    }
}
```

La version `for` est du Rust idiomatique — elle ne peut pas sortir des
limites parce qu'il n'y a pas d'index à se tromper, et elle se lit comme
« pour chaque valeur dans cette collection » plutôt que « compter jusqu'à
cette longueur et indexer dedans ».

## `match`

`match` compare une valeur à une série de motifs et exécute le code du
premier qui correspond. Contrairement à `switch` dans les langages de la
famille C, `match` en Rust est **exhaustif** — le compilateur rejette un
`match` qui ne couvre pas toutes les valeurs possibles, à moins d'ajouter
une branche fourre-tout `_`.

```rust
fn describe(n: i32) -> &'static str {
    match n {
        0 => "zero",
        1 | 2 | 3 => "small",
        4..=9 => "medium",
        n if n < 0 => "negative",
        _ => "large",
    }
}

fn main() {
    for n in [-5, 0, 2, 7, 100] {
        println!("{n} is {}", describe(n));
    }
}
```

Ce seul `match` montre plusieurs formes de motif à la fois : une valeur
exacte (`0`), des alternatives (`1 | 2 | 3`), une plage inclusive (`4..=9`),
une condition de garde (`n if n < 0`), et le fourre-tout `_`. Comme `match`
est exhaustif, supprimer la branche `_` ici serait une erreur de
compilation — le compilateur peut prouver qu'il existe des valeurs `i32`
qu'aucune des autres branches ne couvre.
