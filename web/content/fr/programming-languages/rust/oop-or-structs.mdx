Rust n'a pas de mot-clé `class` ni d'héritage entre types de données. À la
place, il divise les deux choses qu'une classe regroupe habituellement en
constructions séparées : un **`struct`** détient des données, et un
**`impl`** attache des fonctions à ce struct. Le comportement partagé entre
types sans lien — ce que d'autres langages expriment avec des interfaces ou
de l'héritage — se fait avec les **traits**.

## Structs

```rust
struct Rectangle {
    width: f64,
    height: f64,
}

fn main() {
    let rect = Rectangle { width: 30.0, height: 10.0 };
    println!("area: {}", rect.width * rect.height);
}
```

## Blocs `impl` : méthodes et fonctions associées

Un bloc `impl` attache des fonctions à un struct. Une méthode prend `&self`
(ou `&mut self`, ou `self`) comme premier paramètre et est appelée avec la
syntaxe pointée ; une **fonction associée** (sans paramètre `self`) est
appelée sur le type lui-même, le plus souvent comme un constructeur nommé
`new` par convention.

```rust
struct Rectangle {
    width: f64,
    height: f64,
}

impl Rectangle {
    // associated function — no `self`, called as Rectangle::square(5.0)
    fn square(size: f64) -> Rectangle {
        Rectangle { width: size, height: size }
    }

    // method — takes &self, called as rect.area()
    fn area(&self) -> f64 {
        self.width * self.height
    }

    fn scale(&mut self, factor: f64) {
        self.width *= factor;
        self.height *= factor;
    }
}

fn main() {
    let mut sq = Rectangle::square(5.0);
    println!("area before scale: {}", sq.area());

    sq.scale(2.0);
    println!("area after scale: {}", sq.area());
}
```

`&self` emprunte l'instance de façon immuable (suffisant pour `area`, qui ne
fait que lire), tandis que `&mut self` l'emprunte de façon mutable
(nécessaire pour `scale`, qui écrit dans `width` et `height`). C'est la même
règle d'emprunt qui régit chaque autre référence en Rust — les méthodes ne
sont pas un cas particulier.

## Traits : comportement partagé sans héritage

Un **trait** définit un ensemble de méthodes qu'un type promet
d'implémenter — la réponse de Rust à une interface. Contrairement à
l'héritage de classe, implémenter un trait ne donne à un type aucun champ
ni comportement gratuitement ; cela requiert seulement que le type fournisse
les méthodes que le trait déclare (les traits peuvent aussi fournir des
corps de méthode par défaut que les implémenteurs peuvent redéfinir).

```rust
trait Describe {
    fn describe(&self) -> String;
}

struct Rectangle {
    width: f64,
    height: f64,
}

struct Circle {
    radius: f64,
}

impl Describe for Rectangle {
    fn describe(&self) -> String {
        format!("a {}x{} rectangle", self.width, self.height)
    }
}

impl Describe for Circle {
    fn describe(&self) -> String {
        format!("a circle with radius {}", self.radius)
    }
}

fn print_description(shape: &dyn Describe) {
    println!("{}", shape.describe());
}

fn main() {
    let rect = Rectangle { width: 3.0, height: 4.0 };
    let circle = Circle { radius: 2.0 };

    print_description(&rect);
    print_description(&circle);
}
```

`Rectangle` et `Circle` ne partagent aucun ancêtre commun ni aucun champ —
ils ne sont liés que par le fait d'implémenter tous deux `Describe`.
`print_description` accepte `&dyn Describe`, signifiant « une référence vers
n'importe quoi qui implémente ce trait », ce qui est comment Rust obtient du
polymorphisme sans hiérarchie de classes : le contrat partagé est le trait,
pas un type de base partagé.
