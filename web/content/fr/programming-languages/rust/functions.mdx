Les fonctions en Rust sont déclarées avec `fn`, et chaque paramètre a besoin
d'une annotation de type explicite — contrairement aux liaisons `let`, Rust
n'infère pas les types de paramètres ou de retour à partir de la façon dont
une fonction est appelée, parce que cela ferait dépendre la signature d'une
fonction de ses sites d'appel au lieu d'être un contrat fixe.

```rust
fn add(a: i32, b: i32) -> i32 {
    a + b // no semicolon: this is the returned expression
}

fn main() {
    let sum = add(3, 4);
    println!("{sum}");
}
```

## Expressions vs. instructions comme valeurs de retour

La dernière expression dans le corps d'une fonction est automatiquement sa
valeur de retour, *tant qu'elle n'a pas de point-virgule final*. Ajoutez un
point-virgule et cela devient une instruction qui s'évalue en `()`,
changeant silencieusement ce que la fonction renvoie :

```rust
fn add_broken(a: i32, b: i32) -> i32 {
    a + b; // semicolon turns this into a statement, not a return value
} // error: mismatched types — expected i32, found ()
```

Vous pouvez toujours utiliser un mot-clé `return` explicite — c'est
nécessaire pour renvoyer tôt depuis le milieu d'une fonction — mais compter
sur l'expression finale pour le chemin de sortie « normal » est le style
idiomatique.

```rust
fn classify(n: i32) -> &'static str {
    if n < 0 {
        return "negative"; // early return, semicolon required after return
    }
    if n == 0 {
        "zero"
    } else {
        "positive"
    } // trailing expression: the normal-path return value
}
```

## Closures

Une **closure** est une fonction anonyme qui peut capturer des variables de
la portée dans laquelle elle est définie — écrite avec des barres verticales
autour de ses paramètres (`|x| ...`) au lieu de `fn name(x: T)`. Les
closures sont beaucoup utilisées avec des méthodes d'itérateur comme `map`
et `filter`.

```rust
fn main() {
    let threshold = 10;
    let numbers = vec![4, 12, 7, 15, 3];

    // the closure captures `threshold` from the surrounding scope
    let above: Vec<i32> = numbers.into_iter().filter(|n| *n > threshold).collect();

    println!("{above:?}"); // [12, 15]
}
```

Contrairement à un `fn` ordinaire, cette closure peut voir `threshold` sans
qu'il soit passé explicitement — les closures empruntent ou déplacent les
variables auxquelles elles font référence depuis leur environnement, ce qui
est exactement ce qui permet à la closure de `filter` de comparer par
rapport à une valeur définie en dehors d'elle.
