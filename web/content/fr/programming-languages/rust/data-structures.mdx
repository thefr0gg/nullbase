Rust sépare « combien d'éléments, connu à la compilation » de « combien
d'éléments, décidé à l'exécution » au niveau du type. Un **tableau** a une
taille fixe et vit sur la pile ; un **`Vec`** (vecteur) est extensible et
possède une allocation sur le tas. Se tromper de choix est une erreur
fréquente au début — les tableaux ne peuvent pas grandir, donc tout ce qui
est construit élément par élément a besoin d'un `Vec`.

## Tableaux

```rust
fn main() {
    let scores: [i32; 3] = [90, 85, 78];
    println!("first score: {}", scores[0]);
    println!("total scores: {}", scores.len());

    // scores.push(100); // error: no method named `push` on array [i32; 3]
}
```

Le type `[i32; 3]` intègre la longueur dans le type lui-même — un tableau de
3 `i32` est un type différent d'un tableau de 4, et aucun des deux n'a de
méthode `push`, parce que leur taille ne peut jamais changer après la
création.

## `Vec<T>`

`Vec<T>` est l'alternative extensible et allouée sur le tas — la collection
vers laquelle on se tourne par défaut quand le nombre d'éléments n'est pas
fixé à l'avance.

```rust
fn main() {
    let mut scores: Vec<i32> = Vec::new();
    scores.push(90);
    scores.push(85);
    scores.push(78);

    // vec! macro is the more common way to write this
    let scores = vec![90, 85, 78];

    let average: i32 = scores.iter().sum::<i32>() / scores.len() as i32;
    println!("average: {average}");
}
```

Indexer un `Vec` en dehors des limites (`scores[10]` sur un vec à 3
éléments) panique à l'exécution plutôt que de renvoyer silencieusement des
déchets — Rust préfère planter bruyamment plutôt que de vous laisser lire de
la mémoire qui n'est pas la vôtre. Pour une recherche qui ne panique pas,
`scores.get(10)` renvoie `Option<&i32>` — `None` au lieu d'une valeur quand
l'index n'existe pas.

## `HashMap<K, V>`

`HashMap` stocke des paires clé-valeur, similaire à un dictionnaire en
Python ou un objet utilisé comme map en JavaScript. Il doit être importé
explicitement depuis `std::collections` — contrairement à `Vec` et aux
tableaux, il n'est pas dans le prélude par défaut.

```rust
use std::collections::HashMap;

fn main() {
    let mut inventory: HashMap<String, i32> = HashMap::new();
    inventory.insert(String::from("apples"), 12);
    inventory.insert(String::from("bananas"), 6);

    match inventory.get("apples") {
        Some(count) => println!("apples: {count}"),
        None => println!("no apples tracked"),
    }

    // entry API: increment if present, insert 1 if not
    *inventory.entry(String::from("apples")).or_insert(0) += 1;
    println!("apples now: {}", inventory["apples"]);
}
```

`get` renvoie `Option<&V>` plutôt que la valeur directement, parce que la
clé pourrait ne pas exister — c'est le même motif `Option` qu'utilise
`Vec::get`, et c'est central à la façon dont Rust évite les erreurs de
référence nulle (couvert en détail sur la page
[Gestion des erreurs](/fr/programming-languages/rust/error-handling)).
L'API `entry` ci-dessus est la façon idiomatique de faire « mettre à jour si
présent, insérer une valeur par défaut sinon » en une ligne sans chercher la
clé deux fois.
