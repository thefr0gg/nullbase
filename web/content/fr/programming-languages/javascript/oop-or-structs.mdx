JavaScript a des objets depuis 1995 mais n'a eu la syntaxe `class` qu'avec
ES6 (2015). Il est important de comprendre que `class` est du sucre
syntaxique : en dessous, JavaScript fait toujours de l'héritage basé sur
les prototypes, le même mécanisme qu'il a toujours eu. Connaître les deux
couches — la syntaxe `class` conviviale et la chaîne de prototypes vers
laquelle elle compile — explique beaucoup de comportements qui
sembleraient sinon magiques.

## Syntaxe class

```js
class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    return `${this.name} makes a sound.`;
  }
}

class Dog extends Animal {
  speak() {
    return `${this.name} barks.`;
  }
}

const generic = new Animal("Creature");
const rex = new Dog("Rex");

console.log(generic.speak()); // "Creature makes a sound."
console.log(rex.speak());     // "Rex barks."
```

`extends` met en place l'héritage, et `super(...)` à l'intérieur du
constructeur d'une sous-classe appelle le constructeur parent — requis
avant de pouvoir utiliser `this` dans le constructeur d'une classe
dérivée.

```js
class Employee extends Animal {
  constructor(name, role) {
    super(name);       // doit s'exécuter avant que `this` ne soit utilisé ci-dessous
    this.role = role;
  }

  speak() {
    return `${super.speak()} ${this.name} works as ${this.role}.`;
  }
}

const e = new Employee("Sam", "an engineer");
console.log(e.speak());
// "Sam makes a sound. Sam works as an engineer."
```

Les classes prennent aussi en charge les membres `static` (attachés à la
classe elle-même, pas aux instances), les champs privés avec un préfixe
`#` (véritablement inaccessibles depuis l'extérieur de la classe, à la
différence d'une convention `_prefix`), et les getters/setters.

```js
class Counter {
  #count = 0; // champ privé — ni visible ni modifiable depuis l'extérieur de la classe

  static description = "A simple counter";

  increment() {
    this.#count += 1;
    return this.#count;
  }

  get value() {
    return this.#count;
  }
}

const c = new Counter();
c.increment();
c.increment();
console.log(c.value);       // 2
console.log(Counter.description); // "A simple counter"
// console.log(c.#count);   // SyntaxError — #count n'est pas accessible ici
```

## Ce qui se passe réellement : la chaîne de prototypes

Chaque objet en JavaScript a un lien interne vers un autre objet appelé
son prototype, formant une chaîne. Quand vous accédez à une propriété, le
moteur regarde d'abord sur l'objet lui-même, puis remonte la chaîne de
prototypes jusqu'à trouver la propriété ou épuiser la chaîne. Les méthodes
`class` ne sont que des fonctions ordinaires attachées à
`SomeClass.prototype`, partagées par chaque instance plutôt que copiées
sur chacune d'elles.

```js
function Animal(name) { // une ancienne « fonction constructeur » — équivalent pré-ES6 d'une classe
  this.name = name;
}

Animal.prototype.speak = function () {
  return `${this.name} makes a sound.`;
};

const a = new Animal("Creature");
console.log(a.speak()); // "Creature makes a sound."

// C'est exactement ce vers quoi `class Animal { speak() {...} }` compile.
console.log(Object.getPrototypeOf(a) === Animal.prototype); // true
console.log(a.hasOwnProperty("speak"));                       // false — speak vit sur le prototype, pas sur `a` lui-même
```

C'est pourquoi ajouter une méthode à `Animal.prototype` après avoir créé
des instances la rend quand même disponible sur ces instances existantes —
elles ne détiennent pas leur propre copie de la méthode, elles la
recherchent à travers la chaîne à chaque appel.
