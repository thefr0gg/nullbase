Une classe Python est définie avec `class`, et presque toutes les classes commencent par une méthode `__init__` — le constructeur, appelé automatiquement à la création d'une nouvelle instance — qui met en place les attributs d'instance via `self`.

```python
class Dog:
    def __init__(self, name, breed):
        self.name = name
        self.breed = breed

    def bark(self):
        return f"{self.name} says Woof!"

rex = Dog("Rex", "Labrador")
print(rex.bark())  # Rex says Woof!
```

`self` est l'instance sur laquelle la méthode a été appelée — Python le passe explicitement comme premier paramètre de chaque méthode d'instance, plutôt que d'en faire un mot-clé implicite comme `this` dans d'autres langages. `rex.bark()` est en réalité `Dog.bark(rex)` sous le capot.

L'héritage permet à une classe de réutiliser et d'étendre le comportement d'une autre classe. Une sous-classe appelle `super().__init__(...)` pour exécuter le constructeur de la classe parente avant d'ajouter sa propre initialisation, et elle peut redéfinir n'importe quelle méthode, y compris celles que le parent définit déjà.

```python
class Puppy(Dog):
    def __init__(self, name, breed, age_months):
        super().__init__(name, breed)
        self.age_months = age_months

    def bark(self):
        return f"{self.name} says Yip!"

buddy = Puppy("Buddy", "Poodle", 4)
print(buddy.bark())  # Buddy says Yip!
```

Les méthodes « dunder » (double underscore) sont la façon dont une classe se branche sur les opérateurs et fonctions intégrés de Python au lieu d'avoir besoin de sa propre API sur mesure. `__repr__` contrôle ce que `print()` et le REPL affichent pour une instance ; `__eq__` contrôle ce que `==` fait entre deux instances.

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __repr__(self):
        return f"Point({self.x}, {self.y})"

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

p1 = Point(1, 2)
p2 = Point(1, 2)
print(p1 == p2)  # True — because __eq__ compares the coordinates
print(p1)         # Point(1, 2) — because __repr__ formats it
```

Sans `__eq__`, `==` retombe sur une comparaison d'identité — vérifier si les deux noms font référence exactement au même objet en mémoire — ce qui n'est presque jamais ce que l'on veut pour une classe de type valeur comme `Point`.
