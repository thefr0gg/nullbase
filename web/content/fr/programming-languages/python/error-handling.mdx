Python signale un échec en levant des exceptions, et gérer l'une d'elles consiste à envelopper le code risqué dans un bloc `try` avec une ou plusieurs clauses `except` qui interceptent des types d'exception spécifiques.

```python
try:
    value = int(input("Enter a number: "))
except ValueError:
    print("That wasn't a valid number.")
else:
    print(f"You entered {value}")
finally:
    print("Done processing input.")
```

Chaque clause a un rôle distinct : le bloc `try` contient le code qui pourrait échouer ; `except ValueError` n'intercepte que cette erreur spécifique (un `TypeError` ailleurs dans le bloc se propagerait sans être intercepté) ; `else` ne s'exécute que si le bloc `try` s'est terminé sans aucune exception ; `finally` s'exécute toujours — exception ou non, `return` ou non — ce qui en fait l'endroit idéal pour le nettoyage comme fermer un fichier ou relâcher un verrou.

Intercepter spécifiquement `except ValueError`, plutôt qu'un `except:` nu, importe : un `except` nu avale *tout*, y compris les fautes de frappe qui lèvent `NameError` et les interruptions comme `KeyboardInterrupt`, ce qui fait disparaître silencieusement de vrais bugs au lieu de les faire remonter.

Les exceptions personnalisées ne sont que des classes qui héritent de `Exception` (ou d'une exception intégrée plus spécifique), ce qui permet au code appelant d'intercepter votre mode d'échec spécifique par son nom plutôt que de deviner à partir de messages de chaîne.

```python
class InsufficientFundsError(Exception):
    """Raised when a withdrawal exceeds the account balance."""

def withdraw(balance, amount):
    if amount > balance:
        raise InsufficientFundsError(f"Cannot withdraw {amount}, balance is {balance}")
    return balance - amount

try:
    withdraw(100, 150)
except InsufficientFundsError as e:
    print(e)  # Cannot withdraw 150, balance is 100
```

`raise` est la façon dont le code signale explicitement un échec ; `except ... as e` lie l'instance d'exception interceptée à un nom pour que son message (ou toute donnée supplémentaire qui y est attachée) puisse être inspecté.

```python
def read_config(path):
    try:
        with open(path) as f:
            return f.read()
    except FileNotFoundError:
        return "{}"
```

Ici, un mode d'échec spécifique et attendu (le fichier n'existe pas encore) est géré avec un repli sensé, tandis que toute autre erreur — un problème de permissions, une panne de disque — est laissée à se propager, puisque les avaler silencieusement cacherait un vrai problème.
