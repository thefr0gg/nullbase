Les fonctions sont définies avec `def`, et Python n'exige pas de déclarer un type de retour ou des types de paramètres — les paramètres peuvent cependant recevoir des valeurs par défaut, ce qui les rend optionnels au niveau de l'appel.

```python
def greet(name, greeting="Hello"):
    return f"{greeting}, {name}!"

print(greet("Sam"))                 # Hello, Sam!
print(greet("Sam", greeting="Hey"))  # Hey, Sam!
```

`greeting="Hello"` donne à ce paramètre une valeur par défaut, si bien que les appelants peuvent l'omettre entièrement. Les arguments peuvent aussi être passés par nom (`greeting="Hey"`) plutôt que par position, ce qui est utile dès qu'une fonction prend plusieurs paramètres et que l'appel serait sinon une liste confuse de valeurs nues.

Parfois, le nombre d'arguments qu'une fonction devrait accepter n'est pas fixé à l'avance. `*args` rassemble tout argument positionnel supplémentaire dans un tuple, et `**kwargs` rassemble tout argument nommé supplémentaire dans un dict — les noms `args`/`kwargs` ne sont qu'une convention, ce sont les préfixes `*`/`**` qui comptent.

```python
def total(*args, **kwargs):
    print("positional:", args)     # (1, 2, 3)
    print("keyword:", kwargs)       # {'label': 'sum'}
    return sum(args)

result = total(1, 2, 3, label="sum")
print(result)  # 6
```

Ce motif apparaît constamment dans le code de bibliothèque — une fonction wrapper qui doit accepter « quels que soient les arguments que la chose qu'elle enveloppe accepte » sans connaître cette signature à l'avance utilise `def wrapper(*args, **kwargs)` et les transmet avec `wrapped(*args, **kwargs)`.

Les fonctions sont aussi des objets ordinaires : elles peuvent être assignées à des variables, passées comme arguments, et renvoyées par d'autres fonctions, ce qui est ce qui rend les closures possibles.

```python
def make_multiplier(factor):
    def multiplier(x):
        return x * factor
    return multiplier

double = make_multiplier(2)
triple = make_multiplier(3)
print(double(5), triple(5))  # 10 15
```

`multiplier` « se souvient » de la valeur `factor` de l'appel qui l'a créée, même après que `make_multiplier` a déjà retourné — c'est une closure, et c'est le mécanisme derrière les décorateurs Python.
