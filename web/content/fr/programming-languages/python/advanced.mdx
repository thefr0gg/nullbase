Un **décorateur** est une fonction qui prend une fonction et renvoie une nouvelle fonction qui l'enveloppe — utilisé pour ajouter du comportement (journalisation, chronométrage, vérifications d'accès) sans toucher au corps de la fonction originale. La syntaxe `@decorator` au-dessus d'un `def` n'est qu'un raccourci pour réassigner la fonction à la valeur de retour du décorateur.

```python
def logged(func):
    def wrapper(*args, **kwargs):
        print(f"Calling {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@logged
def add(a, b):
    return a + b

print(add(2, 3))
# Calling add
# 5
```

`@logged` au-dessus de `def add(...)` équivaut à écrire `add = logged(add)` juste après sa définition — chaque appel à `add` appelle maintenant en réalité `wrapper`, qui affiche un message, puis appelle l'`add` original via la closure sur `func`, et renvoie son résultat. C'est le même mécanisme de closure couvert dans [Fonctions](/fr/programming-languages/python/functions), appliqué ici pour envelopper du comportement plutôt que simplement capturer une valeur.

Un **générateur** est une fonction qui produit une séquence de valeurs paresseusement, une à la fois, en utilisant `yield` au lieu de `return`. Appeler une fonction génératrice n'exécute pas son corps immédiatement — elle renvoie un objet générateur, et le corps n'avance que jusqu'au prochain `yield` chaque fois qu'une valeur est demandée.

```python
def countdown(n):
    while n > 0:
        yield n
        n -= 1

for number in countdown(3):
    print(number)
# 3
# 2
# 1
```

Chaque itération de la boucle `for` reprend `countdown` juste après son `yield`, plutôt que de réexécuter toute la fonction depuis le début — l'état local de la fonction (`n`, et sa position dans la boucle `while`) est préservé entre les yields. Cela rend les générateurs efficaces en mémoire pour de grandes séquences ou des séquences non bornées : rien au-delà de la valeur actuelle n'a besoin d'exister en mémoire en même temps.

Une **expression génératrice** — `(expr for item in iterable)` — est l'équivalent paresseux d'une compréhension de liste, produisant le même type de générateur un-à-la-fois sans aucun `def` ni `yield`.

```python
squares = (x * x for x in range(5))
print(next(squares))       # 0
print(next(squares))       # 1
print(list(squares))       # [4, 9, 16] — the rest, in one go
```

`next()` extrait exactement une valeur du générateur à chaque appel ; `list()` draine ce qu'il reste. Notez que les deux premières valeurs (`0`, `1`) ont déjà disparu au moment où `list()` s'exécute — un générateur ne produit chaque valeur qu'une seule fois, et il n'y a aucun moyen de le « rembobiner ».
