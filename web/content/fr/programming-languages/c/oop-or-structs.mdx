C précède la programmation orientée objet en tant qu'idée grand public, et il n'a ni `class`, ni héritage, ni syntaxe de méthode intégrée. Ce qu'il a, c'est `struct` pour regrouper des données liées, et le fait que les fonctions soient des valeurs adressables signifie que vous pouvez stocker un pointeur vers une fonction à l'intérieur d'un struct — c'est ainsi que les bases de code en C simulent des « objets avec méthodes » quand elles en ont besoin. C'est un substitut délibéré et fabriqué à la main, pas une fonctionnalité cachée qui ferait de C un langage secrètement orienté objet depuis le début.

## struct : regrouper des données liées

Un `struct` regroupe des champs nommés de types potentiellement différents en un seul type :

```c
#include <stdio.h>

struct Point {
    double x;
    double y;
};

double distanceFromOrigin(struct Point p) {
    /* passed by value: this receives a copy of the whole struct */
    double dx = p.x;
    double dy = p.y;
    return dx * dx + dy * dy; /* squared distance, skipping sqrt for brevity */
}

int main(void) {
    struct Point origin = {0.0, 0.0};
    struct Point p1 = {3.0, 4.0};

    printf("p1 = (%.1f, %.1f)\n", p1.x, p1.y);
    printf("squared distance: %.1f\n", distanceFromOrigin(p1));

    return 0;
}
```

Comme toute autre valeur, un `struct` est copié lors d'une affectation et passé par valeur dans les fonctions, sauf si vous lui passez explicitement un pointeur — pour un gros struct, passer `struct Point *p` et utiliser `p->x` évite de tout copier à chaque appel.

## typedef et pointeurs de fonction comme « méthodes »

`typedef` donne à un struct un alias plus court, et un champ pointeur de fonction permet à un struct de porter du comportement en plus de ses données — ce qui se rapproche le plus d'une méthode en C :

```c
#include <stdio.h>

typedef struct Account {
    double balance;
    void (*deposit)(struct Account *self, double amount);
} Account;

void depositImpl(Account *self, double amount) {
    self->balance += amount;
}

int main(void) {
    Account acc = {0.0, depositImpl};

    acc.deposit(&acc, 100.0); /* looks like a method call, but it's just a function pointer */
    acc.deposit(&acc, 50.0);

    printf("balance: %.2f\n", acc.balance);

    return 0;
}
```

`acc.deposit(&acc, 100.0)` se lit presque comme le ferait `acc.deposit(100.0)` dans un langage orienté objet, sauf que C exige que l'objet (`&acc`) soit passé explicitement comme premier argument — il n'y a pas de `this` implicite. De vraies bases de code C utilisent exactement ce motif (un struct de pointeurs de fonction agissant comme une « vtable ») pour implémenter des interfaces et du polymorphisme — le struct `file_operations` du noyau Linux en est un exemple bien connu.

## La composition plutôt que l'héritage

C n'a aucun moyen de dire « ce struct étend cet autre struct ». Au lieu de cela, un struct en intègre un autre comme champ nommé, et le comportement partagé s'exprime en écrivant des fonctions qui opèrent sur la pièce intégrée :

```c
#include <stdio.h>

typedef struct {
    double x;
    double y;
} Point;

typedef struct {
    Point position; /* composition: a Circle "has a" Point, not "is a" Point */
    double radius;
} Circle;

void printPoint(Point p) {
    printf("(%.1f, %.1f)", p.x, p.y);
}

int main(void) {
    Circle c = {{1.0, 2.0}, 5.0};

    printf("circle at ");
    printPoint(c.position); /* reuse the function written for Point */
    printf(" with radius %.1f\n", c.radius);

    return 0;
}
```

Comme il n'y a pas d'héritage, la réutilisation de code en C vient de la composition de structs plus petits et de l'écriture de fonctions qui opèrent sur ces pièces, plutôt que de la construction d'une hiérarchie de classes — une contrainte qui a poussé les styles ultérieurs de « POO sans classes » (comme l'embedding de Go) vers la même idée.
