**TypeScript** est un langage à typage statique qui compile en JavaScript
ordinaire. Il n'introduit pas de nouveau runtime, pas de nouveau
ramasse-miettes, pas de nouvelle sémantique d'exécution — chaque programme
JavaScript valide est (presque) du TypeScript valide, et chaque programme
TypeScript devient finalement du JavaScript qui s'exécute dans les mêmes
moteurs où JavaScript s'exécute déjà (V8, Node, navigateurs). Ce que
TypeScript ajoute est un **vérificateur de type** : une passe séparée à la
compilation qui lit vos annotations et types inférés, signale les
incohérences, puis efface toute cette information de type avant que le code
ne s'exécute jamais.

Ce dernier point compte. Les types en TypeScript ont un **coût d'exécution
nul et une présence d'exécution nulle** — `interface`, `type`, et la plupart
des annotations de type disparaissent complètement pendant la compilation
(`tsc`, ou un transpileur comme esbuild/SWC). C'est pourquoi TypeScript peut
attraper toute une catégorie de bugs — passer une `string` là où un `number`
est attendu, appeler une méthode qui n'existe pas sur un objet, oublier de
gérer `null` — avant même d'exécuter le programme, sans changer comment le
programme se comporte une fois qu'il s'exécute réellement.

## Pourquoi ajouter un système de types à JavaScript

Le typage dynamique de JavaScript est flexible mais signifie que beaucoup
d'erreurs n'apparaissent qu'à l'exécution, souvent en production. Le
compilateur de TypeScript vérifie la forme de vos données au fur et à
mesure que vous écrivez du code :

```ts
function greet(name: string) {
  return `Hello, ${name.toUpperCase()}!`;
}

greet("Ada");
greet(42); // Type error: Argument of type 'number' is not assignable to parameter of type 'string'
```

Le second appel aurait levé une `TypeError` à l'exécution en JavaScript
ordinaire (`42.toUpperCase is not a function`) — mais seulement une fois
que cette ligne s'exécute réellement, peut-être profondément dans un chemin
de code rarement atteint. TypeScript l'attrape immédiatement, au moment où
vous l'écrivez, dans votre éditeur.

## Typage structurel

Contrairement aux langages basés sur les classes comme Java ou C#, le
système de types de TypeScript est **structurel**, pas nominal : deux types
sont compatibles s'ils ont la même forme, quel que soit leur nom ou leur
relation déclarée.

```ts
interface Point {
  x: number;
  y: number;
}

function printPoint(p: Point) {
  console.log(`(${p.x}, ${p.y})`);
}

const coord = { x: 3, y: 4, label: "origin-ish" };
printPoint(coord); // OK — coord has at least x and y as numbers
```

`coord` n'a jamais été déclaré comme un `Point`, et il a même un champ
`label` supplémentaire, mais il satisfait structurellement la forme de
`Point`, donc l'assignation est autorisée. C'est un choix de conception
délibéré qui reflète comment les objets JavaScript circulent réellement.
