Les classes JavaScript supportent `class`, `constructor`, et les méthodes
depuis ES2015, mais elles n'ont aucune notion de champ privé ou public —
chaque propriété est accessible depuis l'extérieur de l'instance.
TypeScript ajoute des **modificateurs d'accès** que le compilateur impose,
plus `interface`, une forme de déclaration dédiée à décrire des formes que
le JavaScript ordinaire n'a aucun équivalent pour.

## Classes avec modificateurs d'accès

```ts
class BankAccount {
  public owner: string;
  private balance: number;
  readonly accountId: string;

  constructor(owner: string, accountId: string, startingBalance: number) {
    this.owner = owner;
    this.accountId = accountId;
    this.balance = startingBalance;
  }

  deposit(amount: number): void {
    this.balance += amount;
  }

  getBalance(): number {
    return this.balance;
  }
}

const acct = new BankAccount("Ada", "acc-1", 100);
acct.deposit(50); // OK — public method
console.log(acct.balance); // Type error: Property 'balance' is private and only accessible within class 'BankAccount'
acct.accountId = "acc-2"; // Type error: Cannot assign to 'accountId' because it is a read-only property
```

- `public` (le défaut) — accessible depuis n'importe où.
- `private` — accessible seulement à l'intérieur du corps de la classe
  lui-même, pas depuis les instances ou les sous-classes.
- `readonly` — assignable une seule fois, dans le constructeur.

Ces vérifications disparaissent entièrement de la sortie JavaScript compilée
— `private` et `readonly` sont des garanties uniquement à la compilation.
(TypeScript supporte aussi de vrais champs privés à l'exécution via la
syntaxe `#field`, que JavaScript lui-même définit et impose à l'exécution,
contrairement à `private`.)

## Propriétés de constructeur en raccourci

Écrire un champ, puis le réassigner depuis un paramètre de constructeur du
même nom, est assez courant pour que TypeScript vous permette de
compresser les deux en une seule déclaration en ajoutant un modificateur
d'accès directement sur un paramètre de constructeur :

```ts
class Point {
  constructor(
    public x: number,
    public y: number,
  ) {}
}

const p = new Point(3, 4);
console.log(p.x, p.y); // 3 4
```

Ceci déclare `x` et `y` comme des champs publics sur la classe *et* les
assigne à partir des arguments du constructeur, sans avoir besoin de
déclarations de champ séparées ni de lignes `this.x = x`.

## interface vs type

`interface` et `type` peuvent tous deux décrire la forme d'un objet, et
pour des formes d'objet simples ils sont souvent interchangeables :

```ts
interface UserI {
  id: number;
  name: string;
}

type UserT = {
  id: number;
  name: string;
};
```

Les différences qui comptent en pratique :

- **Fusion de déclarations** : deux déclarations `interface` avec le même
  nom fusionnent en une seule ; deux alias `type` avec le même nom sont une
  erreur à la compilation (identifiant en double).
- **Ce qu'ils peuvent décrire** : `type` peut aliaser n'importe quoi —
  unions, tuples, primitives (`type Id = string | number`) — tandis que
  `interface` ne peut décrire que des formes d'objet/de classe.
- **Extension** : `interface` étend une autre avec `extends` ; `type`
  combine des formes avec une intersection (`&`).

```ts
interface Animal {
  name: string;
}
interface Dog extends Animal {
  breed: string;
}

type Vehicle = { wheels: number };
type Car = Vehicle & { brand: string };
```

Une classe peut `implements` l'une ou l'autre forme, tant que la forme est
un type objet — `class Labrador implements Dog { ... }` fonctionne de la
même façon que `class Labrador implements Car { ... }` le ferait,
structurellement.
