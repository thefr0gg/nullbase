Chaque autre section de ce site porte sur une technologie précise — un langage, un protocole, un type de serveur. Cette section porte sur les idées qui les sous-tendent toutes : comment juger si une approche d'un problème est réellement meilleure qu'une autre, ce qu'un CPU et un GPU sont chacun construits pour bien faire, comment un compilateur ou un interpréteur transforme du texte en comportement, et ce qui change dès qu'un système a plus d'une chose en cours à la fois. Les pages ici renvoient vers les sections pratiques qui s'appuient dessus plutôt que de répéter ce terrain.

## Justesse et coût

- **[Algorithmes](/fr/computer-science/algorithms)** — comment décrire ce que coûte un morceau de code, indépendamment de la machine qui l'exécute.
- **[Structures de données](/fr/computer-science/data-structures)** — la poignée de façons d'organiser des données en mémoire, et les schémas d'accès pour lesquels chacune est construite.

## Le matériel sous le code

- **[Mémoire](/fr/computer-science/memory)** — la hiérarchie de stockage à travers laquelle les données d'un programme circulent réellement, des registres jusqu'au disque.
- **[CPU](/fr/computer-science/cpu)** — le cycle chercher-décoder-exécuter, le pipelining, et pourquoi la vitesse d'horloge seule a cessé d'être toute l'histoire.
- **[GPU](/fr/computer-science/gpu)** — pourquoi une puce construite pour des milliers d'opérations simples et simultanées est une machine différente d'un CPU, pas simplement une version plus rapide.

## Du code source au programme en exécution

- **[Compilateurs](/fr/computer-science/compilers)** — comment un texte source devient du code machine avant même que le programme ne s'exécute.
- **[Interpréteurs](/fr/computer-science/interpreters)** — comment un texte source (ou du bytecode) est plutôt exécuté directement, étape par étape.

## Faire plus d'une chose à la fois

- **[Concurrence](/fr/computer-science/concurrency)** — structurer un programme pour gérer plus d'une chose en cours à la fois.
- **[Parallélisme](/fr/computer-science/parallelism)** — exécuter réellement plus d'une chose au même instant précis.
- **[Systèmes distribués](/fr/computer-science/distributed-systems)** — ce qui change une fois que « plus d'une chose à la fois » signifie des machines séparées sans mémoire partagée et un réseau entre elles.
