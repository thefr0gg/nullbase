# HEAD

**HEAD** is identical to **GET**, except the server returns headers only — **no response body**.

Use HEAD when you want metadata about a resource without downloading the full content.

## HEAD vs GET

| Aspect | GET | HEAD |
|--------|-----|------|
| **Response Body** | Yes | No |
| **Headers** | Yes | Yes |
| **Use Case** | Download resource | Check resource properties |
| **Bandwidth** | Full size | Minimal |

---

## Common Uses

**Check if a resource exists:**
```
HEAD /api/users/42 HTTP/1.1
```

If it returns `200 OK`, the resource exists. If `404`, it doesn't.

**Check file size before downloading:**
```
HEAD /downloads/large-file.zip HTTP/1.1
```

Look at the `Content-Length` header to see how big it is, then decide whether to download.

**Check if a resource was modified:**
```
HEAD /api/data HTTP/1.1
```

Look at the `Last-Modified` or `ETag` headers. If they match your cache, you don't need to download it.

---

## Response Status Codes

Same as GET:
- **200 OK** — Resource exists
- **404 Not Found** — Resource doesn't exist
- **410 Gone** — Resource was deleted
- **304 Not Modified** — Resource hasn't changed (if you sent If-Modified-Since or If-None-Match)

---

## Response Headers

The same headers as GET:

```
HEAD /api/users/42 HTTP/1.1

HTTP/1.1 200 OK
Content-Type: application/json
Content-Length: 256
Last-Modified: Mon, 28 Aug 2023 12:00:00 GMT
ETag: "abc123"
```

Notice: no body follows.

---

## Properties

- **Safe:** Yes — doesn't change server state
- **Idempotent:** Yes — calling multiple times has the same effect
- **Cacheable:** Yes — responses can be cached like GET

---

## Common Mistakes

**Avoid:** Assuming HEAD and GET return identical headers — Some servers are lazy and don't implement HEAD properly.

**Avoid:** Not expecting a body — If you send HEAD and get a body, your HTTP client might be broken (or the server is).
