# DELETE

**DELETE** removes a resource. After a successful DELETE, the resource is gone.

## Basic DELETE

```
DELETE /api/users/42 HTTP/1.1
Host: api.example.com
```

**Response:**
```
HTTP/1.1 204 No Content
```

---

## Response Status Codes

- **200 OK** — Deleted, response body contains details
- **202 Accepted** — Deletion is queued/processing
- **204 No Content** — Deleted successfully, no body
- **404 Not Found** — Resource doesn't exist
- **410 Gone** — Resource was already deleted

---

## DELETE with Query Parameters

Remove specific items or with conditions:

```
DELETE /api/sessions/current HTTP/1.1

DELETE /api/files?older_than=2023-01-01 HTTP/1.1
```

---

## Idempotent & Safe?

- **Idempotent:** Yes — calling DELETE twice has the same effect as once (it's gone).
- **Safe:** No — it changes the server state (removes data).

---

## Common Patterns

**Cascade delete:**
```
DELETE /api/users/42?cascade=true HTTP/1.1
```

**Soft delete (mark as deleted, don't actually remove):**
```
DELETE /api/users/42 HTTP/1.1
```
The server might return 200 with `{ deleted: true, id: 42 }` instead of actually removing it.

---

## Common Mistakes

❌ **Assuming DELETE is always instant** — It might be queued (202 Accepted).

❌ **Not using 404 for missing resources** — If the resource is already gone, return 404.

❌ **DELETE with a body** — Delete usually has no body. Include conditions in the URL or headers if needed.
